## 1. App 侧数据层（`VaultSync` 扩展）

新增静态方法（沿用现有签名/信封/线程模型；不破坏旧服务端：HTTP 404/参数错误时降级为旧状态展示）：

| 方法 | 请求 | 说明 |
|---|---|---|
| `fetchAccountPool(ctx, Callback)` | `POST /v1/vault/accounts` (op vaultAccounts) | 返回账号池列表+每角色 state+onlineCount；轮询 5s |
| `roleAction(ctx, fpid, sid, uid, action, Callback)` | `POST /v1/vault/role-action` | action=login/logout/pause/resume/stop；回调返回 stoppedRoles 供 UI 提示 |
| `accountAction(ctx, fpid, action, Callback)` | `POST /v1/vault/account-action` | login-all/stop-all |
| `globalAction(ctx, action, Callback)` | `POST /v1/vault/global-action` | login-all/stop-all |

- 请求字段与响应解析严格按 M1 契约；所有方法**不得在主线程**执行；回调结果直接更新 UI 状态缓存。
- 降级：若 `vaultAccounts` 返回 code!=0 或网络失败 → `AccountPoolCache` 标记 `stale=true`，UI 显示「状态获取失败，点击重试」，但保留上次状态（不误判离线）。
- 与现有 `fetchState/refreshStatus` 共存：`accounts` 接口只做列表/状态，不替代 `/state` 的今日页数据。

## 2. App 侧状态映射（`RoleDisplay` 扩展，纯函数 + 单测）

新增 `RoleRuntimeState`（字段同 M1 state）与 `rolePoolLabel(RoleRuntimeState)`：
- 与网页版 §2.3 文案逐字一致：在线/登录中/已暂停·待恢复/已暂停/已停止/被顶号/需登录/待恢复+倒计时/计划休眠/已收纳/离线；
- 动作可用性（纯函数）：`canLogin/canPause/canStop/canResume`（示例：online→可 pause/stop；!online&&enabled&&runState!=STOPPED→可 login；paused→可 resume/stop；enabled=false→全部禁用）；
- 降级（旧服务端无 state）：沿用现有 在线/离线/重连中/被顶号暂停/需token 映射，并附加「服务器状态暂不可用」标记；
- 单测覆盖 11 态文案 + 动作矩阵（JVM，App 测试基线 176 起）。

## 3. 账号页 UI 改造（`HomeActivity` 账号页）

### 3.1 组件结构（保持 App 设计语言，信息架构对齐网页版）
```
账号页
├─ 顶栏：标题「账号」+ 计数「N 个账号 · 工作区 M · K 个在线」
├─ 批量条：[全部上线/全部停止]（带进度「停止中 x/y」） [刷新]
├─ 搜索：备注名/号ID/角色名/区服
├─ 筛选：全部 N / 工作区 N / 异常 N / 未跑 N；列表/卡片切换（保留）
├─ 账号分组卡（按 fpid）
│  ├─ 头行：勾选（批量子集） + 头像 + 备注名 + [登录方式] UID + 「工作区 N · 在线 N」 + ⚙角色管理
│  └─ 角色行（工作区角色）：状态点+状态文案 | 角色名 | 区号 | 今日完成 | 上次登录 | [上线][暂停][停止] 或 [登录]
│     └─ 被顶号/待恢复：行下 banner「账号被顶号 · 待恢复 mm:ss」
└─ FAB +（新增账号，保留）
```
- 角色行动作规则：按 §2 动作可用性渲染；进行中显示 loading（网络请求期间禁点）；动作成功/失败 toast（含服务端 message）；成功后立即用本地乐观更新 + 触发一次 `fetchAccountPool`。
- 账号级按钮：组头「全部上线/全部停止」（工作区角色批量）；账号登录互斥提示弹窗（返回 stoppedRoles 时提示「已下线 XX」）。
- 全局按钮：批量条「全部上线/全部停止」，操作期间按钮变进度文案（x/y 来自本地逐账号调度结果；全局接口是原子批量，P0 可用本地逐账号调用账号级接口模拟进度，或直接 global-action 后轮询）。
- 空态：无账号/无角色（沿用现有）；未选择工作区角色显示「尚未选择工作区角色」+选择角色（角色管理）。

### 3.2 轮询与刷新
- 仅账号 tab 可见且 Activity resumed 时每 5s `fetchAccountPool`；`onPause`/切 tab 停止；请求串行防重入；操作后立即刷新（≤2s）。
- 本地 clone 在线状态（引擎 live/snapshot）与服务器在线状态**分别标注**：服务器=「在线（云端）」；本地=「本地运行中」（避免混淆），见 M3。

### 3.3 与现有功能兼容
- 角色行点击/登录按钮语义调整：原「登录」= 登录并触发服务器自动化；M2 保留为行操作「登录」，同时新增与网页一致的「上线/暂停/停止」；进入「账号详情」入口保留（卡片视图 tile 点击）。
- 现有筛选/批量管理/搜索/列表卡片切换/新增账号/角色管理弹窗保持可用。
- 今日页 Hero 状态与账号页状态同源（当前角色仍由 activeRole 决定；账号池多角色在线不改变"当前角色"概念，避免破坏防回滚 P2 逻辑）。

## 4. M3：启动分身修复 + 分身游戏版本升级

### 4.1 入口与诊断
- 账号页账号行二级菜单新增「启动分身」（与账号详情页启动分身并存）；点击前前置检查并显示结果：
  1. 授权闸门（LicenseManager.gateForLaunch）→「授权已过期/未激活」+去激活；
  2. 引擎就绪（`ensureEngineReady`）→「容器引擎未就绪」+重新初始化；
  3. 游戏已克隆（`VirtualCore.getInstalledAppInfo(GAME_PKG)`）→「游戏未克隆」+去克隆；
  4. 版本检查（新增，见 4.2）→「分身游戏版本过旧，需更新」+更新；
  5. 全部通过 → 启动；失败时**必须展示 `VaultEngine.lastLaunchError` 具体值**（分类+原文）。
- `doLaunch` 失败 toast 改为弹窗（原因 + 修复动作按钮 + 复制诊断信息）。

### 4.2 分身游戏版本检测与升级（P0 核心）

> **T1b 真机取证结论（2026-10-21 00:35–00:55，test CLI）**：
> 容器内/系统原版游戏均为 **1.16.11 (versionCode 146)**（启动页渠道角标显示 1.16.11.12，检测应以 versionCode 为准）；
> 最新版本 **1.16.12 (versionCode 147)**；游戏内「更新」跳转短链 **`https://wjdr-app.campfiregames.cn/download`**
> → 302 到 CDN `https://wjdr-download.campfiregames.cn/apk/package/2026/10/14/wjdr_1-16-12_147_1.apk`，
> 大小 **887,587,540 B (888MB)**，支持 Range 断点续传，etag `219b2b41bda641ceacf272c9c1aecbef-847`。
> 证据：`qa/evidence-20261021-account-pool/T1b-游戏更新链路取证.md`。

- 版本读取：容器内 `com.gof.china` 的 PackageInfo（VirtualCore API）→ versionName/versionCode（**以 versionCode 比较**，渠道角标不可作依据）。
- 最新版本配置来源（按可用性降级）：
  1. 服务端配置 `GET/POST /v1/vault/game-client`（M1 可扩展；字段 latestVersionName/latestVersionCode/apkUrl/sha256/size/force；
     `apkUrl` = 短链 `https://wjdr-app.campfiregames.cn/download`，App **必须每次解析 302** 拿真实 CDN 地址，禁止硬编码含日期的 CDN 路径）；
  2. 本地配置文件（assets 或远端拉取失败时提示手动导入）；
  3. 手动导入：用户将官方 APK 放入 Download，App 提供「从本地 APK 更新分身游戏」入口。
- 下载器要求：存储空间预检（≥1.5GB 可用）、Wi-Fi/流量提示（888MB）、Range 断点续传、进度/速度/剩余时间、
  完成后校验 size + etag（或服务端 sha256）+ APK 包名/versionCode/签名一致性，再进入安装。
- 升级流程：下载（断点续传/进度/剩余时间，显示速度）→ 校验（size、sha256、包名、versionCode 提升、签名与容器内一致/官方）→ `VirtualCore.get().installPackage(Uri.fromFile(apk), installParams)` 覆盖安装（保数据：安装后启动验证原角色数据仍在；失败回滚提示）→ 重新拉起游戏进入登录页。
- 失败分类：网络/校验/签名不一致/安装失败/版本未提升/数据异常；每类给下一步（重试/换源/联系支持/回滚）。
- 注意：官方 APK 分发/授权合规需用户确认（U3）；若无法内置下载，则保留「本地 APK 导入 + 版本检测提示」作为 P0 兜底。

### 4.3 本地分身与服务器会话关系
- 启动分身成功后若该 fpid 在服务器有在线会话：提示「本地登录将顶掉云端会话（XX 角色）」，确认后执行；本地退出/切回 App 时提供「恢复云端在线」一键操作（调用 role-action login）。
- 账号页状态行同时显示云端/本地两个角标（例：「在线·云端」「本地运行」）。
