# 账号池 P1 功能契约（2026-10-21）：防封保护 / 暂停自动恢复 / 角色管理增强

> 用户确认 P1 范围：**只做 防封（antiban）、暂停自动恢复、角色管理增强**；**不做**账号移动、批量复制凭据、计划休眠(禁运行时段)、角色创建、游戏内角色删除（game-delete）。
> 基准：京东云线上 release 400（jar sha 6c9f9c84…）+ 反编译源码 `/tmp/latest-jar/src`。行为以线上最新版为准，UI 用 App 设计语言。

## 一、数据模型（VaultStore）
- `Account` 增加恢复策略（账号级，作用于该账号全部角色）：
  - `takeoverRecoveryEnabled`（默认 true）、`takeoverInitialDelaySeconds`（默认 1800，范围 1..86400）
  - `takeoverRetryIntervalSeconds`（默认 5，范围 1..300）、`takeoverMaxAttempts`（默认 3，范围 0..10；0=不自动顶号）
  - `takeoverCooldownMinutes`（默认 15，仅允许 15/30/60/120/1440）
  - 校验失败返回 3002 + 中文原因（对齐线上：`顶号后等待必须在 1 到 1440 分钟之间` / `重试间隔秒数必须在 1 到 300 之间` / `连续尝试次数必须在 0 到 10 之间` / `冷却时长只支持 15 分钟、30 分钟、1 小时、2 小时或 24 小时`）
- `RoleEntry` 增加：`antibanEnabled`（默认 false）、`pauseResumeAt`（epoch millis，0=无）、`runState` 复用（PAUSED 表示暂停/待恢复）；`name` 已有。

## 二、服务端 API（/v1/vault/*，保持 M1 风格）
`/accounts` 输出新增：
- `account.recovery = {enabled, initialDelayMinutes, retryIntervalSeconds, maxAttempts, cooldownMinutes}`
- `roles[].antibanEnabled`（bool）、`roles[].pause_resume_at`（ISO-8601，可空）
- `roles[].state` 已有字段不变；暂停/待恢复时 `runState=PAUSED`，`state.online=false`。

新增动作（现有 `role-action` / `account-action` 扩展 op）：
1. `role-action` op `antiban`，payload `{enabled: bool}`：持久化到角色；在线角色切换时若开启且本次在线尚未做风险检测则立即补做；响应 `{message:"已开启防封风控安全保护"|"已关闭防封风控安全保护"}`。
2. `role-action` op `pause`（升级）：前置 `account.recovery.enabled=true`，否则 3002「顶号恢复未开启，无法暂停」；角色必须在线，否则 3002「账号当前离线，无法暂停」；设置 `runState=PAUSED`、`pauseResumeAt=now+initialDelay`，停止该角色会话（保留 desiredOnline=true 以便自动恢复）；响应 `{message:"账号已暂停，将在 N 分钟后自动上线", pauseResumeAt}`。
3. `role-action` op `rename`，payload `{name}`：角色必须在线；名称规则 3~12 个字符、首尾不能空格、不能含控制字符；调用协议 `req_player_modify_name {name, use_diamond:false}`，若返回错误码 51/err_item_not_enough 则重试 `use_diamond:true`；应用响应 `result.nickName`（缺省用入参）更新角色名；响应 `{name, usedDiamond, diamondCost:(usedDiamond?400:0), itemId:610001}`。
4. `role-action` op `remove`：把角色从账号工作区移除（**仅工具内移除，不删除游戏内角色**）；先停止该角色会话；响应 `{message:"角色已移除（游戏内角色未删除）"}`。若移除的是 active 角色，activeSid/activeUid 置空。
5. `role-action` op `enabled`，payload `{enabled: bool}`：启用/停用（收纳）角色；停用时停止会话；响应 `{message:"已启用"|"已收纳"}`。
6. `account-action` op `recovery-settings`，payload `{enabled, initialDelayMinutes, retryIntervalSeconds, maxAttempts, cooldownMinutes}`：写账号全部角色所在账号级字段；响应 `{message:"顶号恢复设置已保存并立即生效", recovery:{...}}`。
7. 自动恢复（SessionKeeper 周期 tick，建议复用现有 1s reconcile 节拍）：
   - `runState=PAUSED && pauseResumeAt>0 && now>=pauseResumeAt && desiredOnline` → 尝试重新登录；成功后 `runState=RUNNING, pauseResumeAt=0`。
   - 登录失败按恢复策略：第 1 次失败后等 `retryIntervalSeconds` 重试；连续失败达到 `maxAttempts`（0 视为不自动顶号）→ 进入 `cooldownMinutes` 冷却，冷却结束后重置尝试计数并再试；期间保持 `runState=PAUSED`、`pauseResumeAt=下次尝试时间`，`statusMessage` 给中文说明（如「等待重试（N/M）」）。
   - `stop`/`logout` 清空 pauseResumeAt 与 desiredOnline；`resume`/显式 `login` 立即清除 PAUSED 并尝试上线。
8. 防封协议（引擎 WjdrEngine）：
   - 新增 `setAntibanEnabled(boolean)`；登录流程中在 `req_loaddata` 成功之后、online 之前，若开启：发送 `req_settings_set_device`，payload `{params:[platform, deviceModel, "13", qualityLevel]}`，platform= `"android"/"2"`→`"2"` 否则 `"1"`，deviceModel 缺省 `"meizu MEIZU 18 Pro"`，qualityLevel 缺省 `"3"`；
   - online 后 10 秒（异步，不阻塞登录）若有开启且本次在线未做过：发送 `req_dun163_risk_check`，payload `{token: HtProtectTokenSupport.rewrapToken()}`；token 算法照抄 `/tmp/latest-jar/src/com/wjdr/tool/core/common/util/HtProtectTokenSupport.java`（24 字节固定 payload `3dbc96467b10571f4446101001438853222a02f05a572ff8` + 4 字节随机 mask，raw28=payload^mask + mask，Base64URL 无填充）；
   - 协议失败只记日志（`[防封保护] ... 已忽略，不阻断登录`），不得影响登录/在线。
   - 日志格式：`[防封保护] 设备环境上报完成 uid=… code=…` / `[防封保护] 易盾安全风控检测完成 uid=… code=… sdkRespLen=…`

## 三、App UI（M2 风格，账号页）
1. 角色行/卡片增加「防封保护」开关（在线/离线均可切换；开关调用 op antiban）：
   - 开启前确认弹窗（逐字对齐线上）：标题「开启防封保护确认」，正文「确定为角色【角色名】开启防封保护吗？开启后，该角色在登录游戏时将自动模拟真实客户端上报设备环境（req_settings_set_device），并在进入游戏 10 秒后执行易盾安全校验（req_dun163_risk_check）。⚠ 注意事项：1. 采用官方受信任特征与动态 Nonce 掩码重封装机制；2. 开关变更将在下一次角色登录/启动时生效；3. 未开启时，角色仍按原来的极简协议链路登录启动。」按钮「确认开启/取消」；成功 toast「已开启防封风控安全保护」/「已关闭防封风控安全保护」。
2. 暂停：角色行「暂停」按钮直接调用 op pause（不弹确认），成功 toast「账号已暂停，将按顶号设置自动恢复」；失败展示服务端 message（如「顶号恢复未开启，无法暂停」）。在线状态显示已有「已暂停·待恢复」+ 倒计时（用 pause_resume_at）。
3. 恢复设置入口（账号分组头/账号菜单「恢复设置」）：对话框字段
   - 允许意外下线后自动上线（switch）
   - 顶号后等待（分钟，1~1440，默认 30）
   - 连续尝试（次，0~10，默认 3；0=不自动顶号，账号保持离线）
   - 每次间隔（秒，1~300，默认 5）
   - 让号冷却（下拉：15 分钟/30 分钟/1 小时/2 小时/24 小时，默认 15 分钟）
   - 保存调用 op recovery-settings，成功 toast「顶号恢复设置已保存并立即生效」。
4. 角色管理增强（角色行菜单/详情）：
   - 重命名：对话框输入 3~12 个字符（首尾不能空格/不能控制字符），确认调用 op rename；成功 toast 名称已更新，展示「本次消耗：改名道具 / 400 钻石」提示。
   - 移除角色：确认文案「确定要移除角色【X】吗？仅从工具工作区移除，不会删除游戏内角色。」→ op remove。
   - 启用/收纳：切换角色 enabled（op enabled）；已收纳角色置灰、显示「已收纳」。
5. 不做：账号移动、批量复制凭据、计划休眠、角色创建、游戏内角色删除。

## 四、验收标准
- server 单测 ≥ baseline 168 + 25，全绿；App 单测 ≥ baseline 300 + 20，全绿。
- M4d 真机（本地 server，死代理）：防封开关确认弹窗/文案/开关状态持久化；恢复设置保存/校验错误提示；暂停在恢复未开启时报错、开启后可暂停并显示倒计时（死代理下登录失败进入重试/到点重试状态）；重命名离线报错；移除角色确认与列表变化；已收纳显示。
- 生产 M5（需用户批准后）：真实登录后暂停→自动恢复、防封开关在线补做风控检测日志、在线重命名成功/失败提示、移除角色不影响游戏内角色；不执行游戏内删除。
