### ⚠ 两个必须由你确认的环境问题（我未自行绕过）

1. **SSH 端口变了**：`~/.ssh/config` 里 `vault-vps` 配的是 **64868**，该端口当前**不可达**；
   而 **22 端口可达**。
2. **22 端口的主机密钥与 known_hosts 记录冲突**（`known_hosts:4`）：
   ```
   远程 ED25519 指纹：SHA256:UPS7c1IzLIx0UH1QqFIKeacxCukVvMwYkxT4JUjbIJU
   ```
   这通常意味着**服务器重装/迁移**，但也可能是中间人攻击。**在确认之前不要删除 known_hosts 记录**
   （我不做 `StrictHostKeyChecking=no` 这类绕过）。

   - 若你确认服务器重装过（预期行为）：
     ```bash
     ssh-keygen -R '[103.236.96.82]:22'
     ssh-keygen -R '[103.236.96.82]:64868'
     # 重新连接并核对指纹后接受
     ssh -p 22 -i ~/.ssh/vault_vps root@103.236.96.82 'hostname; uptime'
     ```
   - 若不确定：先到云控制台核实实例是否重装/换机，再操作。
   - 确认后建议把 `~/.ssh/config` 的 `Port 64868` 更新为 `22`，下文命令即可直接用 `vault-vps`。

## 1. 构建（本地，已跑通）

```bash
cd <仓库根>            # worktree: .agents/worktrees/add/migrant-1to1-20261106-2058
JAVA_HOME=$HOME/java/jdk-17/Contents/Home ./gradlew -p vault-server fatJar --offline
```

产物：`vault-server/build/libs/vault-server-0.1.0-all.jar`（构建产物在 `vault-server/.gitignore` 的 `build/` 内，**不入库**，每次按本节重建）

> 说明：`vault-server` 是独立 Gradle 构建（自带 settings.gradle），根目录用 `-p vault-server` 调；
> 直接在 vault-server 目录下没有 gradlew。必须用 JDK17（项目 source/target=17）。

可选：本地先跑一遍测试，确认无回归（用 JDK17 可跑正式 Gradle）：
```bash
JAVA_HOME=$HOME/java/jdk-17/Contents/Home ./gradlew -p vault-server test --offline
```

## 3. 服务器端：备份 → 替换 → 重启

```bash
ssh -p 22 -i ~/.ssh/vault_vps root@103.236.96.82 'bash -s' <<'REMOTE'
set -e
cd /opt/vault-server

# 3.1 备份旧 jar（沿用仓库既有命名习惯）
mkdir -p backup
cp vault-server-all.jar "backup/vault-server-all.jar.bak-$(date +%Y%m%d-%H%M%S)"

# 3.2 备份任务数据（本次新增，回滚时保留现场）
[ -f data/migrant.json ] && cp data/migrant.json "backup/migrant.json.bak-$(date +%Y%m%d-%H%M%S)" || true

# 3.3 替换（沿用原属主；仓库部署以 vault:vault 运行）
mv vault-server-0.1.0-all.jar.new vault-server-all.jar
chown vault:vault vault-server-all.jar 2>/dev/null || true
chmod 644 vault-server-all.jar

# 3.4 重启
systemctl restart vault-server
sleep 6
systemctl is-active vault-server
REMOTE
```

## 5. 回滚

| 场景 | 操作 |
|---|---|
| 仅关 App 入口 | `FeatureGate.IMMIGRATION` 置回 `false` 重出包（服务端可留） |
| 关服务端移民 | 目前无 env 开关；回滚方式为**换回备份 jar 并重启**（见下） |
| 完全回滚 | `cp /opt/vault-server/backup/vault-server-all.jar.bak-<ts> /opt/vault-server/vault-server-all.jar && systemctl restart vault-server` |

> 回滚后 `data/migrant.json` 可保留（旧 jar 不读该文件，无副作用）；若要彻底清理再删。

## 6. 上线时机与影响

- **重启会中断所有在线会话**（服务端会自动重连，约数十秒）。建议在低峰期执行。
- **避开自由移民活动窗口**：若窗口临近（开放前 15 分钟已开始准备），请等本轮窗口结束再部署，
  否则正在准备的任务会因重启进入恢复流程（有保护：已发射的任务不会重发，但会转 UNKNOWN 需人工核验）。
