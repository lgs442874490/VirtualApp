## 二、平台与授权用例（TC-P）

### TC-P01 授权签名黄金向量对齐（客户端↔服务端字节级一致）
- 前置：license-server README §6.3 冻结的 4 组黄金向量（APP_SECRET=`vc2026-hj-license-9f3a7c1e5b8d2460`）。
- 步骤：1) 以向量入参调用 `LicenseCrypto.writeCanonical`（规范 JSON）；2) 对 canonical 做 SHA-256；3) 以 `signPayload(v1\nPOST\nOP\nts\nnonce\nsha256)` 计算 HMAC。
- 预期（对标原版服务端）：4 组向量的 canonical 字符串、SHA256 hex、sign hex 与冻结值**逐字节一致**；向量 4 验证 `" \ <>&` 中文、U+0001、U+2028 转义规则（`<>&` 不转义、非 ASCII 不转 \u）。
- 方式：JVM
- 结果：见报告

### TC-P02 客户端内置密钥可还原且与服务端可用同一密钥部署
- 前置：APK 内 `LicenseConfig.APP_SECRET_OBF`（base64+循环 XOR）。
- 步骤：调用 `LicenseConfig.appSecret()`。
- 预期：还原为 64 位 hex 串 `afbaa5ee…c586`（与服务端 LICENSE_SECRET 同值的部署约定），非空、无乱码。
- 方式：JVM（Base64 经静态替身）
- 结果：见报告

- 结果：见报告

## 三、调度与策略用例（TC-S）

> 本节为「策略逻辑与原版一致性」的核心。原版基准：TaskEngine 定时唤醒/心跳 1s 扫描/退避 8s→300s±10%/顶号按策略延迟重登/独占窗口。

### TC-S01 时间窗内首次调度（随机 2–14 分钟）
- 前置：某账号 auto=true，窗口 5–9，今日未跑，当前 6:30。
- 步骤：调度服务 tick（10 分钟巡检）触发 `nextRunInWindow(0)`。
- 预期：nextRunAt ∈ (now, now+14min]，随机分钟级；到点 +1.5s 精确闹钟（requestCode 1002）触发整轮。
- 方式：代码审查 + EMU（观察通知文案「正在执行」/「下次窗口 5:00-9:00」）；随机数分布 JVM 不可直测（私有方法），列入未自动化项
- 结果：见报告

### TC-S02 窗口外/今日已跑 → 次日窗口
- 前置：窗口 5–9。
- 步骤：分别以 lastRunAt=今天 6:00（已跑）、now=10:00（窗外）计算。
- 预期：已跑或窗外 → nextRunAt 落在**明天** [5:00,9:00) 内随机时刻（hour∈[5,9)，秒=0）。
- 方式：代码审查（逻辑分支核对）
- 结果：见报告

### TC-S03 时间窗修改即时生效
- 步骤：日常页横幅→时段按钮→NumberPicker 改为 10–22。
- 预期：保存后 nextRunAt 清零重算；通知文案即时显示「下次窗口 10:00-22:00」；window_start/window_end 落盘。
- 方式：EMU（run-as 读 daily_sched prefs 验证）
- 结果：见报告

## 七、协议层用例（TC-X）

> 对标基准：原版 core/protocol（2 字节大端长度前缀 + sproto；加密 0 明文/1 XOR/2 RC4，默认密钥 "4b5eea17"；登录签名 SHA-1 盐+11 字段顺序拼接）。

**TC-X01 帧编解码**
- 预期：`prependLength` 2 字节大端前缀；`readLength` 还原 0..65535；空 payload 长度 0。
- 方式：JVM

**TC-X02 XOR 流加密**
- 预期：`apply(input,key)` 循环 XOR；null/空 key 原样返回；两次 apply 互逆（对称）；与原版默认密钥语义一致（逐字节异或）。
- 方式：JVM

**TC-X03 RC4 流加密（对齐原版）**
- 预期：标准 KSA+PRGA；同一实例 apply 为**流式**（两次调用不重置状态，等价于连续流加密一段数据）；cryptLength 只加密前 N 字节、其余原样；并发安全（锁）；空 key 构造抛 IllegalArgumentException。
- 方式：JVM（含与 Python 独立实现的已知答案向量比对）

**TC-X04 登录签名（loginauth sign，对齐原版 CryptoUtils）**
- 预期：`SIGN_PREFIX + ";" + account;sdkToken;uid;device;device_os;country_code;distinct_id;lan;version;package_tag;ts` 11 字段定序拼接 → SHA-1 → Base64；数值字段整数化文本（1.0→"1"）；ts 缺省为空串；与独立实现逐字节一致。
- 方式：JVM

**TC-X05 sproto schema 解析（真实 .spb）**
- 前置：assets/wjdr/game_proto_c2s.spb（708KB）/ s2c.spb（370KB）。
- 预期：解析成功无异常；c2s 协议数 >500（原版 schema 全量）；常见协议（req_heartbeat/loginauth/req_world_march/req_fourteen_sign_get_all_reward…）均能按名解析到定义（tag 唯一）。
- 方式：JVM

**TC-X06 sproto 编解码往返一致**
- 预期：任取 c2s 协议，encode(map)→decode→字段值与输入一致（整数/字符串/嵌套 map/list）；packed segment（0xFF 压缩段）处理正确。
- 方式：JVM

**TC-X07 未知协议兜底**
- 预期：未收录 tag → `_unknown_proto_tag` 内容（原版同款兜底）；未映射 session → `_unmapped_session`；任务层将其归为 DEGRADED（差异点 D2）。
- 方式：JVM（codec 层）+ 代码审查（任务层）
