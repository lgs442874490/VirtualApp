## 2. 回归场景与判定（服务器模式）

| # | 场景 | 操作 | 判定 |
|---|---|---|---|
| 1 | 新角色首次登录 | App 账号页对未固化角色点「上线」 | 服务器日志出现登录成功；`vault.json` 该角色 `roleIdentity[sid:uid]` 为 v2 且字段合法 |
| 2 | 同账号同服多角色 | 同账号两个 888 角色先后/同时上线 | 两个 `roleIdentity[sid:uid]` 的 `device_id`/`distinct_id` **不同**；两会话均在线不互踢 |
| 3 | 老 v1 数据升级 | 对已有 v1 `roleIdentity` 的角色上线一次 | 升级为 `"v":2`（含 manufacturer/brand/android_version/device_lv），且 `device/device_id/distinct_id/ip` **原值不变** |
| 4 | 重试不漂移 | 同一角色登录失败后重试（或连续两次上线） | 两次设备字段一致 |
| 5 | 连续登录稳定性 | 连续 10 次上线/重登 | 无登录失败、无异常日志、无互踢 |

> 说明：服务器模式不读 App `SharedPreferences`，所以 v1 升级验证以 **VPS 的 `roleIdentity`** 为准；
> App 端只需确认角色卡在线/状态正常。

## 3. 校验命令（VPS 上执行）

```bash
# 3.1 查看某账号全部角色指纹（<fpid> 换成被测账号）
python3 - <<'PY'
import json
d=json.load(open('/opt/vault-server/data/vault.json'))
for a in d.get('accounts',[]):
    if a.get('fpid')=='<fpid>':
        print('account identity:', (a.get('identity') or '')[:200])
        for k,v in sorted((a.get('roleIdentity') or {}).items()):
            print(k, '->', v)
PY

# 3.2 登录相关日志（近 100 行）
grep -iE "登录|identity|设备|loginauth|踢|code=" /opt/vault-server/data/logs/vault-$(date +%Y%m%d).log | tail -100

# 3.3 多角色设备隔离快速判断：同一 fpid 下不同 sid:uid 的 device_id 必须不同
python3 - <<'PY'
import json, collections
d=json.load(open('/opt/vault-server/data/vault.json'))
for a in d.get('accounts',[]):
    if a.get('fpid')!='<fpid>': continue
    seen=collections.defaultdict(list)
    for k,v in (a.get('roleIdentity') or {}).items():
        try: o=json.loads(v)
        except Exception: continue
        seen[o.get('device_id','')].append(k)
    for did,keys in seen.items():
        print(('OK ' if len(keys)==1 else 'CONFLICT '), did[:12], keys)
PY
```
