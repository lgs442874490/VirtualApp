## 7. 偏差与异常（逐项）

### D1（P2）角色等级显示不一致

**现象**：账号详情/角色管理显示“888服 · 城堡 1 级 · 战力 1414214.1万”；
游戏内领主档案显示“领主 15 级”，城堡图标为“10 级”。

**证据**：
- `daily_roles.xml`：`level=1`；
- 执行日志：`syncRoleMeta: ok ... lv=1 power=14142141810`；
- 游戏截图：领主档案显示 `15级`、城堡图标 `10`、战力 `141.4亿`。

**根因线索**：
- `RoleStore.syncRoleMeta()` 读取 `notify_base_info.lv`（`RoleStore.java:194`），
  直接 `registerRole(..., lv, power, ...)`；
- UI 把它标注为“城堡 X 级”（`EntryDetailActivity.java:343`、`HomeActivity.java:3426`）。
- 需要确认 `notify_base_info.lv` 的真实语义（领主等级/城堡等级/领地等级），
  以及为何返回 1；如果是领主等级，UI 文案“城堡”也不准确。

**影响**：角色卡片与详情页等级错误；若后续自动化按等级做路线/解锁判断，可能选错科技/建筑目标
（与 D3 的 4104 可能相关，需联合排查）。

**建议**：先用真实账号对比 `notify_base_info` 全字段与游戏档案，明确 `lv` 的字段语义；
再决定是修正字段映射还是修正 UI 文案。不要把 1 级直接展示为“城堡”。

### D2（P2）每日任务奖励 4302 + 功能 id 丢失

**现象**：
- 两轮日常均返回 `❌ 每日任务奖励：服务端返回错误码 4302`；
- 功能详情页仍然显示“● 今日未跑”；
- `daily_state` 中的状态键为 `st:2026-10-18:107365823:888:每日任务奖励 = 3`，
  而不是 `...:daily_mission`。

**证据**：
- `daily_logs.xml` 键：`107365823:888:每日任务奖励`；
- `st:` 键：`st:2026-10-18:107365823:888:每日任务奖励 = 3`；
- 功能详情 `FunctionActivity` 按 `fn.id` 查询：`LogStore.status(fpid, serverid, fn.id)`
  （`FunctionActivity.java:228`），`fn.id = daily_mission`；
- `LogStore.status()` 使用 `st:<date>:<fpid>:<serverid>:<fnId>`（`LogStore.java:161-166`）。

**根因**：
`DailyTasks.classifyServerCode()` 的 default 分支返回
`new DailyResult(name, name, ERROR, ...)`（`DailyTasks.java:1211`），
把**显示名**当成了 **功能 id**。`dailyMission()` 调用它时传入 `"每日任务奖励"`
（`DailyTasks.java:636`），于是日志/状态落到中文键，功能详情按 `daily_mission` 查不到，
显示“今日未跑”。同类问题也会影响其他走到 default 分支的服务端错误码。

**影响**：
- 账号筛选显示“异常 1”，但功能详情显示“今日未跑”，两处状态互相矛盾；
- `dayStats()` 按注册表 id 统计，漏掉该失败，完成度/异常统计不可信；
- 用户无法从功能详情看到真实失败原因。

**建议**：
1. `classifyServerCode` 增加 `fnId` 参数，所有分支都用功能 id 作为第一个参数；
2. 把 4302 映射为 `SKIPPED`（若语义是“无可领/已领”）或至少保留原始码并显示；
3. 增加单元测试：所有 `classifyServerCode` 分支返回的 id 必须等于传入的功能 id。

> 备注：4302 在既有《服务器模式P3B-全量任务迁移验证》中也出现过，当时被判定为
> “账号/活动状态而非移植差异”。本次不把它当作新回归，但“id 丢失导致详情页状态错误”是确定缺陷。

### D4（P2）角色作用域 0/888 分裂

**现象**：
- 首次手动日常（角色尚未加入工作区）把任务记录/状态写到 `sid=0`；
- 启用角色后第二轮写到 `sid=888`；
- `daily_sched` 同时存在 `lastr:107365823:0` 与 `lastr:107365823:888`；
- 启用角色前 Today 页显示“巨熊行动 未预约”，启用并选中角色后变为
  “巨熊陷阱预约 21:00 开启 · 即将开始”。

**证据**：
- `daily_logs.xml` 同时存在 `107365823:0:*` 与 `107365823:888:*` 两套 69 条记录；
- `daily_state.xml` 中 `mod:107365823:888:bear` 为“已预约 10月19日 21:00”，
  但 Today 页在 `current_role` 为空时读取 `mod:107365823:0:bear`（不存在）；
- `home.xml` 在启用角色前没有 `current_role`，启用后写入 `107365823:888`。

**根因线索**：
- `HomeActivity` 的代办读取使用 `currentRoleSid()`（`HomeActivity.java:1354`），
  没有当前角色时返回 0；
- 手动“跑日常”在角色未加入工作区时仍会执行，并发现/写入 888 角色状态；

**影响**：

- 账号卡显示正确，但待办事项错误（巨熊未预约）；
- 两套状态键并存，后续统计/清理容易混淆。

**建议**：手动跑日常前先解析并固定当前角色（只有一个角色时自动选中/加入工作区），
或让 Today/详情在 `sid=0` 时回退到该账号唯一角色；同时清理/合并 0 作用域历史键。

### D5（P3）100% 完成 vs 异常 2

**现象**：执行进度面板显示 `100% / 1 / 1 项已完成 / 执行结束`，

“账号完成 1/1 · 任务异常 2”，或把存在 ERROR 的账号进度显示为“完成（有异常）”。
