## 7. 实现要点与风险

### 实现要点

- **日志节流**：`BearState.logWindowStart/logKeys` 按场次保存「已打过的原因键」；跨轮次持久化，重启后同场次会重新打一次（可接受，不刷屏）。
- **字段统一**：新增日志统一 `巨熊{原因} fpid= sid= 场次=`，不含 token/cookie。
- **F2 最小改动**：只在 `nextIntervalForResult` 顶部对 `bear` + 窗口内短路；不动 `applyResult` / `wakeAt`，窗口外与其它任务行为不变。
- **F3 只特殊处理 5203**：`bearCodeText` 其它未知码仍返回空串（保持原契约），由 `launchFailureText` 兜底「未知码」。
- **F4 摘要**：`compactFallbackSummary` 去掉「（编队库 [...]）」明细，取前 3 个失败槽、单条 ≤300 字符；`conflictTypeOf` 去掉尾部动态英雄列表作为节流键。
- **F6 不误判**：查询失败只 `tries+1` + 保留 pending + warn，不进入「对账未确认/释放」分支。

### 风险与残余

| 项 | 说明 | 处置 |
|---|---|---|
| F2 仅窗口内生效 | `BearGate` 为内存态，进程重启后由 `runPrepGate` 在窗口内重新进入；未进入前仍按原退避 | 二次审查复核窗口内首轮路径；部署后观察实际重试间隔 |
| F1 只记一次 | 同场次同原因仅首条，后续轮次静默（符合「不刷屏」要求） | 若生产需要逐轮追踪，再评估采样 |
| F4 槽跳过日志仍含编队库 | 本次只压缩「回退自动」；`巨熊上车槽跳过` 单条仍可能较长（已有每槽一次节流） | 二次审查确认是否纳入后续优化 |
| F6 每 pending 每场一条 | 查询持续失败时只首条告警 | 二次审查确认是否需要按轮计数 |
| 生产验证 | 未部署、未操作生产机 | 运营部署阶段在下一打熊窗口观察 1–2 场 |
