### 2.2 Caddy 修复细节（重要）

- 直接 `sed -i` 修改 `/etc/caddy/Caddyfile` 会**替换 inode**，而 `lic-caddy` 的 bind mount 仍指向旧 inode → 容器内看到的仍是旧配置（8791），`caddy reload` 也加载旧内容。
- 处理：`docker rm -f lic-caddy` 后用原参数重建（保留 `lic_caddy_data` / `lic_caddy_config` 卷）：
  ```bash
  sudo docker run -d --name lic-caddy --restart unless-stopped \
    -p 80:80/tcp -p 443:443/tcp \
    --add-host host.docker.internal:host-gateway \
    -v /etc/caddy/Caddyfile:/etc/caddy/Caddyfile:ro \
    -v lic_caddy_data:/data -v lic_caddy_config:/config \
    caddy:2-alpine
  ```
- 重建后容器内确认 `reverse_proxy host.docker.internal:8790`，公共 `/v1/vault/hotconfig` 立即返回热更 JSON。
- 原 8791 是 sshd 反向隧道的 gateway 端口（`ss` 显示 `sshd` 持有），不是 vault-server；其背后旧实例已被新实例取代。
