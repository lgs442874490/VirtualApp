## 14. 工具箱：合并「真机抓包 + 真机监控」为「诊断」页（2026-11-10 22:5x）

### 14.1 背景

两个入口同区、同图标（TARGET）、描述都带"协议"，用户分不清；但数据源不同、不能互相替代：

| | 客户端抓包 | 服务端监控 |
|---|---|---|
| 数据源 | 本机 VpnService + tun2socks | 服务端 `POST /v1/vault/monitor` |
| 内容 | 原始 TCP 帧（sproto 实时解码） | 服务端任务级事件流（task/io/session/notify/mark） |
| 依赖 | 本机 VPN 授权 | 服务端部署监控接口 + `VAULT_MONITOR=on` |

### 14.2 实现

- 新增 `ProtoCapturePanel` / `MonitorPanel`：从原 Activity 抽出的可复用面板（宿主传入 Activity，生命周期由宿主转发），原 Activity 改为薄壳（保留旧入口兼容）。
- 新增 `DiagnosticActivity`：顶栏「诊断」+ 两个 tab（客户端抓包 / 服务端监控）+ 面板懒加载切换；只转发当前可见面板的生命周期，避免后台无谓轮询；`onActivityResult` 转发给抓包面板（VPN 授权）。
- `ToolBoxActivity`：两个卡片合并为一个「诊断」入口（`canCapture || canMonitor` 时显示），`toolCount` 同步改为合并计数。
- `AndroidManifest.xml` 注册 `DiagnosticActivity`（`exported=false`）。
