## 916 缺失因果链（三层）

1. **02:24 轮被跳过**：lastr:94450730:916 停在 10-13 18:10（顶号保护/登录失败不盖 lastr，
   符合设计）；但 913 同轮正常 → runAccountRoles 返回非 null → 调度排明天，916 当天无人补。
2. **22:12 补跑轮未执行**：nextRunAt=22:12，但 22:12 后零任务日志（最后一条 18:35:27）。
   设备 Android 14（SDK 34）：嫌疑 = 进程被杀后 START_STICKY 未复活 / 闹钟唤醒的前台服务启动
   受限 / Doze 推迟。无法远程完全定案。
3. **发现的相关 bug**：scheduleAlarmAt 所有账号共用 requestCode 1002 的同一 PendingIntent
   （Intent filterEquals 不含 extras）→ 巡检循环里后排账号覆盖前排账号的精确闹钟，
   任意时刻每类闹钟只剩最后一个账号的。多账号唤醒可靠性天然残缺。

## 非损失类问题

- activity_rewards 每日报"失败2"：实证错误码 = **month_card code 2（无在期卡）+
  vip_exp code 4501（已领）**，不在 tryClaim 白名单。快照证明物品均已领，无价值损失，纯汇报失真。
- daily_mission 偶报"响应无奖励字段，未确认到账"（DEGRADED）——响应形状存疑，无法从日志确认到账。
- ProtoLogger 1200 字符截断使 notify_achievement_info 等大协议在快照中不可解析（审计盲区）。

1. **角色级补跑**：runAccountRoles 增加 skipDoneToday——补跑轮对今日已跑角色短路（防重复
