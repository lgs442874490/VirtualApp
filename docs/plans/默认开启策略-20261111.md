# 每日任务「默认开启」策略与生产修复（2026-11-11）

> 本文是 2026-11-11 生产核查（11-09~11-11 每日任务完成情况）后的策略与修复记录。
> 代码分支：`modify/daily-default-on-20261111-0246`。

## 1. 背景

生产 `vault-server` 每日任务快照（`state.json`）显示：

- 3 个在线账户 / 6 个角色每日都有执行，但每角色每天只有 2–5 项真正领取成功，其余 50+ 项是“跳过”。
- 大量任务因 `配置未启用` 未执行：线上每个角色 61 项配置里有 21–28 项是旧默认 `false`。
- 晨曦岛 `free_store`（码 15018）、`weekly_diamond`（码 15071）每天每角色失败 15–21 次，持续 3 天。
- 卡 BP `card_bp`（码 8204，马国成）、军医所求助（码 1526，炎黄）阶段性失败。
- 测试账号 48460403 三个角色活跃度 0、宝箱 0 档，但 `daily_mission` 报“今日任务奖励已全部领取”。

## 3. 迁移（一次性，之后手动关仍生效）

- **App**：`DailyConfigStore` 在首次读取配置时执行一次迁移（`daily_config` 的 `config_defaults_version=1`），
  遍历 `meta` 与全部 `acc:` 配置，把新默认开任务的 `false` 改为 `true`；迁移后用户手动关的 `false` 不再被覆盖。
- **上传**：`VaultSync.syncFields` 随账号 JSON 上传 `configDefaultsVersion`。
- **服务端**：`VaultStore.Account.configDefaultsVersion`；
  - `load()`：旧库（无版本/低版本）迁移后写回 `vault.json`；
  - `/v1/vault/sync` 解析：旧客户端（无版本）上传的 false 按新默认迁移；新客户端带 current 版本，false 视为用户手动关；
  - `replaceAll` 跨 sync 继承版本。

## 4. 错误码修复（按“暂不可用/已领”处理）

| 码 | 任务 | 处理 |
|---|---|---|
| 15018 | 晨曦岛免费商店 | `tryStep` 白名单 + 当日去重台账（`free_store_day`） |
| 15071 | 晨曦岛每周钻石 | `tryStep` 白名单 + 当周去重台账（`weekly_diamond_week`） |
| 8204 | 卡 BP | 写 `card_bp_rx_<id>` 台账并停止本轮，不再记 ERROR |
| 1526 | 军医所联盟求助 | 归“当前不可求助”，子项标 skip 而非 fail |
| 4302/4303 + 活跃度 0 | 每日任务 | 改为 DEGRADED“活跃度 0，今日每日任务未推进”，不再误报“已全部领取” |

> 这些错误码仓库内没有官方含义表；本次按生产现象归为“暂不可用/已领”，并保留去重窗口。
> 若后续真机确认是可恢复条件，去掉对应去重即可。

1. 服务端：恢复上一版 `vault-server-all.jar`；`vault.json` 执行前备份（`vault.json.bak-defaulton-<时间>`）。

3. 配置迁移只写 `configDefaultsVersion` 与 false→true；回滚 jar 后旧逻辑按新配置继续执行。
