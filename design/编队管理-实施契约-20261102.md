## 1. 数据字段（T1）

`FormationStore.Hero` 新增：

```java
public int skillLevel;    // 队长第一个远征技能等级（0..5，0=未同步）
public int weaponLevel;   // 专武等级（0..10，0=未同步/无专武）
```

`parseHeroes` 宽容读取：

- skillLevel ← `expeditionSkillLevel` / `expedition_skill_level` / `skillLevel` / `skill_level` / `firstSkillLevel` / `first_skill_level`
- weaponLevel ← `weaponLevel` / `weapon_level` / `exclusiveWeaponLevel` / `exclusive_weapon_level` / `elv`

服务端 `FormationCatalog.Hero` 同步新增 `weaponLevel`、`expeditionSkillLevel`；
`heroOf` 读 `elv`（专武）与 `skills`（取 skill id = heroId*10+1 的 `lv`，即第一个远征技能；槽 0=基础技能，旧帧无槽 1 时回退槽 0），
`toMap` 输出 `weaponLevel` / `expeditionSkillLevel`。**旧帧/旧服务端缺字段 → 0，App 走降级。**

### 采集规则（6~9）

- 若该队长单独出征的容量（`catalog.capacityFor([captain])`）> 100000 → 只带队长；
- 否则补 2 名英雄：从（≥100000 判定后）未分配给**任何采集队列**的英雄里按战力降序取，排除其他采集队长/成员；
- 采集队列之间英雄不得重复。

### 熊上车规则（10~19）

- 按角色出征队列计算：英雄不可与「打熊队」重复，也不可在熊上车各队之间重复；
- 队长的第一个远征技能等级（`Hero.skillLevel`）优先 5 级：5 级队按上表顺序排在前；未满 5 级按等级降序、同级按上表顺序；
- 最多默认保留 6 队（按上述排序取前 6；不足 6 队有几队保留几队）；前 6 队之后仅作备选，不写入库；
- 每队补 2 名不冲突英雄（排除打熊队与已占用英雄，按战力降序）；
- 队长未拥有则跳过该队。

### 别名

`波根`→卢姆·波根；`米亚`→米娅；`杰赛尔`→杰塞尔；`尼莫`→赫罗尼莫；其余按 HeroCatalog 精确名。
