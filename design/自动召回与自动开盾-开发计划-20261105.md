## 2. 分支与提交策略（遵循 AGENTS.md）

- 从 `master` 新建分支：
  ```
  add/auto-recall-shield-20261105-HHmm
  ```
- 所有改动只在新分支进行；工作区现有未提交改动不动。
- 提交前先给用户“改动文件列表 + 说明”，确认后再 `git commit`。
- 合并回 `master` 同样需要用户确认。
- 建议拆成 3 个逻辑提交（仍需用户确认后执行）：
  1. 服务端配置/召回/开盾/购盾 + 单测；
  2. App 配置卡 + 校验 + 护盾数量展示；
  3. 回归/验收文档与修补。

- 新增内部类/工具：

  - `ShieldLedger`：`notify_city_item_init/update` 槽位 101 + `notify_backpack_init/update` 302301/302302/302305 + `notify_resource_init/update` 101 钻石。
- 两项功能必须共用上述工具，保证默认值/下限/未知行为一致。

## 6. 测试计划

### 6.1 服务端单测

| 用例 | 断言 |
|---|---|
| 默认值 | 未配置时 `eta_sec=2`、模式=`before_arrival` |
| 2 秒下限 | `1`/`0`/`-1` 被拒绝或回退 2；不出现“1 秒卡秒” |
| 空值/非数字 | 回退 2，日志告警 |
| 召回 ETA | 剩余 >2 挂起；≤2 发 `off_work`/`recall` |
| 召回阈值 | 低于阈值不发请求；未知兵力按保护优先 |
| 场景一·先到 | `E-N < A` → 在途 `recall` 立即/按 `E-N` 触发 |
| 场景一·同到 | `0 <= E-A < N` → 不落位，在途召回 |
| 场景一·加速 | `endtime` 提前跨阈值 → 立即重算并召回 |
| 场景二·跟随 | `E-N >= A && E < G` → 落位后按 `E-N` `off_work` |
| 场景二·采集结束后 | `E >= G` → 不召回 |
| 已落地 | `E <= now` / enemy state=3 → 立即召回并标注 |
| 同联盟/友盟 | 不召回；`aid` 未知保护优先 |
| 兜底轮询 | `req_world_mapobj.march_id != own` → 按状态召回 |
| 敌方撤回 | 取消挂起；无其他威胁不召回 |
| 开盾 ETA | 剩余 >2 挂起；≤2 发请求 |
| 开盾阈值 | 低于阈值不发请求；未知兵力按保护优先 |
| 护盾账本 | init + update 增量正确；101 槽 itemid/endtime 正确 |
| 钻石购盾 | 关=不买；开=买 302301×1 → 用盾 → 生效 2h；失败不重试 |
| 幂等/预算 | 8h 内不重复开；日上限；5min 失败冷却 |
| 兼容 | 旧 `gather_recall`/`eta_sec`/`troops_min` 行为不劣化 |

### 6.2 App 单测/手工

| 用例 | 断言 |
|---|---|
| 保存空值 | 提示且不落盘 |
| 非数字/负数/1 秒 | 提示且不落盘 |
| 模式切换 | 立即/抵达前 N 秒回显正确 |
| 开关持久化 | 防骚扰/钻石购盾保存后回显 |
| 护盾数量 | 在线/离线/未同步三种状态显示正确 |
| 角色切换 | 配置按角色隔离，不串号 |

### 6.3 真机灰度

- 采集点遭袭：观察点/真实攻击触发，核对状态行与实际召回。
- **极限场景双账号对拍**：A 号出发采集后，B 号小号分别制造“抢先到/同到/跟随/采集结束后到”四种情况，核对 A 的召回时点与协议；无法双开时用推送回放/观察点造事件。
- 城堡被攻击：侦查/进攻/集结各一次，核对卡秒时点与开盾结果。
- 钻石购盾：仅测试账号、显式开关、记录扣钻；默认关闭时验证零请求。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 钻石误花 | 真实资产损失 | 默认关；单次 1 个、日预算；失败不重试；先买后用分步校验 |
| 登录踢号 | 服务器会话短暂中断 | 沿用现有自愈；测试用测试账号；不在生产高峰做灰度 |
| `init` 快照过期 | 护盾/钻石数量显示错误 | `init + update` 账本；显示“未同步”而不是旧值 |
| 时钟未校准 | 卡秒偏差 | 沿用 `serverNowSec` 降级 + 告警；禁止在未校准下静默卡秒 |
| 资产库未 READY | 召回定位不到队伍 | 只提醒 + 明确文案；下一轮补扫 |
| UI 框架限制 | 输入框无法复用 | 专用配置卡优先；必要时扩展 `InputSpec` |
| 旧配置冲突 | 行为回退 | 兼容映射：旧 `gather_recall=true` → immediate；缺省键用默认值 |
| 采集点推送丢失/范围外 | 途中发现不了敌方 | 60 秒 `req_world_mapobj` 兜底；只保证落位后发现，状态明确说明 |
| 同联盟归属未知 | 误召回友军 | `aid`/昵称口径；未知时保护优先并留痕，便于复盘 |
| 召回来不及 | 仍可能接战 | 尽早触发；失败最多重试 2 次并告警；不承诺 100% 免战 |

## 8. 发布与回滚

- 发布前：单测全绿、真机验收通过、用户审核 diff。
- 发布顺序：先服务端（配置兼容、默认行为不变），再 App（UI 入口）。
- 回滚：
  - 关闭 `shield_buy_diamond` / 恢复旧 `eta_sec` 即可停购盾/卡秒；
  - 服务端保留旧键读取，App 回滚不影响旧配置；
  - 出问题优先关开关，不删配置。
