# 自动召回与自动开盾 · 需求文档

> 版本：v1.0（2026-11-05）
> 状态：需求冻结，待开发
> 适用代码基线：`master`（App + `vault-server`）
> 关联文档：`design/自动召回与自动开盾-开发计划-20261105.md`

---

## 1. 背景与目标

当前 `battle_shield` 已具备“反应式开盾 + 采集点遭袭提醒/可选撤矿”的应急能力，但与产品要求存在结构性差距：只有单个 `eta_sec` 数值、没有输入框、没有防骚扰开关、采集侧没有兵力阈值、没有护盾数量展示、没有钻石购盾，也没有完整的输入校验。

本需求的目标是补齐两套完整能力：

1. **自动召回**：采集点被攻击时，按“立即”或“抵达前 N 秒”自动召回在采队伍，并可用防骚扰开关 + 兵力阈值过滤小规模骚扰。
2. **自动开盾**：自身城堡被侦查/进攻/集结时，按“立即”或“抵达前 N 秒”自动开盾；展示当前护盾数量；背包无盾时可按开关用钻石购买 2 小时护盾；同样支持防骚扰开关 + 兵力阈值。

两项功能使用同一套定时模型、默认值和校验规则，避免“一个立即、一个卡秒”的不一致。

## 4. 功能需求

### 4.1 自动召回（采集点被攻击）

| 编号 | 需求 | 说明 |
|---|---|---|
| RC-01 | 识别采集点被攻击 | 来袭行军命中自己的资源点（`target.map_resource.uid==ownUid`），或 endpoint 坐标命中自己在采的 `type=4/state=3` 行军；命中后进入告警 |
| RC-02 | 提供两种召回模式 | 「被攻击立即召回」与「攻击抵达前自定义秒数召回」，二选一 |
| RC-03 | 自定义秒数输入框 | 数值输入，单位秒；默认 **2**；最小 **2**；建议最大 600 |
| RC-04 | 默认模式 | **抵达前 2 秒**（`before_arrival` + `eta_sec=2`） |
| RC-05 | 防骚扰开关 | 独立开关；关闭时忽略兵力阈值 |
| RC-06 | 兵力阈值输入框 | 数值输入；`0=不限`；仅防骚扰开启时生效 |
| RC-07 | 低于阈值不召回 | 来袭兵力已知且 `< 阈值` 时跳过，并写状态说明；兵力未知时按保护优先照常召回 |
| RC-08 | 召回协议 | 在途（state=2）用 `req_world_march_recall{id}`；驻扎（state=3）用 `req_world_march_off_work{id}` |
| RC-09 | 冷却与幂等 | 同一 `marchId` 10 分钟内不重复召回；失败只留痕，不风暴重试 |
| RC-10 | 状态展示 | App 状态行显示：当前模式、等待卡秒/已召回/低于阈值/未定位队伍等原因 |

**边界**：

- 资产库未 READY 时，保留“只提醒不召回”，并明确写“未定位到在采队伍”，不得假装已召回。
- 无 `endtime` 时执行“立即召回”，并留痕。

### 4.1.1 采集召回极限场景（本次补充）

> 目标：覆盖“出发时无人、临近抵达时敌方采集队抢先/加速进入”与“出发后有人跟随、落位后遭袭”两类极端场景。
> 原则：**同点匹配 + 时间窗口 + 状态机**；宁可提前召回，不把队伍送进已知战斗。

#### A. 术语与时间基准

| 符号 | 含义 |
|---|---|
| `A` | 我方抵达采集点时刻。`state=2` 时取该行军的 `endtime`；`state=3` 表示已抵达 |
| `G` | 我方采集结束时刻。`state=3` 时取该行军的 `endtime`；`state=2` 时未知，等 `state=3` 更新 |
| `E` | 敌方抵达同一采集点时刻，取敌方行军 `endtime` |
| `N` | 召回提前量，取配置 `gather_eta_sec`（默认 2，最小 2） |
| `now` | 服务器当前秒（`serverNowSec`） |

我方采集行军口径：

- `type=4`，`state=2`（在途）或 `state=3`（采集中）；
- 目标坐标取 `endpoint(x,y)`；
- `state=2` 的 `endtime` 是抵达时刻；`state=3` 的 `endtime` 是采集结束时刻（实测 7 小时级）；
- 只处理个人采集 `type=4`；联盟采集 `type=110` 仅识别、不自动召回（除非产品另行确认）。

#### B. 威胁判定条件

**同点匹配**（满足任一即可）：

1. 敌方 `endpoint(x,y)` == 我方采集点 `(x,y)`；
2. 敌方 `target.map_resource.uid == ownUid`，且坐标一致；
3. 敌方 `target_type=2`，且 `target` 坐标 == 我方采集点。

**敌方范围**：

- 只接受 `type=2`（出征/攻击）、`type=4/110`（采集/联盟采集）；
- 排除 `type=100/102`（集结主体，按 2026-11-04 watchpoint 口径，集结不会打采集点）；
- 排除 PvE 行军（巨兽/野怪/采集点自身字段）；
- 排除 `owner == ownUid`；
- 排除同联盟/同阵营友盟：优先用双方 `aid` 比对；`aid` 缺失时用昵称 `[abbr]` 兜底；仍未知 → 按保护优先视为威胁并留痕；
- 同一采集点出现多个敌方 → 取最早 `E`；任一满足即触发。

**敌方状态**：

- `state=2`：在途，按 `E` 计算；
- `state=3` 或 `E <= now`：已落地，视为即时威胁；
- `E <= 0`（缺 endtime）：无法卡秒，按保护优先立即召回并留痕。

#### C. 两类场景的判定与触发

**场景一：出发时无人，临近抵达时敌方采集队抢先/加速进入**

判定：

```text
E - N < A
```

含义：按“提前 N 秒召回”的规则，召回时点已经早于我方抵达；继续飞会直接落进战斗。包括：

- 敌方先到（`E < A`）；
- 敌方与我方几乎同时到（`0 <= E - A < N`）；
- 敌方 `endtime` 被加速提前后，重新满足上式。

触发时机：

- `E - N <= now`：立即召回（在途用 `req_world_march_recall`）；
- `E - N > now`：挂起到 `E - N` 再召回；
- 若挂起期间我方已抵达（`state=3`）：改走场景二判断；
- 若挂起期间敌方已落地（`E <= now`）：立即召回。

**场景二：出发后有人跟随，落位后可能遭袭**

判定：

```text
E - N >= A  且  E < G
```

含义：敌方在我方之后到，但会在我方采集结束前到；按 `E - N` 召回即可，既避免落位即被打，也不至于过早放弃采集。

触发时机：

- `state=2` 且 `E - N >= A`：先不召回，等 `state=3` 拿到 `G` 后再判断；
- `state=3` 且 `E < G`：
  - `E - N <= now`：立即撤矿（`req_world_march_off_work`）；
  - `E - N > now`：挂起到 `E - N`；
- `state=3` 且 `E >= G`：敌方在我方采集结束后才到，**不召回**；
- 敌方 `E` 被加速提前到 `E < G`：立即按上式重新判断；若 `E - N <= now` 立即撤矿。

**统一判定伪代码**：

```text
if (E <= 0 || E <= now) -> 立即召回
if (state == 2 && E - N < A) -> 场景一（在途召回）
if (state == 3 && E < G) -> 场景二（E-N 触发，已过则立即撤矿）
if (state == 2 && E - N >= A) -> 等 state=3 再判
if (state == 3 && E >= G) -> 不召回
```

#### D. 触发时机汇总

| 模式 | 触发点 |
|---|---|
| `immediate`（立即） | 检测到同点敌方即召回；若敌方已落地，立即召回 |
| `before_arrival`（抵达前 N 秒，默认 2） | `triggerAt = E - N`；`triggerAt <= now` 立即执行；否则挂起；场景一必须在我方抵达前完成（`E-N < A`），场景二可在落位后执行（`E-N >= A`） |

补充规则：

- 挂起期间敌方 `endtime` 提前（加速）→ 重新计算；跨过阈值立即触发；
- 挂起期间敌方 `del`（撤回/消失）→ 取消；若还有其他敌方，取新的最早 `E`；
- 我方 `state=2→3` → 重新计算；`E >= G` 则取消；
- 我方行军 `del`（已回/已结束）→ 清理 watch；
- 同一行军 10 分钟冷却；失败最多重试 2 次（间隔 60 秒），之后只告警不风暴重试；
- 召回已提交 → 不再重复提交。

#### E. 实现逻辑

1. **数据源**
   - 我方：核心资产库 `QUEUE` 中 `type=4`、`state=2/3` 的行军（`id/endX/endY/endTime/state/aid`）。
   - 敌方：`notify_world_situation_info_add/_up/_del`、`notify_world_alliance_situation_add/_update/_del` 推送；维护 `Map<enemyMarchId, EnemyMarch>` 缓存，`add/update` 合并字段，`del` 删除；`endtime` 变小标记“加速”。
   - 兜底：每 60 秒对每个在采/在途采集点发 `req_world_mapobj{kid,point}`，读 `mapobj.type==2 && map_resource.march_id`；`march_id != 0 && march_id != ownMarchId` → 该点已被其他行军占据，立即按状态召回。
2. **watch 状态机**
   - `GatherWatch{ownMarchId, x, y, state, A, G, scheduledAt, enemyId, recallState, attempts}`。
   - 每个 tick（1 秒）：
     - 刷新我方行军状态；
     - 遍历敌方缓存，做同点/时间判定；
     - 到点执行召回；
     - 清理已结束/已召回 watch。
3. **召回动作**
   - `state=2`：`req_world_march_recall{id}`；
   - `state=3`：`req_world_march_off_work{id}`；
   - 失败：记录 code，60 秒后重试 1 次，最多 2 次；仍失败写告警状态。
4. **状态与账本**
   - 状态行按场景输出：
     - 场景一：“敌方采集队#id 将于 X 秒后先到/同到 @(x,y)，早于我方 Y 秒 → 已在途中召回”；
     - 场景二：“敌方#id 跟随至 @(x,y)，预计 X 秒后到达，早于采集结束 Y 秒 → 已撤矿”；
     - 加速：“敌方#id 加速，ETA 提前至 X 秒 → 召回”；
     - 兜底：“地图复核发现 @(x,y) 已被其他行军占据 → 召回”；
     - 失败：“召回失败 code=...（已重试 N 次）”。
   - 账本 `gather_recall` 记录：我方 marchId、敌方 marchId、A/G/E/N、场景、触发原因、code。
5. **误报控制**
   - 同联盟/友盟/PvE/集结主体排除口径复用 2026-11-04 watchpoint 规则；
   - 只处理与自己在采点同点的行军，不做全图扫描；
   - `req_world_mapobj` 每点 60 秒一次，且仅在该点有 active 采集时发；
   - 同一敌方/同一我方行军去重，避免每次 tick 重复请求。

#### F. 边界与异常

| 场景 | 处理 |
|---|---|
| 资产库未 READY | 不召回，写“未定位采集队伍”；资产库恢复后下一 tick 重新评估 |
| 我方 `endtime` 缺失 | `state=2` 时按保护优先立即召回；`state=3` 时 `G` 未知，保守立即撤矿并留痕 |
| 敌方 `endtime` 缺失 | 按保护优先立即召回 |
| 敌方已落地 | `state=2` 在途召回；`state=3` 立即 `off_work`，并标注“可能已接战” |
| 敌方撤回/消失 | 取消挂起；无其他威胁则不召回 |
| 多队同点 | 每队独立 watch；一队召回不影响其他队 |
| 同联盟/友盟 | 不召回；`aid` 未知时按保护优先召回并留痕 |
| 推送丢失 | 60 秒 `req_world_mapobj` 兜底；只保证“落位后被发现”，不保证“途中提前发现” |
| 时钟未校准 | 使用服务器时钟；未校准降级本机并告警，卡秒误差写入状态 |

### 4.2 自动开盾（自身城堡被攻击）

| 编号 | 需求 | 说明 |
|---|---|---|
| SH-01 | 识别城堡被攻击 | 来袭 `type=1` 侦查、`type=2` 进攻、`type=100` 集结进攻，且目标 uid==本人；`type=5` 驻防/增援不触发 |
| SH-02 | 提供两种开盾模式 | 「被攻击立即开盾」与「攻击抵达前自定义秒数开盾」，二选一 |
| SH-03 | 自定义秒数输入框 | 默认 **2**；最小 **2**；建议最大 600 |
| SH-04 | 默认模式 | **抵达前 2 秒**（`before_arrival` + `eta_sec=2`） |
| SH-05 | 展示当前护盾数量 | 同时展示：当前生效护盾（槽位 101）剩余时间 + 背包护盾 `302301/302302/302305` 数量；数据未同步时显示“未同步” |
| SH-06 | 钻石购盾开关 | 独立开关，默认 **关**；开启后仅在“背包无护盾且风险触发”时购买 |
| SH-07 | 默认购买 2 小时护盾 | 固定使用 `itemId=302301`（2 小时）；实测价格 **400 钻石**；实现以服务端实际扣钻推送为准 |
| SH-08 | 防骚扰开关 | 独立开关；关闭时忽略兵力阈值 |
| SH-09 | 兵力阈值输入框 | 数值输入；`0=不限`；仅防骚扰开启时生效 |
| SH-10 | 低于阈值不开盾 | 已知兵力 `< 阈值` 时跳过并写状态；未知兵力按保护优先照常开盾 |
| SH-11 | 开盾顺序 | 优先用当前免费盾（`req_city_item_free_use`）；其次用背包盾（`req_use_item`）；最后按开关走钻石购盾 |
| SH-12 | 购盾+用盾原子性 | 先 `req_shop_quick_buy{use:false}` 买入，校验 `notify_backpack_update add 302301`，再 `req_use_item` 使用；任一步失败即止损，不重试风暴 |
| SH-13 | 幂等与预算 | 开盾成功以护盾账本到期为幂等判据（不再固定 8h 窗）；购盾单次最多 1 个、每次攻击最多 1 次、**每日钻石预算用户可配**（默认 **1200 钻/日**，0=不购买，按 400 钻/个换算，另设日个数硬上限 10）；失败 5 分钟冷却 |

**护盾状态口径（实测）**：

- 生效护盾看 `notify_city_item_init/update` 的 `id=101` 槽位：`itemid`、`starttime`、`endtime`。
- `notify_town_interaction_info.shield_end_ts` 在实测中始终为 0，**不得作为开盾判断依据**。
- 背包与钻石：`notify_backpack_init/update`、`notify_resource_init/update` 必须维护“init 快照 + update 增量”的实时账本；`init` 不会因购买自动刷新。

### 4.3 一致性与默认值

| 编号 | 需求 |
|---|---|
| CN-01 | 两项功能使用同一套定时模型：立即 / 抵达前 N 秒 |
| CN-02 | 两项功能的默认值一致：`N=2`，默认模式 `before_arrival` |
| CN-03 | 两项功能的 2 秒下限一致：自定义秒数 `<2` 一律拒绝 |
| CN-04 | 两项功能的未知 `endtime` 行为一致：按保护优先立即执行并留痕 |
| CN-05 | 两项功能的防骚扰语义一致：开关关闭忽略阈值；兵力未知按保护优先 |

### 4.4 输入校验

| 编号 | 场景 | 期望 |
|---|---|---|
| VL-01 | 秒数为空 | 拒绝保存，提示“请输入秒数” |
| VL-02 | 秒数非数字 | 拒绝保存，提示“秒数必须是数字” |
| VL-03 | 秒数负数 | 拒绝保存，提示“秒数不能为负数” |
| VL-04 | 秒数 `<2` | 拒绝保存，提示“秒数不得低于 2 秒” |
| VL-05 | 秒数 `>600` | 拒绝保存，提示上限（上限可按产品调整） |
| VL-06 | 兵力阈值为空 | 拒绝保存，提示“请输入兵力阈值（0=不限）” |
| VL-07 | 兵力阈值非数字 | 拒绝保存，提示“兵力阈值必须是数字” |
| VL-08 | 兵力阈值负数 | 拒绝保存，提示“兵力阈值不能为负数” |
| VL-09 | 服务端收到非法值 | 记录告警日志并回退安全默认（秒数 2、阈值 0），不得静默变成“立即”/“禁用阈值” |

**校验实现要求**：

- App 保存前校验，错误就地提示、不落盘。
- 服务端 `TaskContext` 读取后再校验一次，防御旧版本/手工改配置。
- 共用同一个解析函数，避免两套逻辑。

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| NF-01 | 安全：钻石购盾默认关；开启后单次/日预算硬上限；失败不重试风暴 |
| NF-02 | 安全：不覆盖用户已有护盾；已有生效护盾时优先复用，不重复购买 |
| NF-03 | 时钟：使用服务器时钟；未校准时降级并告警，卡秒误差可解释 |
| NF-04 | 角色隔离：配置与状态按 `fpid:sid:uid` 隔离，active 角色才镜像旧键 |
| NF-05 | 兼容：旧 `gather_recall` / `eta_sec` / `troops_min` 配置可读；新键缺失时有默认值 |
| NF-06 | 可观测：状态行 + FileLog + 账本，至少能回答“为什么没触发/为什么买了” |
| NF-07 | 防风暴：同一事件/同一行军不重复请求；召回 10 分钟冷却；开盾 5 分钟失败冷却 |
| NF-08 | 性能：事件钩子只解析+置脏；请求在会话线程/执行器串行，不阻塞推送线程 |

## 6. 配置模型

```json
{
  "battle_shield": {
    "sub": {
      "enabled": true,
      "free": true,
      "reactive": true,
      "force_online": false,
      "gather_attack": true,
      "gather_recall": true,
      "gather_mode": "before_arrival",
      "gather_anti_harass": false,
      "shield_mode": "before_arrival",
      "shield_anti_harass": false,
      "shield_buy_diamond": false
    },
    "strategy": {
      "gather_eta_sec": "2",
      "gather_troops_min": "0",
      "shield_eta_sec": "2",
      "shield_troops_min": "0",
      "shield_diamond_budget": "1200",
      "gather_watch_poll_sec": "60"
    }
  }
}
```

- `*_mode`：`immediate`（立即）或 `before_arrival`（抵达前 N 秒）。
- `gather_recall`：保留为召回总开关；缺省时按旧数据兼容（true→immediate）。
- `*_eta_sec`：仅 `before_arrival` 生效，默认 `2`，范围 `2..600`。
- `*_troops_min`：`0=不限`；仅防骚扰开关开启时参与判断。
- `shield_buy_diamond`：默认 `false`。
- `shield_diamond_budget`：每日钻石预算（钻），默认 `1200`（≈3 个 × 400）；`0=不购买`；范围 `0..100000`；按实测 400 钻/个换算可买个数，另设日个数硬上限 10。
- `gather_watch_poll_sec`：采集点兜底轮询间隔，默认 `60` 秒；仅在该点有 active 采集时发 `req_world_mapobj`。

## 7. 协议实证（2026-11-05 真机抓包）

### 7.1 道具 id

| itemId | 名称 | 实测时长 |
|---|---|---|
| **302301** | **2小时防护罩** | **7200 秒** |
| 302302 | 8小时防护罩 | 28800 秒（免费盾同款） |
| 302305 | 12小时防护罩 | 43200 秒 |

### 7.2 使用背包护盾

```text
req_use_item {"id":302301,"count":1,"extra":{}}
→ {"code":0}
→ notify_backpack_update {"type":"del","data":[{"id":302301,"count":1}]}
→ notify_city_item_update {"info":{"id":101,"itemid":302301,
   "starttime":1793819764,"endtime":1793826964,"cd_endtime":0}}
```

- `endtime - starttime = 7200` 秒，确认 2 小时。
- 生效护盾槽位固定为 `id=101`。

### 7.3 钻石购买 2 小时护盾

```text
req_shop_quick_buy {"id":302301,"count":1,"use":false,"extra":{}}
→ {"code":0}
→ notify_resource_update {"type":"del","data":[{"id":101,"count":400}]}
→ notify_backpack_update {"type":"add","data":[{"id":302301,"count":1}]}
```

- 实测扣 **400 钻石**。
- `use:false` 只入背包；实现应随后显式 `req_use_item`。
- `init` 快照不刷新，实时账本必须叠加 `update`。

### 7.4 召回协议

- 在途：`req_world_march_recall{id}`
- 驻扎：`req_world_march_off_work{id}`

## 8. 验收标准

### 8.1 功能验收

| 编号 | 验收动作 | 期望 |
|---|---|---|
| AC-01 | 采集点被攻击，模式=立即，召回开 | 收到推送后立即发召回；状态显示已召回 |
| AC-02 | 采集点被攻击，模式=抵达前 2 秒 | 剩余 >2 秒时挂起；到剩余 ≤2 秒才发召回 |
| AC-03 | 采集点被攻击，防骚扰开、阈值 5000、来袭 1000 | 不召回，状态显示低于阈值 |
| AC-04 | 采集点被攻击，防骚扰开、兵力未知 | 按保护优先召回，状态留痕 |
| AC-05 | 城堡被侦查/进攻/集结，模式=立即 | 立即开盾 |
| AC-06 | 城堡被攻击，模式=抵达前 2 秒 | 到剩余 ≤2 秒才开盾 |
| AC-07 | 城堡被攻击，防骚扰开、阈值 10 万、来袭 5 万 | 不开盾，状态显示低于阈值 |
| AC-08 | 当前有免费盾 | 优先免费盾，不买钻石盾 |
| AC-09 | 背包有 302301/302302 | 按优先级用背包盾，不买钻石盾 |
| AC-10 | 背包无盾、钻石购盾开、风险触发 | 买 302301 ×1（扣 400 钻）→ 使用 → 生效 2 小时 |
| AC-11 | 背包无盾、钻石购盾关 | 不购买，状态说明原因 |
| AC-12 | 护盾数量展示 | 生效护盾剩余时间 + 背包 302301/302302/302305 数量正确 |
| AC-13 | 输入空值/非数字/负数/1 秒 | 保存被拒绝并提示；配置不落盘 |
| AC-14 | 服务端收到非法配置 | 回退 2 秒/0 阈值并告警，不静默变立即 |
| AC-15 | 场景一：出发时无人，敌方采集队 `E-N < A` | 在途立即/按 `E-N` 召回，使用 `req_world_march_recall` |
| AC-16 | 场景一：敌方 `endtime` 加速提前，跨过阈值 | 重新计算后立即召回，状态标注“加速” |
| AC-17 | 场景二：敌方跟随，`E-N >= A` 且 `E < G` | 落位后按 `E-N` 撤矿，使用 `req_world_march_off_work` |
| AC-18 | 场景二：敌方 `E >= G`（采集结束后才到） | 不召回，状态说明“采集结束前不会到” |
| AC-19 | 敌方已落地（`E <= now`/state=3） | 在途立即召回；已落位立即 `off_work` 并标注可能已接战 |
| AC-20 | 同联盟/友盟/PvE/集结主体 | 不召回；`aid` 未知时保护优先并留痕 |
| AC-21 | 推送丢失，`req_world_mapobj` 发现 `march_id` 非己方 | 按状态召回，状态标注“地图复核” |
| AC-22 | 敌方撤回/消失 | 取消挂起；无其他威胁则不召回 |
| AC-23 | 多队同点/多个敌方 | 每队独立；多个敌方取最早 `E`，任一满足即触发 |
| AC-24 | 城堡被攻击，敌 `endtime` 加速提前（剩余 167→20 秒以内，或连续 3 次 50% 加速） | 当拍开盾并唤醒独立执行器：剩余 ≤20 秒，或连续加速 ≥3 次且累计提前 ≥ 初始剩余一半，即视为紧急；不得等"剩余 ≤2 秒"（2026-11-13 事故：到达后约 4 秒才开盾） |
| AC-25 | 加速后剩余仍 > 安全余量（如 120 秒） | 继续挂起，不提前浪费盾 |
| AC-26 | 挂起期间敌方已到达（`remain < 0`，仍在保鲜期内） | 仍按保护优先补盾，状态/日志标注"敌方已到达，可能已接战" |

### 8.2 回归验收

- 旧配置（只有 `gather_recall`/`eta_sec`/`troops_min`）行为不劣化。
- 免费盾每日任务、战争态召回、守护盟友逻辑不受影响。
- App 单测、`vault-server` 单测全绿。
- 真机灰度≥1 个账号、≥1 次真实采集点遭袭/城堡被攻击场景。

## 9. 风险与待确认

| 风险/待确认 | 说明 | 建议 |
|---|---|---|
| 防骚扰默认值 | 需求未指定开关默认 | 默认关（保护优先），阈值 0；产品可改 |
| 钻石日预算 | 需求未指定上限 | 默认 **1200 钻/日**（用户可在 App 输入，0=不购买），按 400 钻/个换算；日个数硬上限 10 |
| 2 小时价格浮动 | 实测 400 钻，可能随账号/区服变化 | 不硬编码价格；以 `notify_resource_update` 实际扣钻为准，超预算止损 |
| `init` 快照过期 | 购买后 `notify_backpack_init` 不刷新 | 必须维护 init+update 账本 |
| 时钟未校准 | 卡秒会偏 | 沿用现有降级 + 告警 |
| UI 框架限制 | 通用子项卡只支持开关/chips | 新增专用配置卡或扩展 `InputSpec` |
| 推送范围/丢失 | 敌方行军可能不在观察点推送范围，或推送丢失 | 60 秒 `req_world_mapobj` 兜底；只保证落位后发现，不保证途中提前发现 |
| 同联盟归属未知 | 可能误召回友军 | `aid`/昵称口径；未知时保护优先但状态留痕，便于复盘 |
| 召回来不及 | `E-N` 太短/回程耗时，仍可能接战 | 尽早触发；失败最多重试 2 次并告警；不承诺 100% 免战 |
