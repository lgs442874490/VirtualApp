# 反应式开盾服务器化（P1-2）— 2026-10-19

> 分支：`modify/reactive-shield-20261019-0021`（未 commit，待人工审核）

## 背景与缺口

统一自动化后任务只在 vault-server 执行，客户端 `DailySchedulerService.onGameEvent` 已改为
no-op（server-only ignore）。原 WAR/RECON → 免费护盾链路随之失效：服务器常驻会话收到
"被攻击/侦查"时没有任何反应，服务端无对应实现。本设计补上该缺口，行为对齐原版。

## 方案

新增 `ServerShieldResponder`（与 `ServerHelpResponder` 同构：钩子线程只解析+置脏，
会话线程 tick 驱动动作），挂载于 `SessionKeeper.LiveSession`：

```
游戏推送(钩子线程)                会话线程 tick(1s 节拍)
notify_world_situation_info_add/_up      ┌─ online? 否 → 不开盾（让位保护）
notify_world_alliance_situation_add/_up   ├─ 事件保鲜(10min)? 否 → 丢弃
        │                                 ├─ 冷却中? 是 → 跳过（幂等）
        ▼                                 └─ 门控：automation ∧ reactive≠false
  classify: type=1侦查/2=进攻                    │
  target_type=1 攻玩家城                         ▼
  atk_city.targetid == 本人uid            ServerTasks.freeShield(tc)
        │                                 （free_id 动态取 / 码表归 SKIPPED）
        ▼                                         │
     dirty=true                              FileLog + mod:fpid:sid:battle_shield
```

### 触发源与协议口径（实证见 design/守护盟友-协议实证-20261015.md）

| 项 | 口径 |
|---|---|
| 推送 | `notify_world_situation_info_add/_up`（观察哨系列）+ `notify_world_alliance_situation_add/_update`（目标系列） |
| type | 1=侦查(RECON)、2=进攻(WAR)；5=驻防不触发 |
| target_type | 1=玩家城；非 1（打野/情报类）不触发 |
| 目标 uid | `atk_city.targetid` 优先，退化 `target.map_city.uid`；**必须等于本角色 uid** |

只防自己城：他城被进攻/无守方 uid 的观察哨推送不触发——不为邻城 attack 浪费每日免费盾。

### 门控

1. 账号自动化开启（`auto`/`keep` 统一开关，`VaultStore.Account`）；
2. 子开关 `battle_shield.reactive != false`（默认 true，App FnDetail 同款；经
   `TaskContext.subOn` 读 App 同步的角色参数）。

### 幂等与冷却

- 开盾成功（8 小时护盾）→ 8 小时内不重复开；
- 其余结果（今日已用/城市道具未同步/协议异常/错误码）→ 5 分钟重试冷却，防推送风暴；
- 事件保鲜 10 分钟：超过才被处理则丢弃——让位/掉线期积压的事件自然过期，回连后不为旧攻击补盾。

### human_first 让位保护

tick 只在会话 `online` 时执行（LiveSession 亦只在 online 分支调用，且排在采集/互助之前）：
人玩期间服务器不发任何请求，不互踢；推送到达后人恰好在此时上线，事件要么在保鲜期内
回连补盾，要么过期丢弃。

### 留痕

- `FileLog.info`：每次反应式开盾的门控结果与 outcome 分类；
- `mod:fpid:sid:battle_shield` 的 `reactive` 子项（文案 + `_ts` + `_trg=反应式`），
  经 `/v1/vault/state` 同步回 App，FnDetail/今日页同键展示。

## 改动文件

| 文件 | 改动 |
|---|---|
| `vault-server/.../ServerShieldResponder.java` | 新增：推送解析/门控/幂等/让位保护/留痕 |
| `vault-server/.../SessionKeeper.java` | LiveSession 增 `shield` 字段；登录后挂载；online tick 调用（采集/互助之前） |
| `vault-server/.../task/ServerTasks.java` | `freeShield` 可见性 static → public static（供响应器复用，逻辑零改动） |
| `vault-server/.../test/.../ServerShieldResponderTest.java` | 新增 12 条单测 |

## 测试（`cd vault-server && ./gradlew test --offline`）

- 基线 76/76 + 新增 12 = **88/88 全绿**（0 fail / 0 skip）。
- 覆盖：WAR/RECON 推送触发开盾（断言 free_id=42 来自 notify、非写死 1）、重复推送幂等只开一次、
  码 51/6151/6158/7501/4303 归 SKIPPED 且走 5 分钟冷却、无 city_item 推送不发请求、
  reactive 关闭不触发、automation 关闭不触发、takeover 期间不开盾不互踢且回连补盾、
  陈旧事件丢弃、他城/驻防/非玩家城目标不触发、观察哨无目标 uid 不触发、classify 单元语义。

## 已知限制（留待后续）

1. 观察哨系列推送不带守方 uid，无法确认是本人城 → 不触发；若实证无联盟玩家的
   `notify_world_alliance_situation_*` 不推送攻击事件，则该场景反应式不生效，
   由每日定时免费盾（battle_shield 整轮）兜底。
2. 免费盾为每日一次：当日已用时游戏返回码表 SKIPPED，反应式重试也要等次日——
   这是游戏规则，非实现缺口。

# P1-A 断线分类修复（2026-10-19 追加，来源：ZCode 真机回归报告）

## 问题

真实断线未判 SESSION_CLOSED：`ServerTasks.classifyException` 只查顶层 `e.getMessage()`，
而 `GameProtocolClient.request` 把协议异常包装为 `"协议调用失败: <proto>"`（cause 才是
`"连接已关闭"` / `"等待协议响应超时"` / `"发送协议数据失败"` 等）。实测杀出口后整轮
19 个任务全落 ERROR(st=3)、summary 无“会话中断”、`srv:lastrun` 被写 →
RoundScheduler 当日不再自动重试，与“断线可重试”语义相反。

## 修复

1. **`ServerTasks.classifyException` 沿 cause 链匹配**：新增 `causeChain()` 拼接
   “顶层 message + 最多 5 层 cause”（`MAX_CAUSE_DEPTH`，同时防爆栈/防互环），
   对整链匹配 `SESSION_CLOSED_MARKS`；命中仍写原文案 `"会话中断（可重试）：…"`，
   未命中走 ERROR 兜底（class 名 + 全链进展示，排障可见）。`brief` 仅截断展示、不参与判定。
   顶层即命中的输出与旧行为逐字一致（无 cause 时 chain == 原 msg）。
2. **P2-1 `RoundRunner.appendSub` 子项分类**：子项 skip 原先经 `!fail` 传入写成
   `cat=CLAIMED/ok=true`（“已检查但无可领”被记成领取成功）。改为显式传 cat：
   `ok:→CLAIMED / skip:→SKIPPED / fail:→ERROR`，与同处 `st` 口径（2/4/3）一致。

## 测试（新增 8 条，总 96/96 全绿）

- `SessionClosedTruncationTest` +7：包装形态 `协议调用失败: req_x ← 连接已关闭` → SESSION_CLOSED；
  timeout 包装（3 层）→ SESSION_CLOSED；5 层深链 → SESSION_CLOSED；超 5 层封顶 → ERROR；
  互环 cause 不死循环；顶层命中文案与旧行为一致；非断线 cause 仍 ERROR 且全链可见。
- `RoundRunnerTest` +1：子项 ok/skip/fail → cat=CLAIMED/SKIPPED/ERROR 与 st=2/4/3 对齐。

## 备注（未改动，留观察）

- 旧 `RoundRunner`（VAULT_LEGACY_ROUND=1 回退路径）在整轮被 SESSION_CLOSED 截断后仍写
  `srv:lastrun`（当日不重试），与 `ModularRoundRunner` 的 `!sessionClosed` 保护不对称；
  字段默认走模块化路径，本次不扩大改动面，如启用回退路径需一并补上同款 guard。
- App 端 `DailyTasks.classifyException` / `LogStore.applySubResults` 存在同款“只查顶层 /
  skip 记 ok”问题；服务器模式下 App 调度已 no-op，暂不同步改动，避免无关代码变动。
