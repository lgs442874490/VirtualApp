## 1. 背景与目标

### 1.1 现状（只读调研结论）

| 项 | 现状 |
|---|---|
| 兑换码服务端 | Go 单二进制 `license-server`（SQLite）：`license_code`（type=month/permanent、tier=1/2/3、status=active/revoked/exhausted、duration_days、expire_at、remark、created_by）、`device_binding`（一码一机）、`verify_log`（activate/verify/rebind/revoke 全量流水） |
| 管理方式 | **只有 CLI**（issue/list/revoke/rebind），无 Web 后台（原 PRD 将图形后台列为 P2） |
| App 端功能门控 | `FeatureGate` 为唯一事实源，**硬编码** 39 个功能 key 的 `minTier/implemented/debugOnly`；服务端只下发 tier |
| GM | 不存在任何 GM 概念 |
| 热更新 | `hotconfig.json` 支持 `nums/catalogs/claims/disabled` + `apk` 整包提示；**明确不做代码/Dex 加载** |
| 多开限制 | 未发现账号数量限制（"无限多开"当前天然成立） |

### 1.2 目标

1. 在 `license-server` 内置 Web 管理后台（`/admin`）：单管理员口令登录，完成兑换码全生命周期管理与功能权限矩阵配置。
2. 服务端建立"角色 → 功能"权限矩阵（T1/T2/T3/GM），App 端通过 activate/verify 响应获取并本地缓存，覆盖硬编码默认值，实现**后台保存、App 下次启动生效**。
3. 输出"新增活动功能热更启用"可行性评估，明确可行范围与交付边界。

## 3. 用户与场景

| 角色 | 说明 | 关键场景 |
|---|---|---|
| 运营管理员 | 持有 `LICENSE_ADMIN_PASSWORD` 的人 | 登录后台 → 批量发码 → 查码/停用 → 看使用记录 → 配功能矩阵 → 查审计 |
| 普通用户（T1） | 持有 T1 兑换码并激活 | 仅分身相关功能；账号数量不限（无限多开） |
| 普通会员（T2） | 持有 T2 兑换码 | 按矩阵开放部分日常功能 |
| 高级会员（T3） | 持有 T3 兑换码 | 按矩阵开放部分高阶功能 |
| GM | 持有 GM 码并激活 | 全部**已实现**功能开放；未实现/debug 项仍隐藏 |
| App 用户 | 任意已激活用户 | App 下次启动/进主界面时 verify 拉取新矩阵并生效 |

## 4. 功能需求（参数级）

### 4.1 管理后台基础

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-ADMIN-01 | 后台入口 | `https://cs.888syd.xyz/admin`（Caddy 反代到同一 license-server，无新增端口/服务） |
| REQ-ADMIN-02 | 登录 | `POST /admin/api/login`，body `{password}`；口令来源环境变量 `LICENSE_ADMIN_PASSWORD`（**≥16 字符**，未设置时后台一律 503 并提示"未配置管理员口令"）；成功下发 `HttpOnly; SameSite=Strict; Path=/admin` 会话 cookie，有效期 **8 小时**；同一 IP 连续失败 **5 次锁 10 分钟**；口令比对用常量时间比较 |
| REQ-ADMIN-03 | 会话 | 所有 `/admin/api/*`（除 login）校验会话；过期返回 HTTP 401 + 信封 code；前端跳登录页 |
| REQ-ADMIN-04 | 请求保护 | 写操作校验 `Origin`/`Referer` 与 Host 一致（或携带 CSRF token）；全部 JSON body ≤ 1MB |
| REQ-ADMIN-05 | 页面 | 单页应用（原生 HTML/CSS/JS，`//go:embed` 进二进制，无构建链）：登录、概览、兑换码列表、兑换码详情、功能权限矩阵、功能目录、操作审计 |
| REQ-ADMIN-06 | 操作审计 | 表 `admin_audit`：`id/created_at/actor/action/target_type/target_id/detail(JSON)/ip`；记录登录、生成、停用、启用、矩阵保存、矩阵重置；**不可删除/编辑**；后台分页查看（默认 50/页） |
| REQ-ADMIN-07 | 日志纪律 | 服务端日志不落明文兑换码，只落 `code_id`；后台列表页可展示明文码（管理员必需） |
| REQ-ADMIN-08 | 概览 | 展示：码总数、未使用、已激活、已过期、已停用、7 日新增、7 日激活、按角色分布、按类型分布、最近 20 条审计 |

### 4.2 兑换码生成

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-CODE-01 | 批量生成 | 单次数量 **1–100**（整数，越界拒绝并提示）；类型 `month`（30 天）/`permanent`（永久）；等级 `1/2/3/GM`；备注可选 ≤100 字（默认空）；`created_by = admin` |
| REQ-CODE-02 | 码格式 | 沿用现有：15 位随机 + 1 位加权校验位，展示 `XXXX-XXXX-XXXX-XXXX`；剔除易混字符；DB 存 `code` 与 `code_hash`（SHA-256） |
| REQ-CODE-03 | 生成事务 | 单次批量在**一个事务**内完成：任一条唯一冲突自动重试（每条最多 5 次），仍失败则整批回滚并返回错误 |
| REQ-CODE-04 | 有效期 | `month`：激活时 `expire_at = activated_at + 30 天`；`permanent`：`expire_at = NULL`；本期不支持自定义天数/指定日期 |
| REQ-CODE-05 | 生成结果 | 展示本次生成的码列表（码、类型、等级、备注、创建时间）；支持一键复制与导出 CSV（UTF-8 带 BOM，列：code,type,tier,remark,created_at） |
| REQ-CODE-06 | GM 码 | 等级 `GM`：DB 存 `is_gm=1`（逻辑第 4 档，避免重建 `CHECK(tier IN (1,2,3))` 表）；同为一码一机、受有效期约束；activate/verify 下发 `role=4`（`tier` 字段仍回 3，兼容旧 App）；GM 仅对 `implemented=true` 且非 `debugOnly` 的功能全开 |

### 4.3 查询与筛选

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-CODE-10 | 列表字段 | code、类型、等级（T1/T2/T3/GM）、状态（active/revoked）、使用状态（4 态）、绑定设备标签、激活时间、到期时间、剩余天数、备注、创建时间 |
| REQ-CODE-11 | 筛选条件 | 状态（全部/active/revoked）、使用状态（全部/未使用/已激活/已过期/已停用）、等级（全部/1/2/3/GM）、类型（全部/month/permanent）、关键词（code 前缀/备注/设备标签，LIKE，≤64 字）、创建时间范围、到期时间范围；条件之间 AND |
| REQ-CODE-12 | 分页与排序 | 每页 20/50/100（默认 20）；返回总数与总页数；排序：创建时间倒序（默认）/到期时间升序 |
| REQ-CODE-13 | 导出 | 导出**当前筛选结果**（上限 10,000 条；超出时响应头 `X-Export-Truncated=true` + `X-Export-Total=<总数>`，前端提示"请缩小筛选范围"）；CSV 字段同列表（不含 `code_hash`） |
| REQ-CODE-14 | 批量操作 | 勾选后批量停用/启用（≤100 条/次）；逐条失败汇总返回 |

### 4.4 启用 / 停用

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-CODE-20 | 停用 | `active → revoked`；写 `revoked_at=now`、`revoke_reason`（后台必填，默认"后台停用"）；写审计；**verify API 按冻结契约返回 `code=0` + `data.status=revoked`**（不改既有错误码口径），后台使用记录以 `result_code=1004` 落库供"失败"筛选；App 按 `status` 进锁定页 |
| REQ-CODE-21 | 启用 | `revoked → active`；清空 `revoked_at/revoke_reason`；**保留原绑定与原到期时间，不重算**；写审计 |
| REQ-CODE-22 | 边界 | 已过期码不可"启用"（拒绝并提示）；对已停用码再次停用为幂等成功提示；对 active 码启用为幂等提示 |
| REQ-CODE-23 | 绑定关系 | 停用不解除设备绑定、不重置换绑计数；重新启用后原设备可继续使用 |

### 4.5 使用状态（4 态）

| 编号 | 状态 | 判定（优先级从上到下） |
|---|---|---|
| REQ-CODE-30 | 已停用 | `status = revoked` |
| REQ-CODE-31 | 已过期 | `status = active` 且 `permanent = false` 且 `expire_at < now` |
| REQ-CODE-32 | 已激活 | `status = active` 且 `activated_at` 非空且未过期 |
| REQ-CODE-33 | 未使用 | `status = active` 且 `activated_at` 为空 |
| REQ-CODE-34 | exhausted 兼容 | 仅当历史数据存在 `status=exhausted` 时展示为"已用尽（历史）"，不产生新数据；不再新增 exhausted 写入点 |
| REQ-CODE-35 | 剩余天数 | month：`ceil((expire_at-now)/1天)`，最小 0；permanent 显示"永久"；未使用显示"—" |

### 4.6 使用记录

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-CODE-40 | 记录范围 | 沿用 `verify_log` 全量逐条落库、**永久保留**：activate/verify/rebind/revoke；后台启停/矩阵变更写 `admin_audit`，不写入 `verify_log` |
| REQ-CODE-41 | 详情展示 | 时间（浏览器本地时区）、动作、结果（结果码+文案）、设备标签、IP、UA（截断 200 字）、该码累计 verify 次数（按 `verify_log` 全量统计，含成功/失败） |
| REQ-CODE-42 | 筛选与分页 | 动作（全部/activate/verify/rebind/revoke）、结果（全部/成功/失败）、时间范围；分页 50/100（默认 50），时间倒序 |
| REQ-CODE-43 | 导出 | 当前码的使用记录导出 CSV（上限 10,000 条；超出同 REQ-CODE-13 用响应头提示截断） |
| REQ-CODE-44 | 性能 | `verify_log(code_id, created_at)` 已有索引；详情页查询 < 500ms（单码 10 万条量级） |

### 4.7 功能目录与权限矩阵

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-FEAT-01 | 功能目录 | 以 `FeatureGate.Feature` 现有 **39 个 key** 为唯一目录；表 `feature_catalog`：`key/label/default_tier/implemented/debug_only/sort`；服务端内置 seed，启动时 upsert（`key` 唯一）；后台只读展示，支持按等级/实现状态筛选 |
| REQ-FEAT-02 | 矩阵 | 表 `role_feature(role INTEGER, feature_key TEXT, visible INTEGER, PRIMARY KEY(role,feature_key))`，role ∈ {1,2,3,4(仅展示)}；默认 seed 见 §4.7.1 |
| REQ-FEAT-03 | 勾选规则 | `implemented=false`：矩阵中置灰 + "未实现"，任何角色不可勾选；`debugOnly=true`：置灰 + "仅调试包"，不可勾选（构建类型决定，release 始终隐藏） |
| REQ-FEAT-04 | GM 列 | **只读全开**（用户原话"gm 拥有全部功能"）：GM 列 = 全部 `implemented && !debugOnly`（21 项）勾选且不可取消 |
| REQ-FEAT-05 | 保存 | 提交 T1/T2/T3 三列的完整矩阵（39×3 行）；校验 role/key 合法、未实现/debug 项不得为 true；单事务写库；写一条 `admin_audit`（含变更 diff：新增/移除的 key）；保存后**服务端立即生效**，App 下次 verify 拿到 |
| REQ-FEAT-06 | 展示 | 矩阵表格：行=功能（key、中文名、实现状态、默认等级），列=T1/T2/T3/GM；顶部统计每列已勾选数；提供"显示全部/仅已实现"过滤；"未建 key 的 UI 跟随所属页面"说明常驻 |
| REQ-FEAT-07 | 重置 | "恢复默认矩阵"：按 §4.7.1 seed 覆盖，二次确认 + 审计（记录旧→新 diff 摘要） |
| REQ-FEAT-08 | 并发 | 以最后一次保存为准；每次保存写审计（含操作时间/IP） |

### 4.8 App 端下发与生效

| 编号 | 需求 | 参数与规则 |
|---|---|---|
| REQ-APP-01 | 协议扩展 | `POST /v1/activate` 响应 `data.ticket.role`（1–4）与 `data.ticket.features`（string[]，按 key 字典序）；`POST /v1/verify` 响应 `data.role`、`data.features`；既有 `tier` 字段保留（GM 码 `tier=3`、`role=4`）；旧字段/错误码口径不变 |
| REQ-APP-02 | 矩阵来源 | 服务端按 `role` 查 `role_feature`（GM 恒为已实现全集）；`features` 只含 `visible=true` 且 `implemented && !debugOnly` 的 key |
| REQ-APP-03 | 票据缓存 | `LicenseTicket` 新增 `role` 与 `features`；`features` **参与本地 HMAC 规范化串**（排序后拼接），但**旧票据/空 features 时签名串字节不变**，保证旧票据不失效；`role` 仅当 `role != 3` 时参与签名（与既有 tier 兼容策略一致） |
| REQ-APP-04 | FeatureGate 覆盖 | `visible()` 判定顺序：`implemented` → `debugOnly` → **有服务端矩阵则按矩阵 key 命中** → 无矩阵（字段缺失）回退现有 `minTier` 比较；`currentTier()` 返回 role（GM=4）；`sanitizeTier` 扩展 0–4 |
| REQ-APP-05 | 生效时机 | 每次进主界面 force verify（现有 `AccountVaultActivity` 路径）→ 新 features/role 落盘 → 本次/下次界面按新矩阵渲染；离线时用缓存（跟随现有 3 天宽限，不设独立过期） |
| REQ-APP-06 | GM 展示 | 授权卡等级文案显示"GM"；`reasonText` 对 GM 不再出现等级不足提示 |
| REQ-APP-07 | 兼容 | 旧 App 忽略新字段；旧服务端无 features → App 回退硬编码；旧票据无 role/features → 默认 tier=3 并回退硬编码；矩阵 key 未知时 App 忽略该 key（不崩） |
| REQ-APP-08 | 单测 | JVM 单测覆盖：features 解析/排序/空数组 vs 字段缺失、矩阵命中与回退、GM 全开、未知 key 忽略、旧票据签名兼容 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 码列表（1 万条）筛选 < 200ms；批量生成 100 条 < 1s；后台首屏 < 1s；管理 API 单请求 < 300ms |
| 安全 | 口令 ≥16 字符、常量时间比较、失败锁定；会话 HttpOnly/SameSite；写操作 Origin 校验；SQL 全参数化；页面输出转义（防 XSS）；不落明文 code 日志；审计不可删 |
| 可用性 | license-server 保持单静态二进制、无 CGO、无外部依赖；SQLite WAL；迁移幂等（`ensureColumn`/`CREATE TABLE IF NOT EXISTS`） |
| 兼容性 | 旧码默认 T3；旧票据不失效；旧 App 忽略新字段；API 只增字段 |
| 数据量 | `verify_log` 永久保留 + 既有索引；后台分页/导出上限 10,000 |
| 部署 | 不新增端口/进程；Caddy 增加 `/admin` → 同一上游；新增 env `LICENSE_ADMIN_PASSWORD` |
| 可观测 | `admin_audit` 表 + 服务端结构化日志（code_id、动作、结果码） |

## 6. 异常与边界

| 场景 | 期望行为 |
|---|---|
| 未配置 `LICENSE_ADMIN_PASSWORD` | `/admin` 与 API 返回 503 + 明确提示；现有 CLI/授权接口不受影响 |
| 登录失败 5 次 | 同 IP 锁 10 分钟，返回明确剩余时间 |
| 会话过期 | 401，前端跳登录 |
| 批量数量 0/101/非整数 | 400，提示 1–100 |
| 停用已停用码 | 幂等成功提示，不重复写审计 |
| 启用已过期码 | 拒绝，提示"已过期码不可启用" |
| GM 码激活后停用 | 设备下次 verify 返回 `data.status=revoked`（code=0，冻结契约），后台记录为失败（1004），App 进锁定页 |
| 矩阵提交未知 key / 未实现项被勾选 | 400，整批拒绝并列出非法项 |
| 矩阵保存并发 | 最后写入生效，每次写审计 |
| 旧库升级 | 启动时幂等建表/加列（`is_gm`、`feature_catalog`、`role_feature`、`admin_audit`），不丢数据 |
| App 收到空 features 数组 | 视为"服务端明确无功能"，不回退硬编码 |
| App 收到字段缺失 | 回退硬编码 minTier |
| 矩阵含未知 key | App 忽略，不崩溃 |
