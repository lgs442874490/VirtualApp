## 0. 结论摘要（TL;DR）

1. **数据链路本身是通的**：`FormationCatalog.capture → stateStore.putString(srv:formation:catalog:{fpid}:{sid}) → /v1/vault/state → VaultSync.writeDailyState → SharedPreferences("daily_state") → FormationStore.catalog/parseHeroes → FormationPicker` 逐跳键名/类型/解析全部对齐（见 §A）。**断点不在链路上，而在"键是否存在"和"数据是否可信"两处**（§B2/§B1）。
2. **「编辑器英雄列表空」在同一份代码里有两条互斥表现**：
   - 目录存在但名字脏（`"巴希提"` 带引号、star/power=0、status 无映射）→ 列表渲染成"空/脏"行（QA 原文"hero 目录 name 为空 + 状态缺失"）；
   - 目录整体缺失 → `FormationPicker` 直接降级为"手填英雄 ID"，用户看到"没有英雄可选"。
   前者的根因**已定位到确切代码**：`app/src/main/java/com/carlos/vault/wjdr/asset/HeroCatalog.java:84-145` 全部 62 个英雄名被字面引号包裹（脚本核验 62/62），与生产观测 `"\"巴希提\""` 逐字符一致。**这是 P0-1，改 62 行即可主干修复**。
3. **「保存后不生效 / 派队失败」根因确定在"严格 SKIP vs 网页版夹取"的语义分叉**：App 保存时超库存只 toast（`FormationPicker.java:742-752`），服务端 ROLE 路径超库存/超容量直接 SKIP 不派队（`FormationResolver.java:239-262`）→ 用户看到"保存成功"，实际永不出征。叠加三个放大器：功能级 `soldiers` 覆盖残留、删/清空编队库不上传、无职业唯一性校验（§B3）。
4. **1:1 缺口规模**：网页版「编队设置」是一个独立 dialog（基础出征上限 / 游戏内编队 / 我的编队 三段 + 英雄头像卡 + 队长 + 职业 + 星级代际 + 容量夹取 + 冲突校验 + 一键编队 + 编队记忆 + 巨熊模板）；我方 App 只有"功能页卡片 + 编队库弹窗 + 无头像编辑器"。P0 4 项、P1 9 项、P2 6 项（§C）。
5. **素材可行**：网页版 `frontend/hero` 有 65 张 350×350 PNG（50000-50064，共 17.9MB，均 268KB），缩到 96×96 WebP 后约 0.4-0.7MB，可全量内置；App 已依赖 Glide 4.7.1，但 daily 包当前 0 处 RecyclerView、0 张位图，需新增加载与列表组件（§D）。

### D.2 三种头像方案对比

### D.3 页面与列表性能建议

1. **一次性构造成本**：当前编辑器在 `AlertDialog(ScrollView)` 里一次性 `new CheckBox` 62 个（`FormationPicker.java:596-617`）。加头像后单价上升（解码+布局），**必须**改成：`RecyclerView`（GridLayoutManager，3 列）+ `ViewHolder` 复用 + 图片异步解码（内存 `LruCache` 上限 4MB）+ 滚动暂停解码。
2. **打开耗时预算**：目标 <150ms（中端机）。素材 96px WebP 解码 ≈1-2ms/张；首屏只解码可见 9-12 张即可。
3. **管理页**（P1-2）建议 **Activity 而非 Dialog**：网页版是 1080px 宽的 dialog（`responsive-dialog role-formation-dialog`），手机端等效用独立页面（`FormationLibraryActivity`），三段可折叠（`展开/收起` 已有对应交互）。
4. **兼容性**：`Activity`+代码构建 UI 的既有约束（无 XML）保持；`AlertDialog.THEME_DEVICE_DEFAULT_LIGHT` 是现有统一风格（`FormationPicker` 全用），新页面复用 `UiStyle` 即可，不引入 Material 组件以外的东西。

### D.4 素材生成（可直接执行，产物入库）

```bash
# 依赖：python3 + Pillow（本机已有 python3；若无 Pillow：pip3 install --user pillow）
python3 - <<'EOF'
import os, glob
from PIL import Image
SRC = '/Users/liangguansheng/ZCodeProject/wjdr-review/frontend/hero'
DST = 'app/src/main/assets/hero'
os.makedirs(DST, exist_ok=True)
total = 0
for f in sorted(glob.glob(SRC + '/5[0-9][0-9][0-9][0-9].png')):
    hid = os.path.basename(f)[:-4]
    im = Image.open(f).convert('RGBA').resize((96, 96), Image.LANCZOS)
    out = os.path.join(DST, hid + '.webp')
    im.save(out, 'WEBP', quality=80, method=6)
    total += os.path.getsize(out)
print('files=%d total=%.2f MB' % (len(glob.glob(DST + '/*.webp')), total / 1e6))
EOF
# 预期：files=65 total≈0.4-0.7 MB
```
