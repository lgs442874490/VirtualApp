## 1. 功能

服务器侧常驻模块，复用现有游戏会话（不额外登录、不顶号），主动发 `req_world_map_info` 矩形查询：

| 功能 | 行为 | 间隔 |
|---|---|---|
| **监视敌方 80 级炉子** | 对 5 个被监视 uid 的城各查一个 55×55 格；看到从该格出发、owner=监视 uid、目标是城的 PvP 行军 → 企微告警（谁→目标城、行为、ETA、兵力） | 4s |
| **保护友盟聚集地** | 对 7 个聚集地共 8 个 55×55 矩形查询；终点落在矩形内、类型命中 PvP、且 owner 不属于友盟 → 来袭告警 | 25s |
| **迁城/被击飞跟踪** | 监视目标连续 2 轮**完整**查询未出现 → 触发整图扫描（484 格，实测约 16s）→ 按 uid 定位新城 → 更新监视矩形并告警 | 事件触发 |
| （可选）周期基线 | `fullScanIntervalMs>0` 时定期整图刷新城缓存 | 默认关闭 |

**只发告警**：本模块不产生日报/汇总；同时 `DailyDigest` 默认改为关闭（`VAULT_DIGEST=on` 才开），
健康告警（`HealthMonitor`）与战争通知（`WarNotify`）保持不变。

## 2. 协议与实测依据

- `req_world_map_info`：55×55 矩形（实测 110×110 被拒），`session` 用 1e8~4e8，`fulldata=true, lod=1`（lod=0 无数据）；
  只发不等，数据经 `notify_world_mapobjs` / `notify_world_marchs` 推送，按 `content.session` 对账。
- 整图 484 格实测：**15.3–17.9s、0 缺块**；单格平均 28–33ms。
- 行军对象位置语义：**96.3% 同时出现在起点格和终点格**（平均 2.5 格）→ 盯敌城格可在出兵后秒级发现目标。
- 城市对象只有 `uid/lv/nickName/aid/kid`（无盾/燃烧/城墙）→ 本 MVP 不做燃烧判定（后续可逐城 `req_world_mapobj` 补）。

## 6. 预算与延迟

| 项 | 数值 |
|---|---|
| 常态请求 | 监视 5 格 / 4s ≈ 1.25 req/s + 保护 8 格 / 25s ≈ 0.32 req/s + 心跳等，合计 ≈ 1.6 req/s（限速 2.5） |
| 单格响应 | 28–33ms（实测） |
| 出兵发现延迟 | ≤1 个监视间隔（默认 4s），且行军推送带完整 ETA |
| 来袭确认延迟 | ≤1 个保护间隔（默认 25s）+ 行军进入矩形时的时间 |
| 迁城定位 | 2 轮监视确认（≈8s）+ 整图扫描（≈16s） |
| 数据量 | 每格推送远小于整图；整图一次约 83k 对象/7.6k 行军条目 |

> 风控边界：整图突发已实测 3 次无异常；**常态 1.6 req/s 是本次新增负载，必须灰度观察**。

## 7. 上线步骤（生产 vault-vps）

1. 构建：`cd vault-server && JAVA_HOME=~/java/jdk-17/Contents/Home ./gradlew shadowJar --offline`（产物 `build/libs/vault-server-0.1.0-all.jar`）。
2. 备份：`cp /opt/vault-server/vault-server-all.jar /opt/vault-server/backup/vault-server-all.jar.bak-$(date +%Y%m%d-%H%M%S)`。
3. 部署 jar（`vault:vault`，权限与原文件一致），首次启动会生成 `/opt/vault-server/data/watchpoint.json`。
4. 在 `/etc/vault-server.env` 追加：`VAULT_WATCHPOINT=on`（`DailyDigest` 已默认关闭；若历史 env 里显式写了 `VAULT_DIGEST=on` 需改为 off）。
5. `systemctl restart vault-server`，验证：
   - `healthz` ok、双角色自动上线；
   - 日志出现 `[观察点] 已启用：kid=888 监视目标=5 保护矩形=8 ...`；
   - 首次 4s 内出现监视查询；日志出现 `[观察点] 使用会话 ...`（仅首次）。
6. 观察 1–3 天：企微只应收到 `🚨 观察点·…`/`📍 观察点·…` 告警，不应再收到「今日汇总」。

**回滚**：`VAULT_WATCHPOINT=off`（或 watchpoint.json `enabled=false`）→ 重启或等 5s 热重载；
需要完全回滚则恢复备份 jar 并重启。
