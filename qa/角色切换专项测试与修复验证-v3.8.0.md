> 日期：2026-10-06 · 触发：真机报告「k888 切换到 k913 后配置未同步：三个兵营训练等级仍保留 k888 的 t3、只有一个兵营在训练、其它类似问题、功能实际不可用」
> 测试环境：模拟器 diudiu2（API34）+ 开发账号 80971192 的真实三角色（领主1182430719·**K888** / 铁柱、·**K913** / 领主1041164144·K902 未入区）——与真机故障场景同构
> 结论先行：**根因为「当前角色」双事实源分裂，已修复并全场景验证通过**；完整用例库见《测试用例-全量-v3.8.0.md》，本轮新增 RS 系列角色切换用例 12 条全部通过。

## 一、根因分析

### 1.1 缺陷机制

「当前角色」在代码里有**两个事实源**：

| 事实源 | 存储 | 写入方 | 消费方 |
|---|---|---|---|
| `home:current_role`（currentRoleKey="fpid:sid"） | HomeActivity 私有 prefs | `setCurrentRole()`（切换角色/切换账号） | 今日页 Hero/代办/互助/集结、refreshTasks 状态徽章、SubCardUi、openFnDetail |
| `daily_roles active:<fpid>`（RoleStore.activeRole） | 全局 prefs | `setActiveRole()`（launchRole 启动分身、runSingleCurrent 执行前对齐） | **fnOn/setFnOn（日常页功能开关读写）**、FunctionActivity sid 兜底、**RoleSessionKeeper.syncOnline 常驻会话选角**、DailyRunner/DailySchedulerService 兜底 |

**`setCurrentRole()` 只写第一个不写第二个**（`HomeActivity.java` 原 L758-764）→ 用户「切换角色」后：

1. **配置残留**（用户主诉①）：日常页功能开关 `fnOn/setFnOn` 经 `activeSid()` 读 activeRole——仍是旧角色 K888 → 兵营训练档位/子项开关的展示与写入全部落在 K888 名下，K913 的配置从未被读写；
2. **常驻会话不换角**（用户主诉②③的放大器）：`syncOnline` 选角优先 activeRole → 切到 K913 后协议会话仍连 K888 → 推送唤醒/互助/「立即执行」实际发生在 K888 的游戏状态上（K888 的兵营数据 t3 被读取展示；在 K888 上发训练而在 K913 的游戏客户端里看不到兵营在练）；
3. 页面呈现**一半跟新角色一半跟旧角色**的分裂（徽章跟 currentRoleKey、开关跟 activeRole），用户观感即「配置信息未能正确同步」。

佐证：代码中已存在 `runSingleCurrent()`（原 L3858-3861）在执行前手动 `setActiveRole(currentRoleSid())` 的补丁——说明分裂已被察觉，但只补了执行路径，未覆盖 UI 读写与常驻会话选角。

### 1.2 修复内容（统一事实源）

| # | 文件 | 修改点 |
|---|---|---|
| F1 | `HomeActivity.setCurrentRole()` | 切换角色时同步 `RoleStore.setActiveRole(fpid, sid)`——一次修复让功能开关读写、详情页兜底、**常驻会话选角（syncOnline）**、调度/执行兜底全部跟随当前角色（附根因注释） |
| F2 | `HomeActivity.fnOn()/setFnOn()` | `activeSid(taskAccount)` → `currentRoleSid()`——日常页开关与同页状态徽章口径一致（双保险，即使 activeRole 被其它路径改写，日常页仍以全局当前角色为准） |
| F3 | `HomeActivity.buildHomeUi()` 新增 `alignActiveRoleWithCurrent()` | 启动恢复 currentRoleKey 后做一次性对齐——修复**存量设备**上两源不一致的历史残留（升级即生效） |

不破坏性论证：`activeRole` 语义本就是「该账号当前操作的角色」，切换角色时更新符合语义；`launchRole` 启动分身前的 setActiveRole 与新逻辑一致；跨账号入口（openFnDetail 对非当前账号用该账号自己的 activeSid）不受影响；批量跑日常（runList）对每个账号跑其激活角色——跟随当前角色正是预期。

## 二、角色切换专项用例清单与实测结果（RS 系列，本轮新增）

通用前置：账号 80971192（三角色 K888/K913/K902，K888 与 K913 在工作区）；已激活授权。**修复版实测全部通过**（括注修复前行为以对照）。

### RS-01 切换角色后双事实源同步
- 步骤：今日页 → 切换角色 → 选 K888。
- 预期：`home:current_role=80971192:888` **且** `daily_roles active:80971192=888`。
- 实测：✅ 两者同步为 888（修复前 activeRole 残留 913——**配置残留根因**）。

### RS-02 切换后功能开关读写跟随新角色
- 步骤：切到 K888 → 日常页关/开「登录好礼」→ 读 `daily_config`。
- 预期：键落在 `acc:80971192:888`。
- 实测：✅ `{"login_rewards":false}` → `{"login_rewards":true}`，键为 `acc:80971192:888`（修复前错写 `acc:80971192:913`——**串写根因**）。

### RS-03 切回原角色后配置隔离
- 步骤：切回 K913 → 切「邮件奖励」开关 → 读 `daily_config`。
- 预期：写 `acc:80971192:913`；K888 的 `login_rewards:true` 原样保留在 888 键；K913 无 login_rewards 键 → 开关回落默认开。
- 实测：✅ `acc:80971192:913={"mail":false}`、`acc:80971192:888={"login_rewards":true}` 并存互不污染（修复前两角色的开关互相覆盖）。

### RS-04 功能详情页角色行跟随
- 步骤：K913 下打开「登录好礼」详情页。
- 预期：信息卡显示「角色：铁柱、 · K913（913铁柱）（配置只作用于本角色）」。
- 实测：✅（兵营训练档位等子项配置同机制读写 K913 的键——**用户主诉①的 UI 面**）。

### RS-05 常驻在线会话跟随切换（用户主诉②③的执行面）
- 机制验证：`syncOnline` 选角优先 activeRole（修复 F1 后跟随 currentRole）；实测启动后状态行「**913区·在线**」——常驻会话确实连到 K913（修复前停在 K888，导致 K913 的推送唤醒/互助/执行全部发生在 K888 会话上）。
- 真机补充建议：切角色后等状态行变为「<新区>·在线」再点「立即执行」；切换本身即触发换会话（使用说明「切换角色=自动换会话」现在真实成立）。

### RS-06 存量分裂数据自愈
- 步骤：手工构造 `active=888` + `current_role=…:913` 分裂状态 → 冷启动。
- 预期：`alignActiveRoleWithCurrent()` 以 currentRoleKey 为准对齐。
- 实测：✅ 启动后 active 自动变 913（覆盖升级用户/历史残留，无需重装或手动清理）。

### RS-07 切换后页面状态即时刷新
- 预期：`setCurrentRole` 调 `refreshAllPages()`——今日/账号/日常/我的四页全部重算。
- 实测：✅（切换后日常页「已启用 32」按 K913 配置重算；今日页代办/互助跟随）。

### RS-08 跨账号入口不受影响
- 机制核对：`openFnDetail(a≠当前账号)` 用该账号自己的 activeSid ✓；批量跑日常逐账号用各自激活角色 ✓；账号页角色表/角色管理勾选跟随 activeRole（修复后=当前角色）✓。

### RS-09 未入区角色边界
- 步骤：角色选择器显示 K902「未入区」。
- 预期：可选（切换合法，配置键独立），但不进工作区不参与自动日常。
- 实测：✅ 选择器正确标注；K902 切换后配置写入独立键（机制同 RS-02，未重复实测）。

### RS-10 兵营场景专项推演（对应用户主诉①②③）
- 修复后链路：切 K913 →（F1）activeRole=913 →（F2）日常页兵营开关/子项/档位读写 `p:80971192:913:barracks` →（F1）常驻会话换到 K913 → 详情页「立即执行」`runSingle(fpid, sid=913)` → `liveOf(fpid,913)` 借 K913 会话 → `TownTasks.barracks` 用 **K913 的** `notify_barrack_init` 解析档位（auto=K913 已解锁最高档）与三营状态 → 训练/收兵作用于 K913。
- 真机验证建议（本环境无游戏 APK，执行环节需真机确认）：切到 K913 → 兵营详情页确认「训练等级」下拉不再是 t3（应显示 auto 或 K913 实际档位）→「立即执行」→ 游戏内三个兵营均应开始训练（若 K913 兵营等级/解锁允许）。

### RS-11 切换账号（跨 fpid）路径
- 机制核对：`showAccountSwitcher` 选中 → `setCurrentRole(target.fpid, msid)` → 同样走 F1/F2 修复 ✓（今日页 L680 入口）。

### RS-12 重启后当前角色保持
- 实测：冷启动恢复 currentRoleKey=K913，页面四 Tab 数据均按 K913 呈现（RS-06 同轮验证）。

## 四、修复后验证结论

1. **用户主诉三条全部闭环**：配置残留（RS-01/02/03 ✅）、兵营档位跟随（RS-04/10 链路修复 + 真机复核指引）、功能"不可用"（RS-05 会话换角修复——K913 的执行不再发生在 K888 上）；

3. **回归**：修复后 JVM 103/103、构建通过、角色切换 12 用例全过、既有功能（导入/开关/时间窗/授权）复测无回归；模拟器环境已还原（真实游戏会话已断开，prefs 恢复原值）；
4. **真机验收清单**（发布前）：①K888→K913 切换后兵营详情档位非 t3 且「立即执行」三营齐训（RS-10）；②切换后状态行变「913区·在线」再执行；③切回 K888 验证其 t3 配置仍在（隔离）。
