## 4. 发现并修复的缺陷（P1-5 实现漏洞）

### 现象
复核到点、角色离线时：

```
02:35:36 I/VaultSrv: 移民任务拉起登录 job=j-fire-crash ... code=1404 账号缺少 token
02:36:06 I/VaultSrv: 移民任务拉起登录 job=j-fire-crash ... code=1404 账号缺少 token
（每 30s 重复；next_reverify_at 停留在过去，reverify_index 永远 0）
```

### 根因
`MigrantEngine.startReverify` 分支：

```java
if (keeper == null || !keeper.roleOnline(role)) {
    endRunning(job.jobId);
    tryLogin(job);
    return false;          // ← 不推进 reverifyIndex / nextReverifyAtMillis
}
```

`nextReverifyAtMillis` 保持「已过期」→ 调度器每秒重投 → 反复拉起登录（token 失效时刷屏），
且**永远排不到 +10min 第二轮**，任务永久滞留 UNKNOWN，与交付说明「+3min/+10min 自动复核」不符。

### 修复
离线分支也视为「本轮无结论」并推进轮次（两轮后 `clearReverify` 停止自动复核）：

```java
if (keeper == null || !keeper.roleOnline(role)) {
    endRunning(job.jobId);
    // 离线也推进轮次，避免 nextReverifyAt 停留在过去导致每秒重投/反复登录
    synchronized (job) {
        advanceReverify(job);
        job.touch();
    }
    jobs.markDirty();
    jobs.flushIfDirty();
    tryLogin(job);
    return false;
}
```

### 修复后验证

```
02:40:27 I/VaultSrv: 移民延迟复核仍无结论，安排下一次 job=j-reverify-offline at=... (+10min)
02:40:27 I/VaultSrv: 移民任务拉起登录 ... code=1404（仅 1 次）
```

40 秒后再查：拉起登录仍为 **1 次**、复核日志无重复 → 不再刷屏、轮次正常推进。

回归：服务端全量 **1796 用例通过**。
