# 网页版多角色在线机制与互顶修复（2026-11-08）

## 一、现象

同账号点第二个角色「上线」后，先前的角色被顶下线（状态转被顶号/离线），
表现为「同账户只能一个角色会话在线、点上线互顶」。

## 二、网页版（原版 wjdr-tool）机制：已反编译确认

来源：京东云主机 `/opt/wjdr-tool/wjdr-tool.jar`（2026-11-07 22:31 构建，CFR 0.152 反编译；
访问凭据只保存在本机 `~/.dsh-secrets/wjdr-reference.md`，**不入库**）。

### 1. 每角色一台独立「设备」（关键）

`com.wjdr.tool.core.account.ConfigJsonLoader.scopeFingerprintToRole`：

```java
long roleId = ...account.get("accountRoleId");
String identity = roleId + "|" + value(account.get("account"));
account.put("device_id",   sha256("device|"   + baseDeviceId   + "|" + identity).substring(0,32));
account.put("distinct_id", sha256("distinct|" + baseDistinctId + "|" + identity).substring(0,32));
```

- `device_id`/`distinct_id` 按**角色**（accountRoleId）稳定派生，同账号同服的两个角色是两台不同设备。
- `ip`/机型仍为账号级（scoping 只覆盖这两个字段）。

### 2. 单角色上线只动自己

`GameAccountSessionService`：

- `startOne/startInBackground` → `detachSessions(accountRoleId)`，只关闭本角色旧会话；
  兄弟会话对象、心跳、任务全部保留。
- 登录调度：`accountExecutor = Executors.newVirtualThreadPerTaskExecutor()`，
  并发上界 `GameAccountLoginBudget(32)`；失败按恢复策略退避，不做「降级单会话」。
- 跨模块互斥只到「同角色」粒度（`GameAccountLoginCoordinator`，与多角色并存无关）。

### 3. 生产日志实证（网页版）

- 同账号同服双角色长期同时在线：`80049204` 的 `531 终极挑战@888` + `532 仙逆～昆虚星域@888`；
  `62641294` 的 `536/537@888`。同一批 22:33:33 并发上线后持续在线。
- 2026-11-07 78 次单角色手动上线（`trigger=MANUAL_START`）中，仅 **2 次** 同账号兄弟在
  上线后 20s 内被顶（统计口径：触发后 [-5s, +20s] 内同账号其它角色出现「其他设备上线」）；其余兄弟保持在线。典型：22:42:00 角色 742 单角色上线时，同账号 798 自
  22:33 起一直在在线、未掉线。
- 日志中 143 次「检测到账号在其他设备上线」绝大多数是**真人手机登录**，不是自家角色互踢。

## 三、我方缺陷根因

我方登录身份按**区服 sid** 维护：

- App：`role_settings:<fpid>:<sid>`（`AccountStore.getRoleSettings/roleIdentitySeed`）；
- 服务端：`VaultStore.roleIdentity[sid]`、`SessionKeeper.identitySeed(acc, sid)`。

后果：**同服多角色共享同一 device_id/distinct_id**，服务器判为同设备重复登录 →
后登录者把兄弟踢掉（code=46 同设备 / code=5 顶号），随后顶号恢复又反向踢回，形成互踢。

跨服角色因 sid 不同、指纹天然不同，所以「跨服能上、同服互顶」——与线上现象完全吻合
（生产账号 48460403 的 888 服双角色 35371154/88280792 即为同服场景）。

> 2026-10-07/08 的「服务器按账号唯一会话」终判需修正：当时实验 A 的互踢记录里 web 端
> 正在反抢（文档已注明“web 抢回打断”），实验 B 是同指纹 code=46；真正条件是**同设备**，
> 而非账号唯一会话。

## 四、修复（对齐原版）

### 服务端（vault-server，立即生效，无需 App 发版）

1. `VaultStore.learnIdentity(fpid, sid, uid, json)`：登录成功后按 `sid:uid` 固化实际指纹
   （已有固定设备不覆盖）；旧 3 参签名写 `sid` 键，旧数据零迁移。
2. `SessionKeeper.identitySeed(acc, sid, uid)` 解析顺序：
   - `roleIdentity[sid:uid]` 已固化 → 直接用；
   - 该 sid 只有这一个角色 → 沿用旧 `sid` 键/账号级 identity（不换脸）；
   - 同 sid 多角色 → 以旧键为基线，按 `fpid|sid|uid` stable sha256 派生 device_id/distinct_id
     （`scopeIdentity`，与原版同规则）。
3. 登录成功后 `learnIdentity` 用实际落地 uid 落 `sid:uid` 键（重启后指纹不漂移）。
4. `ensureSession`（账号级登录）在 `VAULT_PER_ROLE=on` 时改用 `applyRoleLogin`（保留兄弟期望态），
   修掉 11-01 修复漏掉的一半（当时只保护了会话列表，落库仍走 exclusive → reconcile 停兄弟）。

### App（下一版 APK 生效）

1. `AccountStore`：新增 `role_settings:<fpid>:<sid>:<uid>` 读写与 `roleScopedIdentity` 派生；
   `roleIdentitySeed(fpid, sid, uid, mainSid)`（旧签名保留）。
2. `VaultSync`：角色 sync 下发优先 `sid:uid` 指纹，旧数据回落 `sid` 键。
3. `RoleSessionKeeper`：`LiveSession` 带 uid，登录注入身份按 uid；`Desired` 同时保存 sids/uids，
   热补/整号竞速按角色 uid 起跑。

## 五、迁移与兼容

- 单角色账号、跨服角色：**指纹不变**（沿用旧键），零扰动。
- 同服多角色：首次登录会派生新设备身份（各自稳定固化），随后不再变化。
- 服务端优先用 `sid:uid` 固化值；旧 App 下发的 `sid` 键仍作为派生基线，不会互相覆盖。
- 回滚：服务端替换旧 jar 即可；`roleIdentity` 新增键对旧版本是未知键（JSON 透传保留，无副作用）。

## 八、第二轮审查修复（2026-11-08）

1. **本地会话键带 uid**：`RoleSessionKeeper` 的会话键由 `fpid:sid` 改为 `fpid:sid:uid`
   （uid 未知退回旧键）。旧键下同服双角色会互相覆盖：后建会话覆盖先建、被覆盖会话既不进
   map 也无法 close（引擎/连接泄漏），竞速结算还会对同一对象数两次、误报「全员在线」。
   同步更新 `borrowOnline(fpid,sid)`（遍历匹配并优先当前选中角色，避免把兄弟角色数据
   当本角色返回）、新增 `borrowOnline(fpid,sid,uid)`、
   `closeRoleSession(fpid,sid,uid)`；竞速结算改用会话键列表；死代码 `pickSingle/pickSingleLog` 删除。
2. **主角色指纹不再与兄弟共享**：`AccountStore.resolveRoleSeed` 纯函数化——主角色仅在
   「同区服无兄弟角色」时沿用账号级指纹，否则返回空串由引擎随机后固化；修复「A 用账号级固化后
   B 成为主角色又拿到同一指纹」的互踢残留。
3. **派生实现收敛为一份**：新增 `com.carlos.vault.wjdr.RoleFingerprint`，App 与 vault-server
   共用（服务端 sourceSets 已包含 `com/carlos/vault/wjdr/**`），消除两端规则漂移。
4. **perRole 判断统一**：`SessionKeeper` 的 tick 与 `ensureSession` 都走 `VaultStore.perRoleMode()`。
5. 测试：服务端断言收紧为「两个派生值都不得等于账号级指纹」；新增 App
   `resolveRoleSeed` 决策用例与 `RoleSessionKeeperKeyTest`（同 sid 不同 uid 键互异、旧键兼容）。
