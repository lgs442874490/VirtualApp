## 0. 一句话结论

网页版编队 = **一套编队库（我的编队）+ 游戏内编队只读镜像 + 自动编队（全局比例）+ 巨熊模板体系 + 编队记忆**，通过统一的「编队板（Board）」组件在 3 个 tab（自动/游戏/我的）里复用；各功能队列通过 `formationMode=ROLE|AUTOMATIC` + `formationId/formationIds` 绑定编队；容量以 `marchCapacity`（0/1/2/3 英雄上限）为准，比例/兵力分配全部在前端算好后落库。

### 1.4 编队编辑器（我的编队「新建/编辑」）【线上JS :3256-3351 + :2088-2794】

- 入口：主按钮 `新建编队`（无选中编队或选中 `ONE_INFANTRY` 内置）或 `编辑编队`；buff-actions 的编辑图标。
- 头部：`编队设置` + `<strong>{name|新建编队}</strong>` + 关闭（aria `关闭编队设置`，关闭会重置校验状态并回收保存弹窗）。
- tabs：`Qe`（过滤掉 `templateKey=ONE_INFANTRY` 与 `source=GAME` 的编队）+ 末尾 `新建编队`；tabs-label=`我的编队`。
- Board：`heroesInteractive=true`、`ratio-mode = allocationMode==="PERCENTAGE"`、`show-open-settings=true`。
- 校验状态（:2095-2202）：
  - `pe = 容量(编制英雄)`；`we = 三兵种数量之和`；`Je = 三比例之和`；
  - `Ae`（非法）= PERCENTAGE ? `Je<=0 || Je>100` : `we > pe`；
  - 非法原因 `ka`：`比例合计必须大于 0%` / `比例合计不能超过 100%` / `兵力超过当前档位上限`；
  - `At = !name.trim() || Ae` → 主按钮 `保存编队`（hint `{heroIds.length} 英雄`）disabled；点保存若非法 toast 原因（:2649-2655）。
  - banner `Ht`：非法→原因（warn）；有 `N` 名英雄 `!available`→`有 N 名英雄未归队，出征前请确认`（warn）；否则 `本次出征胜券在握`（ok）。
- 队长规则【:2133-2172】：展示顺序 = 队长在最前（`captainHeroId` 在 heroIds 中则置顶，否则 heroIds 原序）；`heroIds[0]` 兜底为队长图标；点队长图标 = `toggle`（当前是则清空 null，否则设该英雄）。
- 英雄格点击 → 英雄选择弹窗（初始职业 = 该格职业）；`×` 移除 → 从 heroIds 删除，若删的是队长则 `captainHeroId=null`；移除后 `Da()` 按上限自动裁剪兵量。
- 兵种分配（:2613-2773）：
  - 手动改某兵种数量：`clamp(输入, 0, capacity - 其余两项)`；
  - 改比例为：`clamp(输入, 0, 100 - 其余两项)`，并重算三项兵力（`Ba(capacity, ratios)` 最大余数法）；
  - 动作：`clear` → MANUAL、三项数量与比例全 0；`average` → MANUAL、`floor(cap/3)` 均分且盾兵吃余数、比例按数量反算 `round`；`ratio` → PERCENTAGE、比例 50/20/30 并重算数量。
- 默认值（新建，:2517-2522）：`PERCENTAGE`，比例 **50 / 20 / 30**，兵量按当前容量最大余数分配；`name=""`。
- 切 tab 有未保存修改 → 确认框：`切换编队会丢弃当前未保存的修改，是否继续？`，按钮 `继续切换`/`留在当前编队`（:2573-2593）。
- 游戏编队不可直接改：点游戏编队「编辑」→ 复制为副本：`id=null`、`name="{原名}（副本）"`、toast `游戏编队不可直接覆盖，已按副本编辑，保存后生成自定义编队`（:2539-2549）。
- 保存（:2680-2711）：`id?PUT /formations/{id} : POST /formations`；成功 toast `编队已更新` / `编队已创建`，关闭编辑器并回到对应页；失败 toast `${message}`。
- 删除（:2664-2679）：确认文案 `删除“{name}”后，引用它的队列需要重新选择编队。`，标题 `删除编队`，按钮 `确认删除`/`取消`；`DELETE /formations/{id}`；成功 `编队已删除`；若当前页仅 1 条且 page>1 则回退一页。
- 保存目标弹窗（§1.6）确认后：`targetId != 当前 id` 时把 id 换成目标 id 再 PUT（覆盖目标编队）。

### 2.1 编队对象 `FormationView`（`formations[]` / `gameFormations[]` 同构）【线上确认 + 线上JS index:180509 `Wf`】

|---|---|---|
| `id` | long | 编队引用 id。`>0`=自定义/内置；`<0`=游戏编队（= `-游戏内序号`）；禁止 0。特殊：`9000000001`=内置「一盾兵」、`9000000002`=内置「任意英雄一兵」 |
| `source` | `CUSTOM`/`GAME` | 必须与 id 符号一致，否则**整条丢弃**（`source==="GAME" != id<0` → null） |
| `sourceId` | long | `abs(id)`，游戏编队即游戏内 slot 序号（1..N，实测 1..12） |
| `name` | string | 显示名；缺省 `编队 {id}` |

### 2.3 集合响应 `FormationCollection`【线上确认 + index:177812 `wN`】

| 字段 | 类型 | 说明 |
|---|---|---|
| `configured` | bool | 容量是否已同步（false 时 UI 显示 `marchCapacity.message` 并 1.5s×8 轮询） |
| `limits` | object | `{threeHeroLimit,twoHeroLimit,oneHeroLimit,zeroHeroLimit}` 与 marchCapacity 对应档位一致 |
| `automaticAvailable` | bool | 自动编队是否可用（=容量已就绪） |
| `automaticSettings` | object | `{infantryRatio,lancerRatio,marksmanRatio}`；三项和≠100 时客户端回退 50/20/30 |
| `total` | int | 分页列表总数（= 6 常规内置 + 自定义数；2 个基础内置不计入，且始终置顶返回） |
| `page`/`pageSize` | int | 服务端 `pageSize` 上限 10（传 20 也回 10） |
| `formations[]` | FormationView[] | 分页：首页 = 2 基础内置 + 前 N 条（6 内置 + 自定义，按 id 排） |
| `gameFormations[]` | FormationView[] | 游戏内编队**全量返回，不参与分页** |
| `heroOptions[]` | HeroOption[] | 全量英雄 |
| `avalancheCapacity` | object | `{initialized,owned,petBreakLevel,useTime,skillLevel,activeUntil,active,configuredTroopBonus,troopBonus}` |
| `marchCapacity` | object | `{initialized,message,fixedCapacity,percentageBasisPoints,zeroHeroCapacity,oneHeroCapacity,twoHeroCapacity,threeHeroCapacity}` |

**分页实测语义**（role 5，total=11，自定义 5 条）：
- `pageSize=10` → 首页 12 条 = 2 基础 + 6 内置 + 4 自定义；第 2 页 1 条；
- `pageSize=5` → 首页 7 条（2 基础 + 5 内置），第 2 页 = 第 6 个内置 + 4 自定义；
- `pageSize=3` → 首页 5 条 = 2 基础 + 3 内置。
- 结论：分页域 = `[6 个常规内置(按固定序) + 自定义(id 降序)]`，`total = 6 + 自定义数`；2 个基础内置（9000000001/9000000002）always prepend 不占配额；客户端补齐策略：当 `formations.length < total` 时按 `ceil(total/pageSize)` 拉剩余页并按 id 合并（:2503-2513）。

## 4. 规则清单（Android/服务端必须实现）

### 4.1 编队库
- R1 每编队 **最多 3 名英雄**（且按职业唯一：盾/矛/弓各 1）；前端 `slice(0,3)` 兜底。
- R2 `captainHeroId` 必须 ∈ `heroIds`；不合法时前端展示用 `heroIds[0]` 兜底，保存前 UI 自动纠正（选英雄后若队长不在则置首）。
- R3 编队 id 规则：`>0` CUSTOM/内置；`<0` 游戏（`id=-sourceId`）；`9000000001/9000000002` 为**可重复使用**的内置模板（`DailyFormationReference.repeatable`：ONE_INFANTRY 表示"无英雄 1 盾兵"、RANDOM_HERO_ONE_SOLDIER 表示"任意英雄 1 兵"）。
- R4 内置模板随容量同步懒创建（`ensureBuiltInFormations`，需 `marchCapacity.initialized` 且 `formationHeroOptions` 非空）；采集/巨兽/打野模板 `templateKey` 已存在则跳过；未同步时只有 2 个基础内置（role 81 实测 `total=0`、`configured=false`）。
- R5 命名上限 **30 字符**（输入 maxlength=30）；名称必填；覆盖保存 = 覆盖目标编队的英雄/名称/兵量（弹窗固定警示 `储存后，原先的编队阵容和名称将被覆盖。`）。
- R6 游戏编队只读：不可直接 PUT；编辑走"副本"（`id=null`，名字加 `（副本）`）。
- R7 内置 `ONE_INFANTRY`（9000000001）不可编辑/删除，表现为主按钮 `新建编队`；`RANDOM_HERO_ONE_SOLDIER` 在代码里 `He()` 未特殊处理 → 可编辑（线上 bug 行为，Android 建议一致或标注差异）。
- R8 删除编队不影响运行配置，但引用它的队列需重选（删除确认文案即如此）。

### 4.2 英雄状态与占用
- S1 状态枚举与中文：`AVAILABLE 在家` / `HERO_AWAY 未归队` / `RESERVED 前序占用` / `SYNC_PENDING 等待同步` / `SYNC_ERROR 同步异常`。
- S2 `available` 只表示"在城可出征"；`构建/保存` 只要求"拥有"（owned），应用巨熊模板亦只要求 owned（不要求在城）。
- S3 多编队同队列集（采集/巨熊上车）不可共用同一编队、且编队英雄不可交叉占用（前端预检，见 4.6）；运行时占用以游戏返回码为准（403）。
- S4 英雄不在家的编队仍可保存/记忆；UI 只提示 `有 N 名英雄未归队，出征前请确认`。

### 4.3 容量（出征上限）
- C1 `marchCapacity` 由登录推送计算：`zeroHeroCapacity = fixedCapacity`；`{1,2,3}HeroCapacity = floor((fixedCapacity + Σ选中英雄 troopCapacity) × (10000 + percentageBasisPoints) / 10000)`；实测 role5：140990 + 13470×3 = 181400（吻合 `threeHeroLimit`）。
- C2 前端编队容量公式（formation_manager.pretty.js:2784-2790）：`floor((fixedCapacity + Σ troopCapacity) * (10000+percentageBasisPoints)/10000)`；未初始化时容量 = 0（编辑按钮禁用）。
- C3 自动编队容量 = 当前在家英雄按职业取最高战力 3 人（`rt`，index:1873-1882），若无可用英雄则容量 0、比例非法。
- C4 `limits` 是服务端给出的 0/1/2/3 英雄参考上限，UI 只在容量弹窗展示，不参与校验。
- C5 PERCENTAGE 模式：先按比例算目标总量 `round(capacity × ratioSum / 100)`（旧版 `roundedPercentage` + 最大余数法），再把目标量按比例权重分配三兵种（最大余数法，余数相同按盾→矛→弓）；**前端演示公式 `Ba()`（:2732-2745）**：`target=round(cap*sum/100)`，先 floor 三份，再用最大余数把差额补回。
- C6 MANUAL 模式：三兵种数量之和不得超过容量（前端阻止保存：`兵力超过当前档位上限`）；服务端同样校验。
- C7 兵量随容量变化自动裁剪（`Da()`）：容量回落后，按 弓→矛→盾 顺序削减，PERCENTAGE 模式再重算。
- C8 宠物技能容量（雪猿 `avalancheCapacity.troopBonus`）**只在真正出征前实时叠加**，编队保存/展示容量不含它（容量弹窗原文说明）。

### 4.4 比例/取整
- P1 比例三项 0..100，和 **必须 >0 且 ≤100**；自动编队全局比例 **必须=100**（保存按钮 disabled：`比例合计为 X%，请调整为 100%`）。
- P2 比例展示码 `De`：三项均 %10==0 → 各位数字拼接（50/20/30 → `523`；50/10/40 → `514`；60/40/0 → `640`）；否则 `50:20:30` 形式。
- P3 快捷比例固定 5 档：`523/514/505/640/433`（§1.7）。
- P4 MANUAL 模式下"比例"为只读派生值 `round(count×100/total)`；PERCENTAGE 模式下数量为派生值。
- P5 滑杆/步进：比例步进 5；数量步进 `max(1, floor(capacity/20))`。

### 4.5 协议错误码（运行时，不在 HTTP 层）
- E1 **301** = 编队英雄不在城（`req_world_march` 拒绝）；处理：拉黑该批英雄换组合重试（【仓库现状】`HeroAvailability` TTL 10 分钟、`FormationResolver` 跳过拉黑英雄）。
- E2 **403** = 英雄被占用/安全拒绝（`FORMATION_HERO_IN_ANOTHER`）；处理：等待英雄回城/重连全量同步后重试（旧版 `WAITING_HEROES`）。
- E3 **406** = 编队士兵数量超上限；处理：按容量夹取（仓库已修）或按 75%→50%→25% 逐级缩放（`HeroAvailability.SOLDIER_SCALE_PCT`）。
- E4 **415** = 编队人数/配置超限；处理：自动编队英雄数上限从 3 逐级下调（`HERO_LIMIT_HINT`）。
- E5 **2878** = 世界出征队列已满（等待队列）；**2844** = 已在集结（巨熊上车去重）；**5204** = 巨熊发车窗口已关（跳过发车继续上车）。
- 以上均**不是**网页版 HTTP 接口错误码；网页版 HTTP 层只用 400/401/403/405/409 等状态（403 在 HTTP 层仅表示无权限）。

### 4.6 队列绑定校验（前端预检，原文）
- `{队列名}使用自动编队前，请先登录并完成出征容量同步`（AUTOMATIC 但 `!automaticAvailable`）
- `{队列名}请选择角色编队`（ROLE 但无 formationId）
- `{队列名}不能与同模块其他队列共用角色编队`
- `{队列名}引用的角色编队不存在，请重新选择`
- `{英雄名所在队列}与{队列名}的角色编队存在英雄冲突`
- `{模块}至少选择一支角色编队` / `{模块}还有 N 个启用队列未选择角色编队`
- `{模块}选择的角色编队重复、不存在或存在英雄冲突，请重新选择`
- 巨熊：`{队列}尚未启用`、`{队列}请选择角色编队`、`{队列}不能与其他巨熊队列共用角色编队`、`启用的角色编队队列必须选择一支角色编队`、`同一支角色编队不能服务多个巨兽队列`、`发起和加入数量之和不能超过玩家队列总数 {N}`、`最低等级不能高于最高等级`、`请至少启用一个发起集结队列`
- 失效清理：容量未同步或编队被删后，引用的 `formationId` 会被置空并 `enabled=false`（index `Ui()` char 292553）。

### 4.7 自动编队（AUTOMATIC）语义
- A1 全局自动编队 = 每次出征按"当前在家的盾/矛/弓各取战力最高英雄"选英雄 + 按 `automaticSettings`（或队列级比例）分兵，**不落编队实体**。
- A2 `automaticAvailable=false`（容量未同步）时：自动编队 tab disabled、队列选择器自动 tab disabled、保存比例 disabled。
- A3 `automaticSettings` 默认 50/20/30；非法和值服务端拒绝、前端回退默认。
- A4 编队列表中的 `AUTOMATIC` 队列不占用编队 id、无英雄冲突约束（每个队列运行时独立选人；同一时刻仍可能撞车 → 403 重试）。

### 4.8 巨熊模板/记忆
- B1 模板共 30 套（14 代 × 大氪/微氪/零氪/前瞻，g06+ 无 mid、g12+ 为 preview），应用生成 1 开车队 + 6 上车队，比例 5/5/90；应用成功同时把巨熊配置改为 6 个 ROLE 引用。
- B2 记忆分 `DAILY`/`BATTLE` 两类，各自独立快照（`slotCount` = 保存时游戏编队有效槽数，`savedAt` 秒级时间戳，`version` 递增）；保存默认 `overwrite=false`，已存在需 `overwrite=true`（前端二次确认）。
- B3 恢复逐槽 `req_save_prefab` 下发（500ms 间隔），返回 `{total,restored,failures[]}`；失败项文案 `游戏拒绝保存编队 {id}（错误码 {code}）`。
- B4 记忆恢复只影响游戏内编队，不改变编队库；恢复后需重新拉集合。
