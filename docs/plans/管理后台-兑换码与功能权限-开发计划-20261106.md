## 3. 数据模型与接口变更

### 3.1 新增表（SQLite）

```sql
CREATE TABLE IF NOT EXISTS feature_catalog (
  key          TEXT PRIMARY KEY,      -- FeatureGate.Feature.key
  label        TEXT NOT NULL,         -- 中文名
  default_tier INTEGER NOT NULL,      -- 1/2/3
  implemented  INTEGER NOT NULL,      -- 0/1
  debug_only   INTEGER NOT NULL,      -- 0/1
  sort         INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS role_feature (
  role        INTEGER NOT NULL,       -- 1/2/3（GM=4 只读计算，不落库）
  feature_key TEXT NOT NULL,
  visible     INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (role, feature_key)
);

CREATE TABLE IF NOT EXISTS admin_audit (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at  INTEGER NOT NULL,
  actor       TEXT NOT NULL DEFAULT 'admin',
  action      TEXT NOT NULL,          -- login/generate/revoke/restore/matrix_save/matrix_reset
  target_type TEXT NOT NULL DEFAULT '',
  target_id   TEXT NOT NULL DEFAULT '',
  detail      TEXT NOT NULL DEFAULT '', -- JSON：diff/参数
  ip          TEXT NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_audit_time ON admin_audit(created_at);
```

`license_code` 迁移：`ALTER TABLE license_code ADD COLUMN is_gm INTEGER NOT NULL DEFAULT 0`（`ensureColumn` 幂等）。

### 3.2 授权接口变更（只增字段）

`POST /v1/activate` → `data.ticket` 新增：

```json
{"role": 2, "features": ["account_add","account_pool","account_start","aid_alliance","..."]}
```

`POST /v1/verify` → `data` 新增：

```json
{"role": 2, "features": ["..."]}
```

- `features`：按 key 字典序、只含 `visible=true && implemented && !debugOnly`；GM(`role=4`) 恒为已实现全集。
- `tier` 字段保留：GM 码 `tier=3`（旧 App 按 T3 处理）、`role=4`（新 App 识别）。
- 旧 App 忽略未知字段；旧票据无 role/features 时 App 回退硬编码。

### 3.3 管理 API（`/admin/api/*`，JSON 信封 `{code,message,data}`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/admin/api/login` | `{password}` → 会话 cookie |
| POST | `/admin/api/logout` | 清会话 |
| GET | `/admin/api/me` | 当前会话信息 |
| GET | `/admin/api/overview` | 统计 + 最近审计 |
| GET | `/admin/api/codes` | 筛选/分页：`status,usage,tier,type,q,from,to,page,size,sort` |
| POST | `/admin/api/codes/generate` | `{count,type,tier,remark}`（tier=`1|2|3|gm`） |
| GET | `/admin/api/codes/{id}` | 详情（含绑定设备、剩余天数、verify 次数） |
| POST | `/admin/api/codes/{id}/revoke` | `{reason}` |
| POST | `/admin/api/codes/{id}/restore` | 启用（可逆） |
| POST | `/admin/api/codes/batch` | `{ids,action:revoke|restore}`（≤100） |
| GET | `/admin/api/codes/{id}/logs` | 使用记录筛选/分页 |
| GET | `/admin/api/codes/export` | 当前筛选 CSV（≤10,000） |
| GET | `/admin/api/codes/{id}/logs/export` | 单码记录 CSV（≤10,000） |
| GET | `/admin/api/features` | 39 项目录 |
| GET | `/admin/api/matrix` | `{roles:[...], rows:[{key,role1,role2,role3,gm}]}` |
| PUT | `/admin/api/matrix` | `{rows:[{key,role,visible}]}` 全量或差量；校验后保存 |
| POST | `/admin/api/matrix/reset` | 恢复默认 |
| GET | `/admin/api/audit` | 审计分页 |

> 鉴权：除 `login` 外全部要求会话；写操作额外校验 Origin。所有 body 限 1MB；CSV 响应 `text/csv; charset=utf-8`。

## 5. 关键设计决策（实现层）

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | GM 用 `is_gm` 列而非改 `tier CHECK(1..3)` | SQLite 改 CHECK 需重建表，风险高；加列幂等、旧版兼容 |
| D2 | GM 的 `tier` 仍回 3、新增 `role` | 旧 App 不识别 role 时按 T3 使用，不被降权也不越权 |
| D3 | features 参与票据 HMAC，但空/缺省时签名串不变 | 防本地篡改矩阵，同时旧票据不失效（需黄金向量回归） |
| D4 | 矩阵 key 只认 39 项，App 未知 key 忽略 | 前后端版本可独立升级 |
| D5 | 后台页面 `go:embed` 进二进制 | 保持单二进制部署，无静态文件同步问题 |
| D6 | 单个管理员口令 + 8h 会话 | 已确认最小运维形态；后续可扩展多账号 |
| D7 | 停用/启用不重算到期、不解绑 | 与现有 `revoke` 语义一致，避免"停用再启用白送时长" |

## 6. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 票据签名兼容改错导致旧用户失效 | 🔴 高 | 先写黄金向量回归测试（现有 `LicenseTicket` 旧串逐字节），再实现 features/role；空/缺省路径必须字节不变 |
| SQLite 迁移在线上库失败 | 🔴 高 | 迁移前 `.backup`；只加表/列；`ensureColumn` 幂等；本地用生产库副本演练 |
| 后台口令/会话被绕过 | 🔴 高 | 常量时间比较、失败锁定、HttpOnly+SameSite、Origin 校验、无默认口令（不配即 503） |
| verify_log 量级导致后台卡顿 | 🟡 中 | 已有 `(code_id, created_at)` 索引；分页 + 上限；统计走聚合查询 |
| 矩阵下发后功能"消失"引发用户投诉 | 🟡 中 | 默认矩阵与现网硬编码一致（先 seed 再改）；后台矩阵页常驻"当前生效"说明；审计可回滚 |
| Caddy/环境变量部署需人工 | 🟡 中 | 写 runbook；未经确认不自动改线上；部署前先在测试机验证 |
| 真机构建流程复杂（AAR 补丁/签名） | 🟡 中 | 严格按 MEMORY §6；构建后校验 `libvbox.so` sha256 前缀与签名 |
| 旧 App 不识别 role 导致 GM 码按 T3 | 🟢 低 | 预期行为；GM 用户升级到 v4.2.59 后生效 |

### 12.1 活动页面热更：H5 活动页容器（方案 A）

| 项 | 结论（已确认） |
|---|---|
| 路线 | H5 活动页容器（一次发版做容器；后续活动页面只发 H5 + 配置） |

| 基础能力 | 活动规则/说明/奖励列表展示 |

| 托管 | 活动 H5 放 **vault-server 静态目录**；`hotconfig.activities` 下发（id/name/url/start/end/roles/enabled） |
| 生效 | App 启动/「检查更新」拉取 activities → 活动中心出现入口；无需重装 |
| 前置 | 一次发版（活动中心 + 隔离 WebView + JSBridge + activities 解析） |
| 验收 | 配置新增活动 → 点检查更新 → 入口出现 → 打开 H5 → 领取走 Bridge → 关闭返回；停用后入口消失 |

### 12.2 明确不采用

- Tinker/Bugly/Robust：不能新增 Activity/Manifest（Tinker README 明确限制），只适合修 bug。
- Shadow/RePlugin/VirtualAPK/Atlas：可新增原生页面但与 VirtualApp 容器存在双 hook 冲突风险；VirtualAPK 已归档、Atlas/Robust 停更。若未来必须原生页面，先做 Shadow + VA 的 PoC 再立项。
- AAB Dynamic Feature：仅 Google Play 分发，本项目侧载不适用。

### 12.3 已确认决策（2026-11-06）

| 决策项 | 结论 |
|---|---|
| 活动数据源 | 游戏协议抓包 → **服务端统计**；H5 通过 Bridge/接口读取服务端统计结果 |
| 权限矩阵 | **纳入**：新增功能 key `activity_center`（随容器一次发版）；服务端 `featureSeed` 39 → 40 项；建议默认 T2 可见、GM 恒开，最终默认等级按运营口径实现时确认 |
| H5 发布流程 | 仓库新增 `activity-web/<activity-id>/`（纯静态）；产物上传 vault-server `data/activity/<id>/`；hotconfig url 指向 `/v1/vault/activity/<id>/index.html`；vault-server 增加静态路由（或 nginx 映射）；回滚保留上一版目录 + 配置指回；灰度用 `enabled`/`roles` |

### 12.4 待实现时确认
