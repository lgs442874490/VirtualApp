# 分身内输入触发闪退修复（2026-10-22）

## 现象
号库分身（VirtualApp 容器内 `com.gof.china`）中点击任何输入框（聊天/账号密码）时，容器游戏闪退回宿主 App。

## 根因（真机复现 + 系统记录）
1. 冷输入法（`adb shell am force-stop com.baidu.input_vivo`）后，进入容器游戏并点击聊天输入框；
2. 输入法冷启动期间游戏窗口收到焦点变化，游戏主线程 5s 内未确认 → 系统 ANR：
   `Input dispatching timed out (com.gof.china/...DDUnityLaunchActivity is not responding. Waited 5000ms for FocusEvent(hasFocus=false))`；
3. 系统移除容器任务，表现为「闪退」；输入法进程在 ANR 之后才完成冷启动（`am_proc_start` 时序）。
4. 对照实验：先在**宿主 App** 内聚焦输入框预热输入法，再启动分身 → 点输入框键盘正常、无 ANR、可输入 → 确认是输入法冷启动与 VirtualApp 焦点事件竞争。

## 修复
在 `EntryDetailActivity` 拉起分身游戏前执行 `warmUpInputMethodThen()`：
- 宿主窗口挂 1px×1px 透明可聚焦探针 → `showSoftInput` 拉起输入法（≤800ms，检测键盘显示即提前收尾）→ 收起键盘/移除探针 → 继续原启动流程。
- 所有启动路径（按钮/重试/重新克隆后拉起）统一走预热；防重入；异常/超时永不阻断启动。
- 状态机 `daily/ImeWarmup`（纯逻辑，16 单测）。

## 验证
- 修复前：冷输入法 → 容器输入框 → ANR（lastanr 时间更新，任务被移除）。
- 修复后（debug 集成包）：冷输入法 → 启动分身日志 `[IME预热] 开始/完成` → 容器输入框键盘弹出、`adb shell input text` 可输入、`lastanr` 不更新、无闪退。
- 证据：`qa/evidence-20261022-imefix/`。

## 残余风险
- 冷输入法预热时键盘可能短暂闪现（≤800ms）。
- 若某 ROM 完全阻止宿主 `showSoftInput`，预热超时后会退化为现状（不更差）。
