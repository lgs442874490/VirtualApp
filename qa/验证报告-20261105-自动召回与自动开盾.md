## 2. 实现要点

### 2.1 自动召回

- 我方采集：`type=4`，`state=2`（在途）/ `state=3`（采集中）。
- 敌方：`type=2/4/110`，同点匹配；排除自己、同联盟/友盟、PvE、`type=100/102`。
- 时间基准：`A`=我方抵达（state=2 的 endtime）、`G`=采集结束（state=3 的 endtime）、`E`=敌方抵达、`N`=提前量（默认 2，最小 2）。
- 场景一：`E-N < A` → 在途 `req_world_march_recall`；
- 场景二：`E-N >= A && E < G` → 落位后 `req_world_march_off_work`；
- 敌方已落地/`E` 未知 → 立即召回；
- `endtime` 加速提前 → 下一 tick 重算，跨阈值立即触发；
- 推送丢失兜底：每 60s `req_world_mapobj` 查采集点，`map_resource.march_id` 非己方 → 召回；
- 失败最多重试 2 次（间隔 60s），之后告警；同行军 10 分钟冷却。

### 2.2 自动开盾

- 两种模式：`immediate` / `before_arrival`（默认 2 秒，最小 2）。
- 防骚扰：新键 `shield_anti_harass`；旧配置无该键时保留原 `troops_min` 行为。
- 开盾顺序：已有护盾（跳过）→ 免费盾 → 背包盾（2h→8h→12h）→ 钻石购盾（默认关）。
- 钻石购盾：`req_shop_quick_buy{id:302301,count:1,use:false}` → `req_use_item{302301}`；实测 400 钻；日预算默认 3、单次 1 个、失败不重试风暴。
- 护盾账本：`notify_city_item_init/update` 槽位 101 + `notify_backpack_init/update` 302301/302302/302305；写回 `shield_active_item/shield_active_end/shield_count_*`。
- App 展示：当前护盾剩余分钟 + 背包 2h/8h/12h 数量；未同步显示提示。

### 2.3 输入校验

- App：空值/非数字/负数/`<2`/`>600` 秒拒绝；阈值空/非数字/负数拒绝；错误 toast，不落盘。
- 服务端：同口径二次校验，非法值回退 2 秒 / 0 阈值并告警。

## 3. 协议依据（2026-11-05 真机实测）

```text
使用 2h 盾：req_use_item {"id":302301,"count":1,"extra":{}} → code=0
          → notify_backpack_update del 302301
          → notify_city_item_update slot 101 itemid=302301，7200 秒
购买 2h 盾：req_shop_quick_buy {"id":302301,"count":1,"use":false,"extra":{}} → code=0
          → notify_resource_update del 101×400
          → notify_backpack_update add 302301
```

- `302301`=2 小时、`302302`=8 小时、`302305`=12 小时。
- `notify_backpack_init` / `notify_resource_init` 是登录快照，购买后不刷新；实现按 `init + update` 维护账本。

## 6. 已知限制与风险

1. **兜底查询只保落位后发现**：`req_world_mapobj` 每 60s 一次，推送丢失/范围外时无法保证“途中提前发现”；状态会标注“地图复核”。
2. **友盟判断依赖 watchpoint 配置**：`friendAids` 为空时只能按同 aid 排除；`aid` 未知时保护优先，可能误召回。
3. **钻石价格不硬编码**：实现按 302301 购买，实测 400 钻；预算按次数（默认 3/日），未按余额动态限流。
4. **默认行为变化**：新配置默认 `before_arrival` + 2 秒；旧配置无 `shield_mode`/`eta_sec` 时服务端按新默认 2 秒（旧单测用显式 `eta_sec=0` 保留原语义）。
5. **护盾数量刷新**：App 读取服务端状态快照，页面打开后不主动拉取；未同步时显示提示。
