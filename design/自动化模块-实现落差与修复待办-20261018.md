## 7. 下一批 P1：「服务器多角色轮转」文件级实现预案（只写预案，不写代码）

### 7.1 目标与非目标

- **目标**：账号开启统一自动化（keep/auto）后，对 App 传入的**所有启用角色**（工作区 `enabled=true`，sid>0）依次执行每日整轮；每角色独立落 `log:/st:/summary`，账号级 `srv:lastrun` 表示“全部启用角色已完成”；支持中断后续跑；单角色账号行为完全不变。
- **非目标**：不做同账号多角色**并行在线**（游戏硬约束，见 7.2）；不改协议；不改 App 容器侧 `RoleSessionKeeper` 竞速逻辑（那是 App 端容器模式，与本服务器模式互斥，需 UI 提示）。

### 7.2 硬约束与现状证据

1. **游戏单会话硬约束**：同账号多角色并行会互踢（同指纹也互踢，错误码 5/46）——`qa/多角色并行在线验证与单会话终判-v3.9.0.md:39-50`；App v3.9.2 的“竞速登录”只是客户端容器侧高风险方案，服务器模式不应依赖。→ **顺序轮转**。
2. **服务器现状 = 每账号一条会话、绑定 activeSid**：`SessionKeeper.java:14-19`（类注释“每账号一条会话（active 角色，v3.9.1 单会话语义）”）、`LiveSession:43` 起、`resolveSid:122-131`、`loginBoundRole(acc):141-200`、`submitRound:367-417`。
3. **调度器现状 = 按账号、账号级 lastrun**：`RoundScheduler.tick:102-170`，`srv:lastrun:<fpid>`（`:128`），supply 补领按会话 sid（`:164`）。
4. **服务端不知道“哪些角色启用”**：App 上传 `roles[]` 只有 sid/identity/config/params，无 `enabled`（`VaultSync.syncFields:456-482`）；服务端 `handleSync:142-205` 不解析 enabled、`VaultStore.Account:34-54` 无角色清单/启用位；只能用 `roleConfig/roleParams` 的 key 推断 sid（会把未启用角色也算进来）。
5. **既是资产也是约束的键位**：`log:<fpid>:<sid>:<fn>`、`st:<day>:<fpid>:<sid>:<fn>` 已天然 per-role（`RoundRunner.java:101,129`）；采集状态键已含 sid（`CaptureTasks.java:215,228,270,317,349,392`）；`srv:roleuid:<fpid>:<sid>` 角色 uid 缓存已存在（`SessionKeeper.java:155-165` 附近 `srv:roleuid`）→ 轮转切换可复用，无需重新 discover。
6. **账号级键需改造**：`summary:<fpid>`（`RoundRunner.java:87`、`ModularRoundRunner.java:104`）、`srv:lastrun:<fpid>`（`:90`、`:106`）、`/status` 单 sid（`SessionKeeper.status:428-461`、`VaultHttpApi.statusAccountsJson:241-262`）。

### 7.3 关键设计决策（建议）

| # | 决策 | 说明 |
|---|---|---|
| D1 | **顺序轮转，一账号同一时刻只在线一个角色** | 单会话硬约束；角色间切换需重新登录（引擎 close/initialize + applyIdentity + loginByRole） |
| D2 | **启用角色清单唯一事实源 = App `RoleStore.Role.enabled`** | App `syncFields` 上传 `roles[].enabled`；服务端持久化到 `VaultStore.Account`；不再用 roleConfig keys 推断 |
| D3 | **调度粒度 `(fpid, sid)`，但窗口随机抽样按账号一次** | 保持现有“窗内随机时刻”语义；当天窗口内跑完所有启用角色（可超出窗口继续，不中止） |
| D4 | **账号级 `srv:lastrun:<fpid>` = 所有启用角色已尝试完**；新增 `srv:lastrun:<fpid>:<sid>` 角色级 | 兼容 App 现有“今日已跑”读取（`VaultHttpApi.automationSnapshot:340-375` 读账号级；`RoundScheduler:128` 读账号级） |
| D5 | **新增“角色轮转编排”类，复用 `ModularRoundRunner.runRound(engine, acc, sid, ...)`** | 执行器已按 sid 落账，签名无需大改；编排器负责切角/续跑/汇总 |
| D6 | **切角流程**：close 旧引擎连接 → 重建/复位引擎 → `applyIdentity(roleIdentity[sid])` → `loginByRole(角色 uid 缓存或 discoverRoleUid)` → 等 online → 跑整轮 → 记录结果 → 下一角色 | 复用 `loginBoundRole` 逻辑参数化；`identitySeed(acc)` 需接受 sid 参数（`SessionKeeper.java:464-471` 现在只读 activeSid 指纹） |
| D7 | **失败策略**：任一角色登录失败/掉线 → 中止本轮轮转，**不写账号级 lastrun**；写续跑标记，下一 tick 从失败角色继续；连续 N 次失败降级只跑 activeSid + 告警 | 避免“某角色坏了导致整号永不整轮” |
| D8 | **兼容/灰度**：`VAULT_MULTI_ROLE=0` 关闭（先本地默认关）；单角色账号走现有 `submitRound` fast path 零改动；`VAULT_LEGACY_ROUND=1` 与多角色正交（legacy runner 也接受 sid） | 回滚简单 |
| D9 | **App 展示二阶段**：`/status` 每账号追加 `roles:[{sid,enabled,lastRun,state}]`；今日页文案“角色 i/n 已完成” | 旧 App 忽略未知字段，先服务端灰度 |
