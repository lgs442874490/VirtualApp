# 消息战争通知模块（敌人监视 → 企微机器人/短信）2026-10-22

## 目标（用户原话）
> 会话监听的时候监听标记的敌人有没有动作，然后通过企业微信机器人/短信的形式通知到我方。

## 架构
```
[游戏服务器推送 notify_player_march_add/update/del、notify_mass_march_*、notify_world_*]
        │  (vault-server 常驻会话，WjdrEngine.addMessageHook)
        ▼
[WarNotify 解析：健壮递归查找 owner/uid、march id、目标坐标、endtime、type]
        │  命中账号级「监视名单」+ 冷却节流（默认 300s）
        ▼
[WatchEventStore 事件环形缓冲（最近 200 条，data/events.json，SEQ 游标）]
        ├──► WeComNotifier：HTTP POST 企业微信群机器人 webhook（msgtype=text，6s 超时，重试 1 次，失败仅日志）
        └──► App WarNotifyPoller（前台服务内 30s 轮询 /v1/vault/events 增量）
                 └──► WarNotifyGate（开关/权限/eventId 去重/5 分钟节流）
                          └──► SmsManager 发送到配置手机号
```

## 服务端（vault-server）
- `WarNotify`：推送解析 + 监视名单匹配 + 冷却；事件内容 `{eventId, fpid, sid, targetUid, targetName, action, marchId, endtime, point{x,y}, proto, detectedAt}`。
- `WatchEventStore`：最近 200 条环形缓冲，增量游标 ack，落盘 `data/events.json`。
- `WeComNotifier`：企微机器人 text 推送；日志只留 webhook host 不含 key。
- 新 API（签名沿用 ApiSign，路径 `/v1/vault/watch`、`/v1/vault/events`）：
  - `list/add/update/remove`：账号级监视名单（uid 必填，name/kid/note 可选，enabled）
  - `config`：全局通知配置（enabled/wecomEnabled/webhookUrl/cooldownSeconds/quietStart/quietEnd）
  - `test`：测试推送
  - `events`：按游标拉增量 + ackCursor
- 安静时段（quietStart/quietEnd，分钟）内不发企微；冷却防轰炸。

## App（号库）
- 入口：我的 → **战争通知**（`NotifySettingsActivity`）。
- 页面：监视账号选择器 / 监视名单（增删改开关）/ 企业微信 webhook 配置+测试 / 短信开关+手机号+`SEND_SMS` 权限引导 / 最近事件列表。
- 后台：`DailySchedulerService` 启动时 `WarNotifyPoller.start`（30s 轮询，幂等；短信关闭时空转）；事件游标/去重/节流存本地 prefs。

## 安全与边界
- 监视名单与 webhook 存服务器侧（随账号数据持久化）；手机号仅存 App 本地。
- 仅通知，不自动执行任何游戏动作；不改账号池/守护逻辑。
- 短信为可选降级（权限拒绝/无 SIM 时只记日志，不影响企微通道）。
