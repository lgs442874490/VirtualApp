## 1. 设计原则

1. **按领域分模块，不按协议/文件分**：奖励、联盟、银行、采集、宠物、商店、军医所、野外/情报。
2. **模块之间零直接调用**：跨域能力只通过注入的 Service（编队、军医、商店、英雄目录）使用。
3. **动作 id 复用旧 fnId**：`log:` / `st:` / App 功能详情零迁移，避免破坏已完成的状态链。
4. **配置集中、默认兼容**：旧 `roleConfig/roleParams` 自动迁移；新配置按模块/动作分层覆盖。
5. **未知能力显式降级**：协议未确认的奖励项标记 `PENDING_PROTOCOL`，绝不假成功。
6. **执行顺序可验证**：模块注册表校验唯一性、依赖存在、无环，并做拓扑排序。

## 3. 核心接口

### 3.1 模块与动作

```java
public interface AutomationModule {
    String id();
    String displayName();
    ModuleCategory category();
    default List<String> dependsOn() { return Collections.emptyList(); }
    List<ActionDefinition> actions();

    default ModuleResult execute(AutomationContext ctx) {
        ModuleResult result = new ModuleResult(id());
        for (ActionDefinition action : actions()) {
            boolean enabled = ctx.config().actionEnabled(action.id(), action.defaultEnabled);
            if (!enabled) {
                result.add(action.id(), new TaskOutcome(action.id(), action.name(),
                        TaskOutcome.Category.SKIPPED, "配置未启用"));
                continue;
            }
            TaskOutcome outcome = action.execute(ctx.task());
            result.add(action.id(), outcome);
            if (outcome.category == TaskOutcome.Category.SESSION_CLOSED) break;
        }
        return result;
    }
}
```

```java
public final class ActionDefinition {
    public interface Executor { TaskOutcome run(TaskContext ctx) throws Exception; }
    public final String id;          // 必须复用旧 fnId
    public final String name;
    public final boolean defaultEnabled;
    public TaskOutcome execute(TaskContext ctx) throws Exception;
}
```

### 4.2 兼容迁移

`AutomationConfig.fromLegacy(modules, roleConfig, roleParams)`：

- 旧 `roleConfig` 的 `fnId→bool` 直接映射为动作开关；
- 旧 `roleParams` 的 `fnId→JSONObject` 直接放入 `params.<fnId>`；
- 未配置项沿用 `ActionDefinition.defaultEnabled`；
- 旧账号不需要任何数据迁移即可运行。

### 5.2 联盟系统模块（Alliance）

- `alliance_chest`：`req_alliance_receive_chest`，按宝箱 id/type 领取；已领/不存在归 SKIPPED。
- `alliance_donate`：`req_alliance_science_donate`；免费科技捐献 + 每日/每周发展奖励；
  账号状态码（2/1507/40031/40032/40034）统一归 SKIPPED。
- 模块无内部状态，幂等由游戏返回码保证。

### 5.3 银行系统模块（Bank）

- 每轮读取 `notify_reward_info.bank.use_locker`：
  - `amount/locker_id/expire_time`；
  - 未到期 → SKIPPED；
  - 到期 → `req_bank_withdraw` 取款，成功后 `req_bank_deopsit` 原额续存（向下取整到 100）；
- `cycle_hours` 只用于配置展示/调度提示；实际到期以游戏 `expire_time` 为准。
- 关键：取款成功但续存失败必须分别记录，不能把整轮记为成功。

### 5.4 采集系统模块（Gather）

- `FormationPlanner` 负责编队；`FormationPlanner.Request` 包含：
  `scheme=GATHER`、`resource`、`targetAmount`、英雄选择器、`ownedHeroIds`。
- **动态兵力公式**：

```text
carry     = max(1, carry_per_troop × (1 + hero_carry_bonus))
required  = ceil(target_amount / carry × (1 + buffer_pct / 100))
required  = clamp(required, min_troops, max_troops, available_troops)
```

- 兵种分配：按 `shield_ratio/spear_ratio/bow_ratio`（默认 40/30/30）分配到具体兵种 id；
  某兵种不足时只派可用量，不超发。
- 英雄选择：
  - 射手：`吉娜`（`HeroDirectory.findByName`）；
  - 矛兵：`波根`；
  - 盾兵：`strongest_shield`（按英雄目录战力选最强盾兵）；
  - 目录解析不到 → 计划 invalid，明确返回“英雄目录缺失”，不派错英雄。
- 持续采集：每轮检查 `countMarches(type=4)` 与 `marchCapacity`，有空位才派；
  `max_queues` 可配；资源类型按肉/木/煤/铁的配置顺序轮转。
- 接入点（2026-10-18 21:xx 更新）：`ServerFieldTasks.gather` 读取 App 采集弹窗的
  `squad_index`，优先直接使用游戏内第 N 队布阵（`Exec.formation`）；未选择编队时才回退
  `FormationPlanner`/英雄参数。动态兵力公式保留给 `hero_ids/troop_count` 配置路径。

### 5.5 宠物系统模块（Pet）

- `auto_skills` 总开关；`selected_skills` 指定技能 id 列表。
- 已落地：`ServerTownTasks.pet` 优先读取 `selected_skills`，为空才回退旧默认技能集合；
  调用 `req_pet_use_skill(skill_id_lst)`。
- 冷却/不可用返回码（11539 等）归 SKIPPED，不污染异常计数。
- 寻宝/联盟宝箱继续走原协议。

### 5.6 商店系统模块（Shop）

- 协议：
  - 库存：`req_shop_info_array(arr_id)`；
  - 购买：`req_shop_buy(shop_id, goods_id, count)`；
  - 刷新：`req_shop_refresh(shop_id)`。
- `ShopService` 负责纯策略：
  - `select()`：指定 id ∪ 全部 ∪ 免费 ∪ 折扣，库存=0 排除；
  - `nextRefresh()`：达到购买目标 → 停；免费次数未用完 → 免费；否则按配置钻石刷新，
    直到 `max_diamond` 或 `target_purchases`。
- 关键安全：`allow_diamond` 默认 **false**，避免误花钻石；只有显式配置才允许。
- 接入点：把 `nextRefresh` 循环接到 `buyFromShops`，每轮刷新后重新拉库存并重新选品。

### 5.7 军医所模块（Medic）

**BUG 修复**：旧实现只读 `notify_hospital_init.wound_soldiers`，实战大量伤兵来自
`notify_hospital_wound_soldiers` 推送（init 可能是空快照）。

`MedicService.snapshot()` 现在合并：

```text
notify_hospital_init.wound_soldiers
notify_hospital_wound_soldiers.wound_soldiers
notify_brawl_war_hospital_init.wound_soldiers
notify_arsenal_war_hospital_init.wound_soldiers
notify_arsenal_league_hospital_init.wound_soldiers
```

- 同一兵种多来源取 **max**，避免重复计数；
- `notify_hospital_init.heal_data.soldiers` 单独记录为“治疗中”；
- `heal_count=0` 治疗全部，>0 最多治疗指定数量；
- `request_help=true` 治疗后调用 `req_alliance_help_all`（当前可用援助协议；若后续确认
  医院专用求助协议再替换）；
- 仍无伤兵时返回 SKIPPED，并在消息里带来源摘要，便于排查“为什么显示无伤兵”。

**已落地**：`ServerTownTasks.medic` 已改为委托 `MedicService.heal()`；
新增 `MedicServiceTest` 锁定“init 空 + push 大量伤兵”合并取 max 的回归。

### 5.8 野外/情报模块（Wilderness）

- `intel`：`req_intelligence_receive(id)` 逐个处理待办情报；无事件 → SKIPPED。
- 专家额外情报：复用 `intel`，配置 `expert_extra_intel=true` 时把专家情报页事件纳入。
- 编队方案集中在 `FormationPlanner`：

| 方案 | 英雄 | 兵力 | 说明 |
|---|---|---|---|
| `beast`（打野兽） | 射手吉娜、矛兵波根、最强盾兵 | 满兵（`full_troops=true`） | 省体力，要求满兵 |
| `behemoth`（集结巨兽） | 一个盾兵 + 吉娜 + 波根（顺序盾兵优先） | 盾兵为主（`shield_first=true`） | 其余英雄与野兽方案相同 |
| `gather` | 吉娜、波根、最强盾兵 | 动态计算 | 采集 |

## 6. 执行编排

`ModularRoundRunner`：

1. 组装 `TaskContext`（engine/fpid/sid/state/params）。
2. `ModuleRegistry` 拓扑排序，按模块顺序执行；每个模块用自己的 `ModuleConfig`。
3. 每个 `ActionOutcome` 以旧 `actionId` 调 `RoundRunner.applyResult` 落 `log:/st:`；
4. 全量采集状态 → `summary:<fpid>`；
5. 只有整轮（`fnOnly=null`）写 `srv:lastrun`，单任务不消耗当天整轮。

## 8. 扩展方式

### 8.1 新增一个奖励项

在 `FormationPlanner.Scheme` 增加枚举 + `DefaultFormationPlanner` 分支；
