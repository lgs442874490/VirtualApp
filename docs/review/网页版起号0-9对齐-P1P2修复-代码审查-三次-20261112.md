## 二、新发现 / 残留（均非阻断）

### P2-12 `single-reset` 在线调用会分裂会话状态，且无审计日志

- **位置**：`vault-server/src/main/java/com/carlos/vaultserver/bootstrap/BootstrapApi.java:470-483`（清 `BootstrapSessionState.shared()` 与 `BootstrapHoldStore`）。
- **问题**：若该 fpid 仍在批次运行（`ACTIVE` 有会话），批次 `BootstrapService` 在构造时已持有旧 `Holder` 引用；reset 只移除映射，旧 Holder 继续被批次使用，新请求则创建新 Holder → 两套 world/finishPass/ENDED 状态并存。表现可能为：旧 ENDED 仍拦截批次、新 Holder 重发 world/重跑收尾、hold 被清后立即重试被退避的动作。方法内无 `FileLog` 记录。
- **影响**：人工操作竞态，只读/离线重置无影响；无审计日志不利于事后追溯。
- **建议**：`ACTIVE.containsKey(key)` 时拒绝（提示先停批次/取消），或显式定义“在线重置”语义（移除 ACTIVE、关闭会话）；并补一行 `FileLog.info`。
- **优先级：P2（低）**

### P2-13 库存足够时仍按 force 全量成本购买（钻石浪费残留）

- **位置**：`vault-server/src/main/java/com/carlos/vaultserver/bootstrap/BootstrapService.java:1313-1330`（`need*` 全量成本 + `buyForMissing`）、`:1342-1355`（unsupplied 已改缺口）。
- **问题**：P1-3 只修了 unsupplied 口径；当四个 gap 全为 0（库存足够）时没有短路，仍按全量成本买包。网页版 `BootstrapService.java:1649-1651` 在缺口全 0 时直接返回。
- **影响**：触发条件为“51 但本地库存足够”（资源表滞后或非资源原因），会多发钻石；不影响 ENDED 判定（coverable 已正确）。
- **优先级：P2（低）**

### 低优先级

- `BootstrapSessionState.worldAbandoned()`（`:150-152`）无调用方（死代码），删除或用于状态视图。
- `BootstrapApi` 类注释 `action=single-* → 无在线 engine 报错`（`:41`）与 `single-reset` 可离线调用不一致。
- `finishPass_serverClockInvalid_fallsBackLocalDate` 仍以断言时刻 `now()` 折算（`BootstrapServiceTest.java:2244-2246`），跨午夜窗口理论 flake（概率极低）；建议注入固定时钟。
- `singleReset` 未清理引擎 `pendingResUpdate`（重连/重登会清，非必需）。
