# 热更新自托管 + 参数选项化（2026-10-25）

> 分支：`modify/ui-config-hotupdate-20261025-0030`（未提交，等用户审核）
> 用户要求：①「热更新你重新做吧」（原热更源不可用）；②「处理高级参数（JSON）功能，不要给用户填 JSON，都改成开关或选项」。
> 实施：DSH Lead + hotupdate-dev + uiconfig-dev；全量门禁见 §5。

## 1. 什么是热更新（先解释）

热更新 = **App 启动/手动检查时拉取一份 JSON**，用它做两件事：
1. **整包更新提示**：JSON 里的 `apk.versionCode/versionName/url/notes` 与本机版本比较，若更高则弹窗引导下载新 APK；
2. **配置/目录热更**（不重装）：`nums/catalogs/claims/disabled` 等字段可改数值、商店目录、声明式领取项、禁用功能。

旧实现的问题：更新源是 `prefs hot_url`，出厂为空；唯一记录的地址 `http://192.168.1.4:8765/hotconfig.json` 是开发机临时 HTTP 服务，已不可用 → 用户侧永远显示「未配置更新源」。

## 2. 新方案：热更新自托管在 vault-server

```
App HotConfig ──GET──> VaultSync.baseUrl(ctx) + /v1/vault/hotconfig
                                    │ (nginx 已反代 /v1/vault/，无需改 nginx)
                                    ▼
                    vault-server: data/hotconfig.json
                       （{base} 替换为 scheme://Host 后原样返回）
App 弹窗下载 ──GET──> .../v1/vault/app-latest.apk
                                    ▼
                    vault-server: data/download/app-latest.apk（12MB 流式）
```

### 2.1 服务端（新增 `HotConfigRoutes.java` + 两条 GET 路由）

| 路由 | 行为 |
|---|---|
| `GET /v1/vault/hotconfig` | 读 `dataDir/hotconfig.json`；把 `{base}` 替换为 `scheme://Host`（`X-Forwarded-Proto`/`X-Forwarded-Host` → `Host` → 监听地址；可用 `VAULT_PUBLIC_BASE` 强制）；原样返回 JSON，无信封；缺失 404 |
| `GET /v1/vault/app-latest.apk` | 流式返回 `dataDir/download/app-latest.apk`；`application/vnd.android.package-archive` + Content-Length；缺失 404 |

### 2.2 App 端

- `VaultSync.baseUrl(ctx)` 公开；新增 `VaultSync.fetchText(ctx,url)`（生产自签 HTTPS 复用 `HTTP_PINNED` 证书 pin，解决裸 OkHttp 拉取失败）。
- `HotConfig.hotUrl(ctx)`：prefs `hot_url` 非空优先，否则默认 `baseUrl + "/v1/vault/hotconfig"`；启动/6h 刷新/手动检查三处统一。
- 「我的 → 检查更新」不再显示「未配置更新源」，默认可直接检查。
- 旧设备若 prefs 残留失效地址仍优先（可用 `adb broadcast ... --es url` 覆盖或清除 App 数据）。

### 2.3 发布流程（每次发版）

```bash
# ① 正常发版（tools/release.sh）得到 APK 与 versionCode
./tools/release.sh
# ② 生成热更 staging（version=yyyyMMddHH；apk.url 用 {base} 占位）
./tools/hotupdate_prepare.sh "无尽号库-v4.2.9-HTTPS加密版.apk" 23519 "4.2.9-HTTPS加密" "更新说明"
# ③ 部署（本地/生产同样）：hotconfig.json 放 dataDir，APK 放 dataDir/download/app-latest.apk
scp .hotupdate/hotconfig.json vault-vps:/opt/vault-server/data/hotconfig.json
scp .hotupdate/download/app-latest.apk vault-vps:/opt/vault-server/data/download/app-latest.apk
# ④ 自检：确认 apk.url 是公网可访问地址（不是 127.0.0.1）
curl -s http://103.236.96.82:64868/v1/vault/hotconfig
curl -sI -X GET http://103.236.96.82:64868/v1/vault/app-latest.apk
# ⑤ App：我的 → 检查更新
```

> nginx 若未透传 Host/X-Forwarded-*，`apk.url` 可能变成 `127.0.0.1`；兜底：`/etc/vault-server.env` 加
> `VAULT_PUBLIC_BASE=http://103.236.96.82:64868` 后重启 vault-server（无需改 nginx/发版）。

## 3. 高级参数（JSON）入口移除 + 参数选项化

| 功能 | 改动 |
|---|---|
| 全部功能 | 删除 FunctionActivity「高级参数（JSON）」卡片、`supportsAdvancedConfig`、`showAdvancedConfig`；用户侧不再有任何 JSON 参数输入 |
| 自动狩猎 | 新增「狩猎设置」卡：等级下限 1-10、等级上限 1-10、出击次数 1-20，全部单选下拉；保存写 `level_min/level_max/max_times`（存储格式不变，服务器/FieldTasks 无感）；下限>上限自动夹取 |
| 采集 | 保留「采集设置」6 队列可视化页（本就不是 JSON 输入） |
| 战斗护盾/守护盟友等 | 保留子项开关/策略选项；无 JSON 入口 |
| 其它曾出现 JSON 入口的功能 | 入口移除；默认值/执行行为不变（这些 JSON 多数为历史遗留、执行侧并未消费） |

新增 `HuntConfig.java` 纯函数（parse/clamp/apply/options/summary）+ 14 例 JVM 单测。
