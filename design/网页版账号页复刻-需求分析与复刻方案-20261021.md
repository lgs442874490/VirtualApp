## 1. 背景、目标与范围

### 1.1 背景
App 当前账号页（`HomeActivity` 账号页，v4.1.4）是「身份库 + 服务器会话」的最小管理视图：按账号卡片展示工作区角色与单角色「登录」，在线状态来自 vault-server `/v1/vault/status`。网页版账号页是成熟的**账号池控制台**：多账号分组、每角色在线状态、单角色/账号级/全局的上线·暂停·停止、批量管理、凭据复制、恢复设置等，支持大量账号同时在线（实测 `online_count=55`）。

### 1.2 用户提出的两个关键缺陷
1. **真机环境下无法启动游戏分身**：账号相关页面缺少可用的「启动分身」能力/失败不可诊断。
2. **无法实现多账号同时在线**：App 只能保持单一当前角色在线，账号页没有账号池级别的并行在线管理。

### 1.3 目标
- 以网页版账号页为**行为基准**，在 App 账号页 1:1 复刻其功能与状态语义（视觉可按 App 设计语言适配，交互/状态/计数/动作结果必须一致）。
- 修复上述两个缺陷：
  - 「启动分身」在本机真机可用、失败可诊断可恢复，并与账号页在线状态联动；
  - 支持**跨账号**多账号同时在线（同账号受游戏服单会话约束，同时仅一个角色在线），账号页提供上线/暂停/停止/批量与实时状态。
- 交付物：本文件（根因分析 + 复刻清单 + 验收标准 + 一致性说明），随后按里程碑开发/测试/验收。

### 1.4 范围
- 本期（P0）：账号池视图、在线状态机、单角色与账号级/全局启停、多账号并行在线、启动分身（本地容器）与诊断、刷新/轮询、搜索/计数、与现有角色切换/自动化/服务器同步的回归。
- 后续（P1/P2）：批量复制凭据、防封保护、导入导出/移动账号/资源统计/恢复设置、多用户 admin「仅我的账号」等（见 §5 分层）。

## 2. 网页版账号页现状（需求基准）

### 2.1 证据来源
- 真机/浏览器实拍：`http://111.228.32.189:8888/` 登录后「日常」模块左侧账号池；
- 前端构建产物逆向（`frontend/` 与线上 `assets/index-DePcdlvG.js` 一致，Vue3+Element Plus）：`AccountSidebar` 组件、`AccountManagementDialogs`、`AccountRecoverySettingsDialog`、`RoleWorkspaceManager` 等；
- 线上 API 实测：`POST /api/auth/login` → Bearer JWT(20min)；`GET /api/daily/accounts` 返回 `{"online_count":55,"accounts":[...]}`；
- 后端源码（`src-tool/com/wjdr/tool/core/account/GameAccountControllerSupport.java`、`GameAccountSyncController.java`、`modules/daily/web/DailyAccountController.java`）。

### 2.2 界面结构
```
左侧账号池（AccountSidebar）
├─ 顶部工具行：[全部上线/全部停止] [批量复制账号] [刷新账号状态] [切换角色]
├─ 搜索框：角色名 / 账号 / 区服
├─ 仅我的账号（admin）开关
├─ 账号分组（按主账号=accountId 分组，可上移/下移）
│  ├─ 组头：账号名 + 区服 + 「工作区 N · 在线 N」 + [全部上线/全部停止]
│  └─ 角色行：状态点 + 角色名 + 区服 + [上线] [暂停] [停止] + 防封保护开关
│     └─ 被顶号时 banner：「账号被顶号 待恢复 mm:ss」
└─ 未选择工作区角色时：「尚未选择工作区角色」+ [选择角色]（角色管理弹窗）
右侧/主区：当前选中角色的日常模块工作区（略，本需求只复刻账号页）
```
账号管理弹窗（AccountManagementDialogs）：新建/编辑账号（账号、令牌、加密串、手机号/SMS 登录）、角色管理（启用/停用、重命名、删除、工作区选择）、恢复设置、资源统计、配置导入导出、账号移动。

### 2.3 角色/账号状态机（网页版权威文案，来自前端 `vt(f)`/`yt(f)` 函数）

判定辅助：`yt(f) = takeover_recovery_active===true && recovery_state==="WAITING_RETRY"`（顶号恢复倒计时中）。

| 优先级 | 条件 | 文案 |
|---|---|---|
| 1 | `online=true` | **在线** |
| 2 | `run_state=PAUSED` 且 `yt` | 已暂停·待恢复 |
| 3 | `run_state=PAUSED` | 已暂停 |
| 4 | `run_state=STOPPED` | 已停止 |
| 5 | `recovery_state=DISABLED` 且 `status_message` 含「其他设备」 | **被顶号** |
| 6 | `recovery_state=ACTION_REQUIRED` | **需登录** |
| 7 | `yt`（顶号恢复中） | 待恢复 + 倒计时（`next_recovery_at`，≥1h 显示 h:mm:ss，否则 mm:ss；≤0 显示「· 即将恢复」） |
| 8 | `startup_in_progress \|\| login_in_progress` | 登录中 |
| 9 | `run_schedule_state=PAUSED` | 计划休眠 |
| 10 | `enabled=false` | **已收纳**（注意：不是"已停用"） |
| 11 | 默认 | 离线 |

补充：
- 角色行还有「角色来源」标记（`originModule`，来自其他模块复制/同步）；
- 状态 chip 的 title = `status_message`（悬停显示详细原因）；
- 「在线」角色可「暂停/停止」；「未在线且未被收纳」可「上线」；`enabled=false` 角色操作禁用并在角色管理中启用。

### 2.4 动作 → 状态转换（网页版语义）
| 动作 | 触发 | 结果语义 |
|---|---|---|
| 上线（单角色） | `toggle-account` → `POST /api/{module}/accounts/roles/{id}/login` | 登录中 → 在线；同账号其它在线角色按策略下线（同 fpid 单会话） |
| 暂停 | `pause-account` → `POST .../roles/{id}/pause` | 在线 → 已暂停（按顶号/恢复设置自动恢复） |
| 停止 | `stop-account` → `POST .../roles/{id}/stop` | 在线/暂停 → 已停止（不自动恢复） |
| 全部上线/停止（账号） | `toggle-parent` → `POST .../parents/{accountId}/login|stop` | 账号下所有工作区角色批量操作 |
| 全部上线/停止（全局） | `toggle-all` → `POST .../login-all|logout-all` | 所有账号批量操作；按钮显示进度「停止中 x/y」 |
| 防封保护 | `update-antiban` → 角色开关 | 下次登录/启动生效（App 是否支持见 §7 差异） |
| 刷新 | `refresh` → 重新拉账号列表 | 状态/计数刷新（网页 3s 轮询 + realtime WS） |
| 复制凭据 | `copy-credentials(/code)` | 账号+token+加密串复制到剪贴板（邮箱验证码） |
| 恢复设置 | `parents/{id}/recovery-settings` | 顶号恢复策略（立即/延迟/不恢复等） |

### 2.5 数据字段（`GET /api/{module}/accounts` 实测）
账户组：`accountId/account/account_name/ownerUserId/displayOrder`；角色：`accountRoleId/uid/server_id/game_name/display_name/power/stove_lv/alliance_*/avatar*/enabled/displayOrder`；状态：`online/run_state(STOPPED|PAUSED|RUNNING)/recovery_state(AVAILABLE|DISABLED|ACTION_REQUIRED|WAITING_RETRY)/status_message/takeover_recovery_active/next_recovery_at/startup_in_progress/login_in_progress/run_schedule_state(PAUSED)/availability`；聚合：`online_count`、每账号 `workspaceCount/onlineCount`（前端按 `accountId` 分组聚合）。另含 `antiban_enabled`、`originModule`/`module`（跨模块账号池同一身份）、`displayOrder`。线上实测：127 个角色、56 个在线（2026-10-21 00:33）。

### 2.6 后端 API 清单（复刻映射参考）
`GET/PUT /api/{module}/accounts`；`/roles/{id}/login|logout|stop|pause|copy-credentials(/code)`；`PUT /roles/{id}/enabled`；`/parents/{accountId}/login|logout|stop`；`PUT /parents/{id}/recovery-settings|run-schedule-settings`；`POST /login-all|logout-all|reload`；`DELETE /roles/{id}|/parents/{id}`；`/sms/send|sms/login|encrypted/login|profile/login`；`/api/game-accounts/login-lease`（跨模块单点登录租约）；`sync` / `sync-batch`（跨模块复制账号）。

## 3. App 账号页现状与两缺陷根因分析

### 3.1 App 现状（v4.1.4 / master c8f2e3f）
- 账号页：`HomeActivity`（账号 tab）——账号卡片（分组卡）→ 工作区角色行（状态点/角色名/区服/今日完成/上次登录/登录按钮）+「角色管理」+搜索/筛选（全部/工作区/异常/未跑）/列表·卡片切换/批量管理入口。
- 账号详情：`EntryDetailActivity`——顶部「启动分身」按钮（`doLaunch()` → `VaultEngine.launchEntry`）、「登录并运行自动化」、角色盒、token 管理等。
- 服务器模式：App 不本地跑自动化；`VaultSync` 全量 sync 账号池 + activeUid 到 vault-server，`SessionKeeper` 在服务端建会话/执行任务；App 通过 `/v1/vault/status`、`/state` 展示状态。
- vault-server：`SessionKeeper.sessions: Map<fpid, LiveSession>`（**模型上支持多账号并发**），`reconcile()` 按 `keep` 维护；API 仅 `sync/token/status/state/policy/automation` 六类。

### 3.2 缺陷一：真机无法启动游戏分身 —— 根因（已真机复现确认）

> **已实证（2026-10-21 00:30，vivo V2141A / Android 14 / v4.1.4 release）**：点击「启动分身」后容器**成功拉起游戏**
> （`topResumedActivity=com.lody.virtual.client.stub.ShadowActivity$P0`，Unity/推送初始化日志正常），但游戏启动页显示
> 「更新公告：当前版本过低，请更新最新游戏版本」——容器内游戏版本 **1.16.11.12**；点「更新」后跳转**系统浏览器**下载
> `wjdr_1-16-12_147_1.apk`（888MB，非应用商店包），无法回到容器内完成升级 → 用户实际体验为"启动分身进不了游戏"。
> 证据：`qa/evidence-20261021-account-pool/T1-启动分身真机复现.md`、两张截图。

**根因（按影响排序）**：

| # | 根因 | 证据/代码 | 影响 |
|---|---|---|---|
| A1 | **容器内游戏客户端过旧，且无容器内升级闭环**：游戏强制 1.16.12，更新入口跳系统浏览器下载 888MB APK，需手动侧载；App 无"下载→校验→导入容器覆盖安装（保数据）"流程 | 真机复现（T1）；游戏版本 1.16.11.12 vs 最新 1.16.12；系统原版仅 1.16.11/146（2026-10-04） | 分身拉起但不可玩，等价于"启动失败" |
| A2 | **无版本检测与升级入口**：App 不检测容器内游戏版本、不检查最新版本、不提示"需更新分身游戏"、无法触发升级 | `VaultEngine` 只有克隆（`installPackage(Uri.parse("package:"+pkg))`）与微信 APK 安装；游戏无覆盖升级路径；`AccountVaultActivity` 克隆向导只做首次克隆 | 用户不知道失败原因，也无法自助修复 |
| A3 | **失败不可诊断**：`doLaunch` 失败统一 toast「启动失败：请从任务栏划掉游戏后重试」，`VaultEngine.lastLaunchError`（授权闸门/引擎未就绪/无克隆/入口解析失败/拉起异常/BUSY）未展示 | `EntryDetailActivity.doLaunch()`；`VaultEngine.launchGameLocked()` | 各类失败同文案，无法定位/无法自助恢复 |
| A4 | **入口深且与账号页割裂**：启动分身仅在「卡片视图→账号 tile→账号详情」内；账号页（列表视图/角色行）无入口；启动后与服务器会话的顶号关系无提示 | `HomeActivity:2295`（卡片 tile→`showAccountDetail`）；`EntryDetailActivity:149` | 账号页用户找不到入口；本地/服务器登录易互踢 |
| A5 | **多账号各自克隆版本一致性**：每个账号共用同一容器游戏实例；升级需一次覆盖所有账号数据，操作不当有丢数据风险 | VirtualApp 单包多数据目录（`/virtual/data/user/*/com.gof.china`） | 升级方案必须保数据（见 AC-11/12） |

**修复方向（进入复刻清单 F-11/F-12 与里程碑 M3）**：
1. 分身游戏版本检测：读取容器内 `versionName/versionCode`，与"最新版本配置"比对（配置来源：协议更新检查响应/服务端配置/官方渠道）；
2. 官方 APK 获取：内置下载器（断点续传、进度、校验 size/sha256/签名一致性），或引导用户放入本地 APK；
3. 容器内覆盖安装：`VirtualCore.installPackage(Uri.fromFile(apk))` 升级并保留 `/virtual/data`（需先验证数据保留；必要时先备份/后回滚）；
4. 失败诊断：把 `lastLaunchError` 分类呈现（引擎未就绪/未克隆/授权过期/版本过旧/下载失败/安装失败/系统限制），每类给可执行动作（重试/重新初始化/去更新/联系支持）；
5. 入口调整：账号页提供「启动分身」显式入口（账号行菜单），并在本地启动前提示顶号风险。

### 3.3 缺陷二：无法多账号同时在线 —— 根因
> 结论：**数据模型与服务端控制面缺失**，不是 UI 小问题；当前 App 以"单一当前角色"为中心，网页版以"账号池+每角色会话"为中心。

| # | 根因 | 证据 | 影响 |
|---|---|---|---|
| B1 | App 只维护单一「当前角色」：`active2`/`activeUid`/`current_role` + 防回滚门控，切换角色即重启服务器会话 | `RoleStore/VaultSync/SessionKeeper.reconcile`（切角色→重启会话，生产日志实证） | 任意时刻仅 1 角色在线；无法表达"多账号同时在线" |
| B2 | 账号页缺账号池在线管理：无每角色在线状态机（暂停/停止/被顶号/需登录/待恢复/登录中）、无账号级/全局启停、无批量、无进度、无在线/工作区计数 | `HomeActivity` 账号页仅角色行+登录；服务器 status 只有单一 active 状态 | 无法操作/观测多账号在线 |
| B3 | vault-server 无账号池控制 API 与状态字段：只有 sync/token/status/state/policy/automation，无 per-role/账号启停/暂停/恢复、login-all/logout-all、run/recovery 状态回传 | `VaultHttpApi` 6 个端点；`SessionKeeper.reconcile` 内部逻辑无外部控制面 | 即使 SessionKeeper 能开多会话，App 无法按账号启停 |
| B4 | 游戏服约束：**同账号（fpid）同时仅一条会话**（换角色互踢 code=46），历史已验证 | `号库端侧形态补充文档.md` §二 实证差异 | "多账号在线"必须定义为**跨账号（不同 fpid）并行**；同账号只允许 1 角色在线，UI 必须给出互斥提示 |
| B5 | 无实时刷新：App 依赖手动/进入页面 fetchState；网页 3s 轮询 + WS 实时 ticket | `VaultSync.fetchState/refreshStatus`；网页 `/api/realtime/ticket` | 在线状态滞后，批量操作无进度反馈 |

**待确认产品语义（用户确认项 U2）**：多账号同时在线 = 跨账号 fpid 并行（建议），每个账号同一时刻最多 1 个角色在线；账号数上限暂定 2（测试账号池），设计上不设硬上限（vault-server 资源决定）。

### 3.4 其他现状差距（复刻相关）
| 维度 | 网页版 | App（v4.1.4） | 差距 |
|---|---|---|---|

## 5. 与网页版行为一致性说明

### 5.1 一致性原则
- **文案**：状态文案、按钮文案（上线/暂停/停止/全部上线/全部停止/刷新/选择角色）、计数（工作区 N · 在线 N）逐字对齐（App 可在前缀图标/布局上适配）；
- **状态机**：状态优先级与转换与 §2.3/§2.4 一致；服务端为唯一事实源（App 不本地推导在线状态，避免双源不一致——沿用 P2 防回滚教训）；
- **动作语义**：上线=建立会话（登录中→在线）；暂停=保留会话但停止执行、按恢复策略自动恢复；停止=销毁会话不自动恢复；全部/账号级为批量原子操作但允许部分失败（逐角色结果+汇总提示）；
- **计数**：`onlineCount` 由服务端聚合返回，App 不自行计数；
- **并发约束**：同 fpid 单角色在线（服务端强制）；跨 fpid 并行；
- **刷新**：页面可见 5s 轮询；操作后立即刷新；批量操作显示 x/y 进度；
- **错误语义**：被顶号→「被顶号/待恢复」；token 失效→「需登录」；服务器不可达→保留上次状态+「连接中」提示，不误显示为离线。

### 5.2 已知平台差异（需在验收中明示，不算不一致）
| 项 | 网页版 | App 本期 | 处理 |
|---|---|---|---|
| 会话宿主 | 云服务器常驻进程 | vault-server 常驻（App 仅控制面） | 一致语义 |
| 启动分身 | 无此概念（云端会话） | 本地 VirtualApp 分身（token 续期/人工兜底） | App 扩展，非复刻项；不影响 1:1 账号页 |
| 防封保护/易盾 | 支持 | 未实现 | 灰显+说明（P1/二期） |
| 多用户/仅我的账号 | 多用户 admin | 单用户 | 不显示该开关 |
| 实时推送 | WS realtime | 轮询（本期） | 体验差异，标注后续可升级 |
| 账号池规模 | 数十~数百 | 设计目标 ≤ 设备/服务器容量，测试 2~3 账号 | 验收按 2~3 账号 + 压测说明 |

- **AC-09 刷新**：页面停留 15s，服务端状态变化（模拟）在 ≤5s 内反映到 UI；操作后 ≤2s 内刷新。
- **AC-10 多账号并行在线**：两个不同 fpid 账号各上线 1 角色 → 同时「在线」，服务端 2 条会话；App 计数=2；两账号任务并行执行不互相顶号。
- **AC-11 启动分身（真机，含版本升级）**：
  - 前提：容器内游戏版本过旧 → 点「启动分身」显示「游戏版本过旧，需更新分身游戏」，提供「立即更新」；

- **AC-12 启动/更新失败诊断**：连续两种失败场景文案不同且准确（如未克隆 vs 下载失败）；`lastLaunchError` 与失败阶段出现在弹窗/日志中；失败不导致容器数据丢失。
