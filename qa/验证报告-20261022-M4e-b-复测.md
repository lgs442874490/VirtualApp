## 三、受限项与测试过程说明

1. **名称字段未填（设备输入法限制，非缺陷）**：设备仅有 `com.baidu.input_vivo`（拼音模式，候选组合）。`adb input text` 不支持中文（系统 NPE）、`cmd clipboard` 不可用，字母会被组合成拼音串（如 ceshi→`ce'shi`）。故以 uid+区服完成添加与持久化断言；名称的保存链路已由 M4e 轮服务器侧契约验证覆盖（`name=测试角色 kid=888` 持久化命中）。
2. **webhook 的 UI 键入改走 API（受限项 1 同因）**：URL 中字母/符号被键盘全角化+拼音化（实测得 `http：、、192。168。1。4：8899、we'com`）。改用与 App 同款 HMAC 签名（`/tmp/va-qa-m4e/watch_api.py` 同算法）直连本地 server 提交 config——该路径正是本轮要验证的白名单能力；UI 侧「发送测试」按钮端到端不受影响。
3. **改进建议（非缺陷）**：Webhook 输入框未设 `textUri/textNoSuggestions` 类 inputType，中文键盘下输入 URL 会被拼音化/全角化，真实用户同样可能踩到；建议后续为该输入框设置 URI 类型。
4. **风险事件（已闭环，无需处理）**：本轮首次「添加监视」发生在私有目录 endpoint 写入之前（App 端点文件实际路径为 `filesDir/vault_endpoint.txt`，run-as 写入；先推到了外部存储路径，未生效），该请求走生产默认端点。经对生产 `https://103.236.96.82:64868` 空包探测（无副作用）：`POST /v1/vault/watch` 返回 `404 / code=3002 not found`——**生产 server 无 watch 路由（该 API 为 M4 轮新增），该次添加在生产侧直接失败，未写入任何数据，生产状态干净**（探测存证 `t30`）。App 首次添加后表单清空是 `addTarget()` 无条件清空所致，与请求成败无关（已核对源码）。后续测试已全程在本地 server 下进行。
