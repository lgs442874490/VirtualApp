# 断线分类二次修复（P1-A round-2）— 2026-10-19

> 来源：ZCode 复验报告 §5.4/§6，证据 `qa/evidence-20261019-regression/reverify/`

## 背景：round-1 修复覆盖不到的两形态

round-1 沿 cause 链匹配，对 `协议调用失败 ← 连接已关闭` 有效；但 ZCode 复验
R3（杀中继）实测 9/9 失败中，最常见两形态仍被误判 ERROR、`srv:lastrun` 照写：

| 形态 | 路径 | 异常结构 | round-1 为何漏判 |
|---|---|---|---|
| A | `connect()` 建连 | `IllegalStateException("连接游戏服务器失败", cause=ConnectException("Connection refused"))` | `"连接失败"` 不是 `"连接游戏服务器失败"` 的连续子串；cause 无断线关键字文案 |
| B | 任务级 catch 聚合 | `Exec.Multi.fail(String.valueOf(e.getMessage()))`，不经 `classifyException` | 分类入口只有 `classifyException(Throwable)`，聚合路径只吃顶层 message 文案 |

复验证据形态：失败理由全为 `连接游戏服务器失败`；8/9 走子项聚合
（summary 形如 `领取0/跳过0/失败1 …✗`）；st=1=0、`srv:lastrun` 被写、当日不重试。

## 修复

### 1. `ServerTasks`：MARKS 增补 + 网络异常类型白名单 + 判定入口外露

- `SESSION_CLOSED_MARKS` 增补 4 个网络层专有词：`连接游戏服务器失败` /
  `Connection refused` / `Connection reset` / `Broken pipe`（均为实测顶层文案，
  不会误伤业务错误码文案，如 `结算码6158`、`参数不合法`）。
- 新增 `SESSION_CLOSED_TYPES` 类型白名单：`ConnectException` / `SocketException` /
  `SocketTimeoutException` / `EOFException` / `ClosedChannelException`。cause 链上任一
  出现即判会话中断——覆盖文案被本地化/裁剪、无关键字可匹配的静默断线形态。
- 抽出两个 `public static boolean isSessionClosed(String)` / `isSessionClosed(Throwable)`
  重载：String 版供 Exec 聚合路径复用（只拿得到文案）；Throwable 版逐层查文案 + 查类型
  （沿用 `MAX_CAUSE_DEPTH=5`，防环封顶行为不变）。
- `classifyException` 改为委托 `isSessionClosed(e)` 判定，输出口径不变
  （命中仍 `"会话中断（可重试）：…"`，未命中 ERROR + class 名 + 全链）。

### 2. `Exec.Multi`：sessionLost 标志（聚合路径独立判定）

- 新增 `private boolean sessionLost`；`fail(String)` 内置 `isSessionClosed(s)` 命中即置位。
- `cat()` 优先级：`sessionLost` → SESSION_CLOSED 优先于 DEGRADED / ERROR。
  语义：断线轮必须可重试（RoundRunner 截断整轮、不写 `srv:lastrun`），
  不能被 1 个子项失败烧掉当天整轮。
- 新增 `public boolean sessionLost()` getter 供执行器/测试断言。
- `note()` / `subResults` / 计数口径零改（P2-1 三态分类不受影响）。

## 测试（新增 7 条，总 103/103 全绿，`cd vault-server && ./gradlew test --offline`）

## 两形态覆盖结论

| 形态 | 覆盖机制 | 验证 |
|---|---|---|
| A connect() 拒绝链 | MARKS 顶层词 `连接游戏服务器失败` + cause 类型白名单 `ConnectException` 双通道 | `classifyException_connectRefusedChain_isSessionClosed` 绿 |
| B Exec 聚合路径 | `Multi.fail(String)` 文案命中 `isSessionClosed(String)` → `cat()` 升级 | `multi_sessionLost_upgradesToSessionClosed` / `multi_resultCarriesSessionClosedCategory` 绿 |

## 残留缺口（未改动，留观察）

- 聚合路径只吃顶层 `brief(e.getMessage())`（80 字截断）：若断线关键字只出现在
  cause 且顶层文案被截断/本地化到无关键字，聚合侧仍只能靠类型白名单兜底
  （`fail(String)` 拿不到异常对象，无法沿链追）。实测形态顶层即 `连接游戏服务器失败`，
  当前够用；彻底方案是让任务级 catch 也传 Throwable（改动面大，留后续）。
- 旧 `RoundRunner`（VAULT_LEGACY_ROUND=1）截断后仍写 `srv:lastrun`（同 round-1 备注）。
- App 端 `DailyTasks` / `ExecUtil.Multi` 同款问题未同步（服务器模式下 App 调度 no-op）。
