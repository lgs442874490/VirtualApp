## 3. 失败清单与发现

### 3.1 【P0 缺陷】D-1 同账号互斥「上线前确认弹窗」永远不触发
- **位置**：`HomeActivity.siblingOnlineName()`（`/tmp/va-integ-work/app/src/main/java/com/carlos/vault/HomeActivity.java` 约 3425–3443 行）
- **原因**：读 `ro.optBoolean("online")`（roles[] **顶层** online 字段），但 M1 契约 §2.1 与服务端实现的 online 在 `roles[].state.online` —— 顶层字段恒缺失 → `siblingOnlineName` 恒 null → `confirmRoleLogin` 直接发 role-action login，**「将下线 XX，是否继续」弹窗（AC-03 前置确认）永不出现**。
- **复现**：注入 pool_cache 小鹿 state.online=true + 隆科多 RUNNING → 点隆科多「上线」→ 无弹窗，logcat 直接出现 `/v1/vault/role-action` 请求（03:13:39）。
- **期望 vs 实际**：期望弹「同一账号同时只能有一个角色在线。上线『隆科多』将下线『小鹿矿工5号』，是否继续？」；实际直接发请求。
- **影响面**：服务端互斥本身正确（同步停旧会话 + stoppedRoles 返回 + 事后 toast 提示），但契约 §3.2/AC-03 的**前置确认 UX 缺失**；D-2（取消路径）无法验证。
- **修复建议**：改为 `ro.optJSONObject("state").optBoolean("online")`（或复用 `AccountPoolCache.stateOfRole(ro).online`）；补 JVM 单测（当前 App 256 测试未覆盖该函数——建议 fixture 直接用 /accounts 真实 shape）。
- **证据**：`G-D1前置-小鹿在线隆科多离线.png`、`D1-互斥确认弹窗.png`（无弹窗）、logcat 03:13:39 role-action 直发。

### 3.2 【P1 发现】「从本地 APK 更新」无存储权限引导
- `findLocalUpdateApk()` 扫 Download 需 READ_EXTERNAL_STORAGE，本机未授予（granted=false）→ `listFiles()` 空 → 永远「未找到本地更新包」，无权限申请/引导。P0 兜底路径在未授权设备不可用。建议：入口处检测并请求权限（targetSdk 26 运行时权限）。测试中经 `pm grant` 授权后链路正常（§2.7）。

### 3.3 【备注·非缺陷】计数口径
- 组头「工作区 N」= enabled 角色数、顶栏「工作区 N」= 有工作区角色的账号数（App 侧工作区口径，与 RoleSessionKeeper 一致）；server `/accounts` 的 `workspaceCount` = 全部角色条目数（本机 5）。UI 自洽但与 M1 §2.1 字段名同源不同义，M5 验收对照网页版时注意。
