## 1. 总体顺序与依赖

```
P1 口径统一（规则 + 文案）
   └─→ P2 名单统一（fid + 迁移）        ← 依赖 P1 的 AlertContext/AlertConfig
          └─→ P3 出口统一（去重 + 事件库 + 观察点入库）  ← 依赖 P2 的名单派生
                 └─→ P4 页面合并
                        └─→ P5 互兜底（本期只预留字段）
```

- P1 与 P2 可以并行准备（不同文件），但 P2 的 `AlertContext.watchedUids` 需要 P1 的接口先定稿，建议 P1 先行 1 天。
- P3 必须等 P2（否则观察点派生的名单不可用）。
- P4 必须等 P3（页面时间线要读统一事件）。

## 3. P2 名单统一（约 1 人日）

**目标**：用户只维护一份 fid 名单；观察点 `monitorTargets` 由名单派生；迁移三套旧数据（自动并入、默认启用、废弃本地）。

### 任务

| # | 任务 | 产出文件 | 验收 |
|---|---|---|---|
| 2.1 | 名单服务 | `alert/WatchlistService.java`、`WatchlistEntry.java`、`LegacyTarget.java` | `add(fid)` 只收 fid；fid→uid 走 `PlayerDirectory.byFid`；未命中 `UNRESOLVED`；`resolvePending` 幂等 |
| 2.2 | 迁移器 | `alert/WatchlistMigrator.java` | 三源合并：`watchTargets`（uid→fid 反查）、`monitorTargets`（uid>0 并入，纯坐标丢弃+报告）、App seed（`source=MIGRATED_LOCAL`，**enabled=true**）；重复执行条数不变 |
| 2.3 | 接口 | `VaultHttpApi`：`POST /v1/vault/alert`（list/add/update/remove/bulk）；旧 `/watch`、`/watchpoint` 保持原行为（统一切换留到 P3，降低旧 App 回归风险） | 新接口 CRUD 可用；旧接口零回归 |
| 2.4 | 派生接入 | `WatchPointEngine.isMonitoredUid` 读 `AlertConfig` 派生集合；`WatchPointStore` 的名单/矩形字段改为只读兼容视图 | 同一 uid 在名单中→观察点识别；移除后 1 个轮询周期内失效 |
| 2.5 | 启动迁移 | `Main` 启动时检测 `alert.watchlist` 缺失则跑一次迁移 | 首次启动日志有迁移报告；二次启动不重复 |

- 旧 App 不受影响。

### 新增测试

- `WatchlistTest`：fid CRUD、UNRESOLVED 重试、`enabled=false` 不匹配。

### 回滚

`alert.watchlist.v2=false` 时回读旧 `watchTargets`/`monitorTargets`；迁移只做加法，不删旧数据。

## 4. P3 出口统一（约 1 人日）

**目标**：所有告警先写 `WatchEventStore`；统一去重（跨账号全局）、聚合（30s，仅迁城+集结）、冷却、企微限速。

### 任务

| # | 任务 | 产出文件 | 验收 |
|---|---|---|---|
| 3.1 | 去重 | `alert/Deduper.java` | 键 `alert:{route}:{ownerUid}:{marchId}`；`ConcurrentHashMap.compute` 原子占位；跨 observer 只放行一次 |
| 3.2 | 聚合 | `alert/Aggregator.java` | `agg:{route}:{ex}:{ey}:{behavior}`，30s 窗口；**仅集结类（99/100/102/10/12）+ A4 迁城**；普通进攻即时发；聚合记录带 count/attackers[] |
| 3.3 | 出口 | `alert/AlertOutbox.java`；`WatchEventStore` 容量 200→500 + `alertKey` 幂等 | 事件先入库再企微；重复 append 跳过；静默只抑制企微 |
| 3.4 | 观察点入库 | `WatchPointEngine.alert()` 改走 Outbox；删除 `isMonitoredUid` 硬互斥 | 观察点告警出现在 `/v1/vault/events`、App 时间线、短信 |
| 3.5 | 限速 | `AlertOutbox` 内全局令牌桶 20 条/分钟 | 压测 30 条候选只发 20 条，其余仅入库 |
| 3.6 | 标题/字段 | 事件 schema 增 `route/trigger/alertKey/fid/aggregated/count/source` | 旧 App 忽略未知字段不崩 |

### 不变量

- 结算事件只入库、不推企微；
- 静默只抑制企微，事件照常入库；
- 事件既有字段（`fpid/sid/targetUid/action/behavior/endpoint/...`）不删不改语义。

### 新增测试

- `DeduperCrossAccountTest`、`AggregatorTest`（30s/仅集结+迁城/普通进攻不聚合）、`AlertOutboxTest`（幂等/静默/限速/企微失败不回滚）、`AlertEventSchemaTest`。

### 回滚

`alert.outbox.v2=false`：观察点回到只推企微（不写事件库），WarNotify 回到旧冷却键。

## 8. 风险与回滚

| 风险 | 阶段 | 缓解 | 回滚 |
|---|---|---|---|
| 等价抽取引入顺序漂移 | P1 | 拒绝码映射 + 对照测试锁死 | revert 单 commit / 关 `alert.rules.v2` |
| fid→uid 解析依赖目录 | P2 | UNRESOLVED 不阻塞、T1 仍可命中 | 关 `alert.watchlist.v2` |
| 旧接口兼容遗漏 | P2 | 旧接口读时合成 + 旧 App 冒烟 | 镜像开关 |
| 观察点事件挤占事件库 | P3 | 容量 500 + 60s sweep | 关 `alert.outbox.v2`（观察点回只推企微） |
| 聚合延迟被感知 | P3 | 只对集结+迁城，普通进攻即时 | 调 `aggregateWindowMs`=0 即关闭 |
| 页面合并影响旧入口 | P4 | 旧 Activity 保留深链 | 关 `alert.page.v2` |

**总回滚策略**：四个独立 feature flag，默认开、单开关回退；数据迁移只做加法（upsert + legacyRaw），不删旧数据。
