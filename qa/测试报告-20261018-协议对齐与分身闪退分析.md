# 协议对齐、功能失效根因与分身闪退分析（2026-10-18）

> 被测：`vault-server` 模块化执行层 + 真机 `com.carlos.multiapp 4.1.2 (23502)`
> 测试账号：`48460403`（888 服 / 隆科多 / 熔炉70 / 战力 207,239,112）
> 分支：`modify/automation-modules-20261018-1930`（未 commit / 未 merge）
> 结论：已定位“配置改了但服务器不生效”的 3 个确定性根因并修复；协议字段对齐后
> 联盟宝箱实领 98 个、排名奖励成功；模块化整轮 55 项 0 异常。分身闪退已拿到 ANR
> 现场，根因是 VA 的 IME/窗口焦点桥接，不是 Unity CPU 卡死；修复需改 VA 引擎 AAR。

---

## 1. 结论摘要

### 1.1 修改未生效 / 完整流程后功能全部无效

三个确定性根因（均已复现/修复）：

1. **日常页开关写入后没有触发同步**：`HomeActivity.setFnOn()` 只写本地
   `daily_config`，没有调用 `VaultSync.onAccountsChanged()`。服务器只能等下一次
   全量同步（App 启动/10 分钟防抖）才收到配置；在此之前整轮仍按旧配置执行。
2. **角色发现前的配置写到 sid=0，永远上传不上去**：新账号/重置后首次打开日常页时
   `currentRoleSid()` 可能为 0，开关写入 `acc:<fpid>:0`；`VaultSync.syncFields()` 只上传
   `roles[]` 里 `sid>0` 的配置，sid=0 的修改被静默丢弃。
3. **新能力只实现了服务层，没有接进执行器**：`FormationPlanner`、`ShopService`、
   `MedicService`、宠物指定技能、野外编队此前没有真正替换旧执行逻辑；模块化 runner
   仍委托旧 `ServerTasks`，所以“代码里有、游戏里没效果”。

另有 2 个环境/协议原因：

4. **生产服务器未部署新接口**：`/v1/vault/automation` 只在本地 jar 中；若 App 使用默认
   生产端点，登录/触发会 404。当前真机通过 `files/vault_endpoint.txt` 指向本地服务端。
5. **协议参数漏传**：联盟宝箱 `req_alliance_receive_chest` 旧代码传 `null`，协议要求
   `id/type`，实测服务端恒返回 `code=2`；联盟科技捐献/排名奖励同样漏参。

### 1.2 分身输入框闪退

- **触发条件**：在游戏分身内点任意文本输入框（登录手机号、聊天、改名等）→ 系统 IME
  弹出 → 游戏窗口失焦。
- **系统判定**：`Input dispatching timed out (... DDUnityLaunchActivity ... Waited 5000ms
  for FocusEvent(hasFocus=false))`，随后 ANR 杀死 `com.carlos.multiapp:p0`。
- **根因**：VA 在 Android 14 上的 IME/窗口焦点桥接不完整；游戏主线程实际空闲在
  `nativePollOnce`，不是 Unity CPU 卡死。重点嫌疑是
  `InputMethodManagerStub` 把 `EditorInfo.packageName` 强制改成宿主包，以及插件
  Activity 的 `softInputMode`/焦点事件没有正确转发。
- **修复方案**：见 §5.4，需要重建 VA AAR 并真机复验；短期可切 Gboard/AOSP 输入法规避。

## 3. “配置改了但服务器不生效”的根因与修复

### 3.1 根因 A：日常页开关没有触发同步

代码位置：`HomeActivity.setFnOn()`（原实现只 `saveRoleConfig`）。

复现证据：

- 修复前服务端 `vault.json`：`roleConfig: {}`、`roleParams: {}`；
- App 日常页实际已启用多项功能；
- 服务器整轮仍按默认值执行（gather/shop/intel 等默认 false）。

修复：

```java
cs.saveRoleConfig(taskAccount.fpid, sid, cfg);
VaultSync.onAccountsChanged(this);   // 新增：3 秒去抖后全量上传
```

同时补齐：角色移入/移出工作区、时间窗修改也调用 `onAccountsChanged`。

### 3.2 根因 B：sid=0 配置被丢弃

代码位置：`HomeActivity.fnOn/setFnOn`、`VaultSync.syncFields`。

- 新账号/重置后首次打开日常页时 `currentRoleSid()` 可能为 0；
- 配置写入 `acc:<fpid>:0`；
- `syncFields()` 只遍历 `RoleStore.roles()` 中 `serverid>0` 的角色，sid=0 的配置不会上传。

修复：

1. `HomeActivity.configSid(a)`：currentRoleSid → activeSid → 已启用角色 → 首个角色；
2. `VaultSync.learnServerRole()` 在服务器登录学到真实 sid 后，调用
   `DailyConfigStore.migrateRole(fpid, 0, sid)` 与
   `FnParams.migrateRole(fpid, 0, sid)`，把 sid=0 的开关/参数迁移到 888；
3. 日常页/补给卡读取也改用 `configSid()`，避免读到 sid=0 空状态。

### 3.3 根因 C：服务层未接线

本次补齐：

- `ServerFieldTasks.gather/hunt` 使用 `formationFor()`，读取 `hero_ids/troop_count/
  target_amount/ratios/resources_named`；
- `ServerShopLeagueTasks.buyFromShops` 增加 `req_shop_refresh` 循环（配置门控）；
- `ServerTownTasks.pet` 支持 `selected_skills`；
- `ServerTownTasks.medic` 委托 `MedicService`；
- `ServerTasks.activityRewards` 增加英雄故事 `req_hero_story_claim_reward`；
- 联盟宝箱/科技捐献/排名奖励按协议补参；
- `ModularRoundRunner` 默认接管整轮，保留 `VAULT_LEGACY_ROUND=1` 回退。

### 3.4 真机闭环验证（关键）

1. App 日常页把“野外采集”开关从关→开；
2. 6 秒内服务端 `vault.json`：
   `roleConfig.888 = {"barracks":true,"arena":true,"intel":true,"adventure_sweep":true,"gather":true}`；
3. 高级参数入口已上线（功能详情页“高级参数（JSON）”）。本轮因设备 Baidu IME
   会干扰自动化输入，改用**等价的本地 `daily_params` 注入**验证上传链路，写入：
   ```json
   {"resources_named":["MEAT","WOOD","COAL","IRON"],"hero_ids":[50001,50002,50003],
    "target_amount":100000,"troop_count":50000,"max_queues":4}
   ```
   服务端 `roleParams.888.gather` 收到完整 JSON；说明“参数存储 → 同步 → 服务端”链路已通，
   UI 输入本身需人工用正常键盘复验。
4. 模块化整轮（20:07）：
   `成功55(领取7 跳过48) 异常0`；
   - 联盟宝箱：**领取×98**；
   - 联盟排名奖励：✓；
   - 兵营训练：收盾/矛/弓 + 训练盾T10×200；
   - 每日任务：SKIPPED（已全部领取）；
   - 战斗护盾：码51 归 SKIPPED；
   - 采集：配置已生效，但账号附近无资源点（“附近未搜到资源点”）。

## 5. 分身输入框闪退分析

### 5.1 ANR 现场

- 时间：`2026-10-18 19:24:58`
- 进程：`com.carlos.multiapp:p0`（PID 15330，Cmd line 被 VA 改为 `com.gof.china`）
- ANR 主题：
  ```text
  Input dispatching timed out
  (com.gof.china/com.unity3d.player.DDUnityLaunchActivity (server) is not responding.
   Waited 5000ms for FocusEvent(hasFocus=false))
  ```
- 前 11 秒系统日志：
  ```text
  InputMethodManagerService:
  startInputOrWindowGainedFocusInternalLocked: reason=WINDOW_FOCUS_GAIN
  editorInfo=android.view.inputmethod.EditorInfo@...
  softInputMode=STATE_UNSPECIFIED|ADJUST_PAN
  windowFlags=#810580
  ```
  以及 `com.baidu.input_vivo` 的 IME 窗口显示、
  `RemoteInputConnectionImpl: getTextBeforeCursor on inactive InputConnection`。
- p0 主线程栈：`nativePollOnce → MessageQueue.next → Looper.loop`，主线程**空闲**。

### 5.2 触发条件

1. 在分身游戏内点击文本输入框（登录手机号/聊天/改名/兑换码等）；
2. 系统 IME（Baidu）弹出，游戏窗口失焦；
3. InputDispatcher 向 `DDUnityLaunchActivity` 发送 `FocusEvent(hasFocus=false)`；
4. 5 秒内未收到窗口响应 → ANR → 系统杀死 `:p0` 游戏进程。

### 5.3 根本原因

**不是 Unity 主线程 CPU 卡死**（主线程空闲），而是 **VA 的 IME/窗口焦点桥接在
Android 14 上不完整**：

- 插件 Activity 的窗口由 VA 宿主进程承载；IME 弹窗导致的焦点转移没有正确回传到
  插件窗口，InputDispatcher 等待超时。
- 重点嫌疑 1：`lib/.../hook/proxies/input/MethodProxies.java` 的
  `StartInputOrWindowGainedFocus` 把 `EditorInfo.packageName` 强制改为宿主包
  （`getHostPkg()`），而窗口/Activity 属于插件包 `com.gof.china`，IME 与窗口的
  目标包不一致。
- 重点嫌疑 2：`HCallbackStub.handleLaunchActivity()` 原样使用插件 `ActivityInfo`，
  `softInputMode=ADJUST_PAN`；VA 的 stub 窗口在 IME 出现时没有正确转发
  `onWindowFocusChanged`/焦点事件。
- 现象与已知 VA + Android 13/14 IME 焦点 ANR 一致；Baidu IME 只是触发者，不是根因。

### 5.4 修复方案

按优先级：

1. **VA 引擎补丁（推荐，需重建 AAR）**
   - 在 `HCallbackStub.handleLaunchActivity()` 中，对 Unity/游戏 Activity 强制：
     ```java
     info.softInputMode = (info.softInputMode
             & ~WindowManager.LayoutParams.SOFT_INPUT_MASK_ADJUST)
             | WindowManager.LayoutParams.SOFT_INPUT_ADJUST_RESIZE;
     ```
     让窗口在 IME 出现时走 resize 而不是纯焦点转移；先只对
     `info.name.contains("Unity")` 或 `info.packageName.equals("com.gof.china")` 生效。
   - 在 `InputMethodManagerStub.StartInputOrWindowGainedFocus` 中，把
     `attribute.packageName` 改为 `VClient.get().getCurrentPackage()`（插件包），
     或至少加开关做 A/B；不要无条件强制宿主包。
   - 重新构建 `lib-release.aar`，按发版门禁校验 `libvbox.so` 哈希后安装。
2. **焦点转发兜底**：在 `ShadowActivity`/插件的窗口回调中确认
   `onWindowFocusChanged(false/true)` 被转发；可在 VA 客户端日志中打印
   `window focus` 事件，验证 ANR 是否消失。
3. **App 侧可观测性**：CrashGuard 目前只捕获未捕获异常，不捕获 ANR。建议增加：
   - 启动时读取 `dumpsys activity exit-info`/`logcat` 的 `reason=6 (ANR)`；
   - 在“崩溃日志”页展示最近 ANR 类型与触发页面；
   - 记录最后进入的游戏输入框/IME 状态（脱敏）。
4. **短期规避**：把系统输入法切到 Gboard/AOSP 键盘再测试；若不再复现，可在 App
   内提示“游戏内输入建议使用系统键盘”。Baidu IME 是当前复现环境，不能作为唯一结论。
5. **长期**：升级到维护中的 VA 版本或迁移容器方案；Android 14 的 IME/窗口焦点改动
   较大，旧 VA 分支需要专项适配。

> 当前仓库中 `lib/` 与 `engine-upgrade/lib/` 有 VA 源码，但 App 实际使用
> `app/sdk/lib-release.aar`（补丁版）。上述补丁改完必须重建 AAR 才会生效；
> 本轮未改 AAR，避免在未复验的情况下替换引擎。
