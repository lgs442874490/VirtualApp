## 0. 范围

1. **Bug 修复**：脚本被顶号（engine=`takeover`）后点「上线」只 toast、不实际回连。
2. **配置扩展**（App 配置面 + 服务端执行面同一份 roleParams JSON）：
   - `battle_shield`（每日免费盾 + 反应式开盾）增加**总开关**与反应式触发策略：
     - `force_online`：自身有被攻击风险时允许强制上线并开盾（默认 false）；
     - `strategy.troops_min`：来袭敌方兵力下限阈值，低于不开盾（默认 `0`=不限）；
     - `strategy.eta_sec`：敌方行军到达剩余 ≤N 秒才开盾（默认 `0`=收到风险立即开）；
     - `gather_attack` / `gather_recall`：**采集点遭袭提醒（默认开）/ 自动撤矿（默认关）**。
       2026-10-24 用户实证「采集点被攻击与城堡被攻击一样有提示」，按网页版 `GATHERING_ATTACK`
       同源逻辑补实现（`type=4/110` + `target.type=2/map_resource.uid` 或 endpoint 匹配在采行军）；
   - `guardian`（驻防盟友）把既有 `enabled` 明确为**总开关**，并增加：
     - `force_online`：盟友受攻击风险且满足阈值时允许强制上线并派兵驻防（默认 false）；
     - `strategy.troops_min`：敌方来袭兵力预警下限（默认 `0`=不限；兼容别名 `min_enemy_troops`）。
3. **明确离线通知与风险检测可行性**（独立文档 + 结论表）。

非目标：不新增游戏协议、不花钻石、不改默认行为（未配置新参数时行为与 master 一致）。

App 渲染：
- `battle_shield`：由 `FnDetail` 子项自动渲染（Switch + 策略 chips；`troops_min` 0/1万/5万/10万/50万，`eta_sec` 0/30/60/120/300）；`FunctionActivity.supportsAdvancedConfig` 增加 `battle_shield` 供自定义数值。

- 全部参数**可独立启用**：总开关关闭时新参数不生效；`force_online` 单独开关；阈值/ETA 单独配置。

## 2. 语义定义

### 2.1 兵力（troops）
`march.squad_list.soldier` 求和（map `{id:count}` / `{id:{count}}` / list `{id,count}`，与 `WarNotify.troopsOf` 同口径）；观察哨形状 `{"marches":{"slot":{"march":{...},"power":n}}}` 只有 power、无 squad 时视为**兵力未知**。

### 2.2 反应式开盾触发链
```
situation 推送（type=1 侦查 / 2 进攻；target_type=1；守方 uid=本人）
  → 记录 kind / endtime(服务器秒) / troops / 到达时刻
  → tick（仅 online）：
      总开关 enabled ∧ reactive ∧ 账号自动化 auto|keep
      → 阈值：troops_min>0 ∧ 兵力已知 ∧ troops<min → SKIP（留痕）
      → ETA：eta_sec>0 ∧ 剩余>eta_sec → 挂起（保持 pending，不用 10min 保鲜窗判死）
      → 剩余≤eta_sec 或 eta_sec=0 → freeShield（既有幂等/冷却不变）
      → 非 online 且 force_online ∧ 有新鲜挂起风险 → 强制回连（SessionKeeper）
```

### 2.3 守护盟友触发链（既有 P0 上扩展）
```
联盟 situation 推送（type=2 进攻；目标为盟友/白名单）
  → Threat 增加 troops/power（squad_list.soldier）
  → decide：既有 ETA/盟友过滤 + troops_min（已知且低于→REJECT；未知→REJECT“兵力未知”）
  → 命中 → dry_run 记录 / 实发 type=5 驻防
  → 非 online 且 force_online ∧ 有命中威胁 → 强制回连（SessionKeeper）
```

### 2.4 强制上线（force_online）
- 只对「本进程已收到并仍新鲜的风险」生效（推送 → 之后被顶号/暂停/掉线）。
- `SessionKeeper.LiveSession.tick` 非 online 分支：
  - `PAUSED`：直接恢复 RUNNING（清 pause 计划）→ 下一拍登录；
  - `TAKEOVER`：`engine.beginRecoveryNow("风险强制上线")`，抢回连接（会顶掉其他设备；App 已有顶号策略提示）；
  - `RECOVERING`：`beginRecoveryNow` 立即重连（跳过退避）；
  - `NEED_TOKEN`：不强制（token 失效只能人工补）；
  - 强制动作 60s 节流，避免登录风暴与互踢环。
- **能力边界**：完全离线（无会话/游戏客户端未运行）没有任何游戏推送通道，`force_online` 不能凭空空想；需要外部触发源（见可行性文档）。

## 3. Bug 根因与修复（顶号后「上线」无效）

`SessionKeeper.loginRoleLocked` 对已存在会话（被顶号后 LiveSession 仍在 map 中、runState=RUNNING）
直接返回 `ok(RUNNING)`，不改变 engine 的 `takeover` 状态 → App toast「上线成功」，实际不回连。
修复：已存在会话且 engine 非 online 时按状态处理——`takeover/recovering` → `beginRecoveryNow` 强制回连；
`need_token` → 返回 1404 中文原因；`offline` → 交给 tick 立即登录。响应 message 回传 App。

| 项 | 最终口径 | 说明 |
|---|---|---|
| 顶号后「上线」 | `SessionKeeper.loginRoleLocked` 对已存在会话按引擎状态推进：`takeover/recovering` → `beginRecoveryNow` 强制回连；`need_token` → 1404 中文原因；`offline` → 下一拍 `startLogin`；`online` 幂等 | 修复旧逻辑「已存在会话直接 ok」导致 App toast 成功但实际不回连；新增 `SessionKeeperTakeoverLoginTest` 8 例 |
| battle_shield 总开关 | `sub.enabled` 默认 **true**；关闭后 `ServerTasks.freeShield`（定时）与 `ServerShieldResponder`（反应式）都零请求 | App `DailyTasks.freeShield` 同步门控（本地旧模式一致） |
| battle_shield 兵力阈值 | `strategy.troops_min` 默认 0；兵力已知且低于阈值 → 跳过留痕；**兵力未知 → 保护优先照常触发并留痕** | 与守护侧「未知保守」相反：开盾是防御动作，漏防代价更高 |
| battle_shield 卡秒 | `strategy.eta_sec` 默认 0；>0 时剩余 >N 秒挂起等待（不受 10min 保鲜窗判死），剩余 ≤N 秒开盾；到达超过保鲜窗丢弃 | 服务器时钟未校准时退化为本机秒（偏差≈时钟偏差） |
| battle_shield 强制上线 | `sub.force_online` 默认 false；`forceOnlineWanted()` 仅查询，由 `SessionKeeper` 在 paused/takeover/recovering 分支执行 | 只对「本进程在线时已收到的仍新鲜风险」生效；完全离线无输入 |
| 采集点遭袭识别 | `sub.gather_attack` 默认开、`sub.gather_recall` 默认关；来袭 `type=4/110`、`target.type=2` 且 `map_resource.uid=本人`，或 endpoint 命中自己 `type=4/state=3` 采集行军；写 `mod:battle_shield.gather`；撤矿 `req_world_march_off_work {id}` 同队伍 10min 冷却 | 2026-10-24 用户实证后更正早期「无推送识别」判断；网页版同源 |
| 集结攻城 | `type=100` 并入 WAR 护盾触发（原只认 type=2） | 网页版 RALLY_CITY_ATTACK 同口径 |
| guardian 总开关 | 既有 `enabled` 即总开关（App 配置卡「总开关」），默认 false；关闭零请求/零状态。**显式 `enabled` 为权威值**；仅旧数据缺少 `enabled` 键时才回退用旧 `intercept` 兼容启用 | 防止「总开关关 + 旧 intercept=true」把模块重新打开；与 `dry_run` 独立：`enabled` 管是否处理敌情，`dry_run` 管是否实发 |
| guardian 兵力阈值 | `troops_min` 默认 0（兼容别名 `min_enemy_troops`）；未知兵力且阈值>0 → **保守不发射** | 守护是进攻性派兵，情报不足不送兵 |
| guardian 强制上线 | `force_online` 默认 false，且**仅 `enabled ∧ force_online ∧ !dry_run`** 时生效 | 演练模式只记录不派兵，不为虚动作抢登/顶设备 |
| 强制上线节流 | 同会话 60s（`SessionKeeper.FORCE_LOGIN_THROTTLE_MS`）+ **每在线周期最多 3 次**（`MAX_FORCE_LOGIN_ATTEMPTS`）；连续抢回仍被顶回则回退「让位/探测」路径，避免与对方设备每 60s 互踢 | 手动「上线」不受节流限制；重新在线后预算清零 |
| 暂停语义 | `force_online` **会覆盖用户显式暂停**（含关闭自动恢复的暂停）——这是用户开启该开关时接受的例外；风险处理后角色保持在线，不自动回到暂停 | 未开启 `force_online` 时暂停行为完全不变（人玩优先） |
| App 配置面 | `battle_shield` 由 FnDetail 子项自动渲染 + 高级 JSON 自定义数值；`guardian` 配置卡新增「风险时强制上线 / 来袭兵力预警阈值」 | 全部参数可独立启用 |

### 6.2 明确能力边界（对用户口径）

- **离线通知**：详见 `design/离线通知与风险检测可行性-20261024.md`。结论：服务端常驻会话在线时，手机离线也能收「自己城 / 采集点 / 盟友」推送；会话 paused/takeover/recovering/need_token 期间收不到新推送；完全离线无通道。**采集点遭袭已补识别（2026-10-24 用户实证后更正首版结论）**。
- **force_online 不等于离线推送**：它只处理断线前已收到且仍新鲜的风险，进程重启即丢；不能承诺「完全离线实时开盾/驻防」。
