三、每项改动解决了什么 Change notes

1旧 token 全量重定向

解决：两套色彩体系并存（v1 9 支旧色 vs v2 token）——规范要求"全项目一套 token"。旧名（BLUE/TEAL/RED/TEXT_PRI…）改为 v2 语义别名并标注 @Deprecated，4 个旧页面 136 处引用零改动对齐。

UiStyle.java · v1 兼容别名段（IDLE_BG 之后）

2RED 对比度修正

解决：旧红 D32F2F 对白底仅 4.2:1（AA 要求正文 4.5:1）。经别名映射到 ERR_INK B91C1C（6.5:1），所有"失败"文字一次性达标。

UiStyle.RED → ERR_INK

3裸色值收编进 token 表

解决：30+ 处 0xFF… 硬编码（INK3、SURFACE_2/3、BRAND_100/200、LINE_STRONG、SWITCH_OFF、WARN_SOLID…）散落在 HomeActivity，改色时要全文检索。现全部走常量，token 表成为唯一色源。

HomeActivity.java（9+2+2+2+7+2+1+2+1+2+2+2 处）+ UiStyle 新增 7 常量

4分段控件底色统一

解决：segmented 容器底用了表外色 0xFFE9EEF9，与 surface-3(#EEF2F9) 相近不同值——同层级面应同色。统一为 SURFACE_3。

UiStyle.segmented()

5徽章全圆化

解决：徽章规范是 22dp 高全圆胶囊，实现里是 11dp 圆角矩形，视觉上"方 pills"。改为全圆（roundRect 999）。

UiStyle.badge()

6轻提示替换系统 Toast

解决：系统 Toast 样式随厂商 ROM 漂移、位置压住底部导航，与规范的"深底胶囊、底部浮出、1.5s 自消失"不符。改为自绘 INK 深底胶囊：200ms 淡入、1.6s 淡出，悬于导航上方 92dp。

HomeActivity.toast()

7 SWITCH_OFF / LINE_STRONG 语义化

解决：开关关闭态底色与输入框强描边各有一个游离灰值，无法从名字推断用途。命名收编后，暗色主题只需替换这两个常量即可整体换肤。

UiStyle.Switch.onDraw() / LINE_STRONG 声明

8页面边距核验（维持）

结论：四页根容器左右均 18dp，符合 screen-x 规范；页内 12–16dp 属卡片内边距（card-pad 12–16 合规档位），不是违例，不动。

buildTodayPage / buildAccountPage / buildTaskPage / buildMinePage

9图标矢量化 + Switch 热区（补完）

解决：原先判"暂缓"的两项实际都能低成本做掉——① 新增 UiStyle.Icon（Path 手绘 GEAR/CLOSE/CHEVRON），齿轮按钮与弹层关闭键已替换，不再依赖机型字体；② Switch 测量尺寸改 46×44、轨道画中段 28dp，透明垫肩扩热区，零调用点改动。

UiStyle.Icon / UiStyle.Switch + HomeActivity 齿轮与关闭键

10全包裸色值清零（补完）

解决：首轮只清了 HomeActivity；复扫发现 FunctionActivity 35 处（活跃度四态色）、AccountVaultActivity、SubCardUi、LicenseUi 共 40+ 处残留，全部收编。终扫（排除 token 定义本体与位掩码）= 0 处。

五文件 · 新增 token：BRAND_300/WAIT_50/WECHAT_GREEN/ERR_BORDER/INVERSE
