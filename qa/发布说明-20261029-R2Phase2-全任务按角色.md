# 发布说明 2026-10-29 · R2 Phase 2：全任务按角色独立 + 每角色独立配置

- 分支：`modify/per-role-phase2-20261029-0251`（基于 master 9d07208，含 P0 + Phase1）
- 范围：vault-server（灰度开关 `VAULT_PER_ROLE=on`）+ App（每角色独立配置，需发 APK）
- 用户决策：角色独立配置=做；派单预算保持 20/分（加每角色保底公平）；手动进游戏只让位当前角色；现在开工。

## 一、服务端 Phase 2A：调度/状态/采集按角色

1. **调度单元** `fpid → RoleKey(fpid,sid,uid)`（新增 `task/RoleKey`、`task/StateKeys` 统一键入口）。
2. **节奏调度**（TaskCadenceScheduler）：on 模式逐角色候选/派单；键 `srv:cad/st/cadlast` 加 uid；
   读 miss 回退旧键；active 角色镜像旧键。预算保持全局 20/分，新增每角色保底
   `floor=max(4, 20/在线角色数)` 加权公平 + 账号级上限 `VAULT_CADENCE_ACCOUNT_MAX`（默认 24/分）。
3. **整轮/补给/手动**（RoundScheduler/RoundRunner/ModularRoundRunner）：每角色各自 `srv:lastrun/supplyfire/summary/log/st` 角色键；active 镜像旧键；`requestRun(RoleKey)` 新增。
4. **采集**（CaptureTasks）：新签名 `captureAll(engine,store,fpid,sid,uid,activeWriter)`；`todo/res/rallies/quest*/mod:*` 角色键；active 镜像旧键；采集周期按 uid 错峰 0-59s；旧签名行为不变。
5. **推送唤醒**（TaskWakeRouter）：`onNotify(fpid,sid,uid,proto)` 写角色 cad 键，节流键含 uid。
6. **SessionKeeper**：`VAULT_PER_ROLE=on` 时所有在线角色各自跑整轮/节奏/采集/互助；
   off（默认）保持现网 active-only 行为。开盾/守护盟友 Phase 2A 仍只主控角色（2B 拆键）。
7. **App 显示兼容**：`/state` 把 active 角色（App 当前选中）的角色键**投影成旧键**下发，
   非 active 角色任务状态不下发；App 无需改动即可显示当前角色数据（切角色自动切换）。
8. **观测**：HealthMonitor/DailyDigest 键解析兼容 `family:fpid:sid:uid:fn`（含 `pet:alliance_chest` 这类带冒号 fn）。
9. **手动让位**：维持只让位 App 当前选中角色（用户决策），不影响兄弟角色自动化。

## 二、Phase 2C：每角色独立配置

- 服务端：`roleConfigByUid/roleParamsByUid`（键 `sid:uid`）落盘；sync 时 `uid>0` 写角色表，
  旧 App 写 sid 默认表；读取优先级 uid→sid 默认→任务目录默认；旧表保留为区服默认（回滚安全）。
- App：`FnParams` 键 `p:<fpid>:<sid>:<uid>:<fn>`、`mod:<fpid>:<sid>:<uid>:<fn>`；
  `DailyConfigStore` 键 `acc:<fpid>:<sid>:<uid>`；`VaultSync` 每角色按各自 uid 上传 config/params。
  旧键读回退 + 惰性 copy 迁移，切换角色后开关/参数各自正确。
- **需发 APK**：`FnParams.java`、`DailyConfigStore.java`、`VaultSync.java`（UI 文件无需改）。
