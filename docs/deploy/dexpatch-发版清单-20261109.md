## 6. 首个真实补丁（v4.2.64 发布并装到用户设备之后）

> 前提：v4.2.64 已是**已发布基线**，补丁必须基于它生成。

```bash
# 6.1 用生产基线 APK 作为 old（从服务器下载，勿用本地构建产物）
curl -sS -o /tmp/base-v4.2.64.apk https://cs.888syd.xyz/v1/vault/app-latest.apk

# 6.2 改代码 → 构建新 APK
./gradlew :app:assembleRelease -x lint
cp app/build/outputs/apk/release/app-release.apk /tmp/new-v4.2.65.apk

# 6.3 生成补丁 + 元数据（secret 与服务端 LICENSE_SECRET 同值）
VAULT_SECRET='<取自 gz:/etc/vault-server.env>' \
  tools/dexpatch_prepare.sh /tmp/base-v4.2.64.apk /tmp/new-v4.2.65.apk "$VAULT_SECRET"

# 6.4 上传补丁 + 合并 hotconfig（在现有 JSON 里追加 patches 块，保留 apk 块）
scp .dexpatch/patch/code.dex gz:/opt/vault-server/data/patch/code.dex
#    把 .dexpatch/patch.json 的 patches 块手工合并进 data/hotconfig.json

# 6.5 验证端点
curl -sSI https://cs.888syd.xyz/v1/vault/patch/code.dex   # 200 + Content-Length
```

**客户端验证**（设备上）：启动 → 日志 `DexPatch: sync done version=...` → 杀进程重开 →
`DexPatch: patch applied version=...` → 功能变化生效。

## 7. 回滚

| 场景 | 操作 |
|---|---|
| 补丁有问题 | 删除 hotconfig 的 `patches` 块（下次同步即停） |
| 单机清理 | `adb shell am broadcast -a com.carlos.dexpatch.CLEAR -n com.carlos.multiapp/com.carlos.vault.patch.PatchDebugReceiver` |
| 整包有问题 | 用 v4.2.63 APK 覆盖安装（同包名同签名，数据保留） |
| 服务端 jar 有问题 | `sudo -n systemctl stop vault-server && cp backup/vault-server-all.jar.bak-dexpatch-20261109-2235 vault-server-all.jar && sudo -n systemctl start vault-server` |
