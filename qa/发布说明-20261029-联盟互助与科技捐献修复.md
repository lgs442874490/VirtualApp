# 发布说明 2026-10-29 · 联盟互助停摆 + 联盟科技免费次数不消费 修复

- 分支：`modify/alliance-p0-20261028-2350`（e8911f5 互助 / db7d1a6 科技）
- 生产：vault-server（App 服务器模式；本批仅服务端，无需重装 APK）

## 1. 联盟互助：1536 被误判为“今日额度用完”，整天停摆

- 现象：手动进游戏看到 11 个可帮请求，自动化不响应；状态写“今日次数已用完（1536），明天自动继续”。
- 真因（生产 monitor 实证）：`req_alliance_help_all` 367 次请求中 348 次返回 1536，19 次成功；
  1536 是**瞬时“当前没有可响应请求”**（网页版参考实现 `NO_AVAILABLE_HELP_CODE`），不是每日上限。
  旧实现把首个 1536 持久化 settled 一整天 → 2026-10-28 04:23（北京）后 18.5 小时 0 次求助。
  叠加：tick 每轮重放登录 init 快照，抹掉推送增量与已帮标记 → 30s 反复请求、日志假成功 95%。
- 修复：1536 改瞬时语义（标记已处理 + 5s 退避，不落盘/不跨天，自动清理历史 settled 键）；
  seed-once；成功只认响应 count；`help_id` 唯一键；5s 最小发送间隔；busy/退避保留唤醒。

## 2. 联盟科技：免费捐献次数 24/25 一直不花

- 现象：游戏内「联盟科技」免费捐献次数长期停在 24/25；后台每 10 分钟只捐 1 次。
- 真因：免费次数双路取小 `min(engine,persisted)` + 仅 `engine<=persisted` 才采纳服务端快照，
  持久化旧值 0 永久锁死服务端真值 24 → 每 600s 只投影 1 次。
- 修复：服务端快照权威 + 本地已消费（`recoverySig`/`spentSinceSnapshot`）；快照变化即整体采纳；
  成功只累加已消费，不再把 count 归一化成 0；旧持久化 JSON 兼容（下份快照自动补捐积压）。

## 3. 验证与回滚

- 单测：vault-server 全量 1249 tests / 0 failures（集成两个修复后）。
- 发版后验证：日志出现新的 1536 文案/互助成功且不再 settled；`state.json` 不再有
  `srv:alliance_help_settled:*`；`alliance_donate` 首轮应出现 `科技捐献✓×N`（N>1，把积压一次捐掉）。
- 回滚：恢复上一版 `vault-server-all.jar` 备份并 `systemctl restart vault-server`（数据文件向后兼容）。
- 已知后续（R2，另立项）：状态键按 `fpid:sid` 不含角色 uid，同服双角色只有 active 角色跑任务；
  「每角色独立自动化」需按 uid 拆状态键 + 调整 App 消费契约。
