# 发布说明 2026-10-29 · R2 Phase 1：双角色独立联盟互助/科技捐献

- 分支：`modify/alliance-perrole-phase1-20261029-0115`（ba8feef + 1812a76，基于含 P0 的 master 0926103）
- 生产：vault-server；App 无需重装（显示链路不变）

## 交付范围

同账号同服多角色并行在线时，「联盟互助」与「联盟科技捐献」两个模块按角色 uid 独立执行与隔离状态；
其它任务（采集/练兵/情报/活动/宝箱/整轮等）本轮仍只由主控角色执行（Phase 2 实现）。

## 行为变化

1. 所有在线角色会话各自挂互助响应器：每个角色响应本角色的盟友请求；
   状态写 `mod:<fpid>:<sid>:<uid>:alliance_help`；主控角色（activeUid）额外双写旧键
   `mod:<fpid>:<sid>:alliance_help`，App 今日页显示不变。
2. 非主控角色每 30s 独立跑科技捐献：`srv:alliance_science:<fpid>:<sid>:<uid>` 按角色隔离，
   首次自动从旧键迁移一次；消耗的是本角色的免费捐献次数（不再只涨不花/长期 24/25）。
3. 门控：账号 auto 开关、角色级 alliance_donate 开关、战时让位、登录后 20s init 保护；
   异常只记日志不打扰兄弟会话。
4. 旧路径（roleUid=0/主控整轮）：键与行为 100% 不变，App/API 契约不变。

## 验证

- 单测：vault-server 全量 1270 tests / 0 failures（新增互助 7 例、联盟角色隔离 11 例、会话门控 3 例）。
- 生产验证要点（需两个角色都 desiredOnline）：
  - `state.json` 出现两套 `mod:<fpid>:<sid>:<uid>:alliance_help` 与
    `srv:alliance_science:<fpid>:<sid>:<uid>`，互不覆盖；
  - 主控角色旧键继续更新（App 今日页正常）；
  - 两个角色的免费捐献次数都能被消耗（游戏内各自 24/25 → 归零）；
  - 日志无「兄弟角色科技捐献异常」。
- 回滚：恢复上一版 jar 备份并 `systemctl restart vault-server`（新增 per-uid 键为增量，不破坏旧键）。
