# 情报功能修复：每日三轮 / 队列语义 / 采集让位 / 出征编队（2026-10-31）

> 用户反馈：**功能性 bug——情报今天一天没打过**。
> 用户给出的游戏规则（本设计的唯一事实源）：
> 1. 每天 0 点、8 点、16 点各刷新一轮情报；每轮情报只存在 **15 小时**；**上一轮没处理完，下一轮不会刷新**。
> 2. 情报有三种类型，**除狩猎外不需要行军队列**。
> 3. 情报**剩余 30 分钟消失**时，召回**一个**采集队列去打情报（情报优先于采集，但**不要全部召回**）。
> 4. 提供情报编队设置（英雄、兵种）；默认 **最强盾 / 波根-矛 / 吉娜-弓**，没有波根/吉娜则补**最强矛/最强弓**。

## 0. 结论：现状根因（为什么“一天没打过”）

| # | 根因 | 证据/机制 | 修复归属 |
|---|---|---|---|
| R1 | **营救行军（type=301）被错误计入普通队列占用**，而营救按规则不占普通队列；默认 `queue_count=1` 时，只要有一队营救在途，`remainingNormalSlots=0`，**狩猎（真正“打”的类型）永远派不出去** | `ServerFieldTasks.intelQueueSnapshot()` 把 `type==301||302` 全部计为 active；`intelRemainingNormalSlots()` 用 `allowedSlots-active` | 服务端队列语义 |
| R2 | **情报默认编队是“游戏第 1 队”**（`Exec.formation(engine,1)`），不是可用的情报编队；第 1 队常是采集队/英雄在途 → 301/403/无兵，派队失败后进入 10 分钟去重窗，全天反复失败 | `formationFor()` 无参数 → `legacyFormationFor()` → `Exec.formation(engine,1)` | 服务端编队 + App 设置 |
| R3 | **队列被采集占满时不会为情报腾位**；情报剩余时间耗尽也只会 SKIP | 现网无情报侧 preempt（守护侧已有同型召回实现可复用） | 服务端采集让位 |
| R4 | **没有轮次概念**：不看 0/8/16 刷新与 15h 生存期，没有“清完本轮才能刷新”的紧迫性；无事件时也没有按刷新点唤醒 | `intel()` 只做 60s 节奏 + 派队后 15min 唤醒 | 服务端轮次调度 |

> 规则 1 的“上一轮没处理完，下一轮不刷新”意味着：**漏清一轮 = 直接损失下一轮**。所以本轮修复的目标不是“加一个开关”，而是让三类情报都能在生存期内真正派出，且狩猎缺队列时按时让位。

## 1. 服务端队列语义（修复 R1）

- 三种情报类型与派队方式：
  | type | 含义 | 派队方式 | 占普通行军队列 |
  |---|---|---|---|
  | 1 | 狩猎（怪物） | `req_world_march type=302` | **是** |
  | 2 | 营救 | `req_world_march type=301`（特殊队列） | **否** |
  | 3 | 英雄之旅 | `req_intelligence_start_battle/end_battle`（PVE） | **否** |
  | 11/100 | 活动/冒险巨兽（历史兼容） | `type=302` | 是（按狩猎类处理） |
- `IntelQueueSnapshot.activeIntelligenceMarches` 拆为：
  - `activeNormalIntelMarches`：**只统计 type=302**（狩猎类占普通队列）；
  - `activeSpecialIntelMarches`：type=301（营救，仅展示/诊断）。
- `remainingNormalSlots = clamp(allowedSlots - activeNormalIntelMarches, 0, worldIdle)`。
- 营救/英雄之旅仍不检查也不扣普通队列（保持 2026-10-28 已修语义）。

## 2. 轮次模型与唤醒（修复 R4）

- 轮次时刻：每天 **00:00 / 08:00 / 16:00**（GMT+8，与项目 `Beijing` 口径一致），每轮 **15h** 生存期。
- 事件轮次优先由权威字段 `expire_ts` 反推：`roundStart = expireTs - 15h`（避免服务器时区误差）。
- 无事件时：下一次唤醒 = 下一个刷新点 + 5s（最多 8h），避免空轮询；新事件仍由 `TaskWakeRouter`（`notify_intelligence_*`）即时唤醒。
- 有事件时：
  - 本轮仍有**可派**事件（status=1、未过期、未被去重窗阻塞）→ 不设置 15min 睡眠，交给节奏/推送尽快处理；
  - 全部派出 → 保留 15min 兜底（战斗结果推送会提前唤醒）；
  - 被队列/体力阻塞 → 60s 级重试（由节奏调度兜底），**情报剩余 ≤30min 时触发采集让位**。
- 状态文案（`mod:intel`）追加轮次与剩余时间，例如
  `处理情报×2（派队2）· 本轮 16:00 批次 · 剩 4h12m`。

## 3. 采集让位（修复 R3）

触发条件（全部满足）：
1. 存在**可派的狩猎类事件**（type 1/11/100，status=1，未过期，未在去重窗）；
2. 该事件 `expireTs - now ≤ 30min`（`INTEL_PREEMPT_WINDOW_SEC=1800`）；
3. 普通队列确实满：`queueIdleKnown && worldIdle==0 && activeNormalIntelMarches < allowedSlots`（若是情报自己占了队列，召回采集没用）。

动作（**只召回 1 队，绝不全部召回**）：
- 候选：资产库 `queue().marches` 中 `type=4`（采集）、`owner=自己`、`state=2/3` 的**在途/驻扎**行军；
- **至少存在 2 队采集行军才允许召回**（只有 1 队时召回=全部召回，违反用户口径 → 不召回，只 SKIP 说明）；
- 选择：剩余采集时间最短（`endTime` 最早）的一队，等长取 marchId 小者；优先 state=2 在途；
- 协议：`state=2` → `req_world_march_recall{id}`；`state=3` → `req_world_march_off_work{id}`；
- 冷却：同角色 **300s**，且 10 分钟内最多 **2** 队（状态键 `srv:intel:preempt:<fpid>:<sid>:<uid>`）；
- 成功：写 `mod:intel` 文案“已召回 1 个采集队列为情报腾位（不会全部召回）”，并 `wakeAt(now+15s)` 尽快重派；
- 失败/无候选：只记录原因，不重试风暴；绝不触碰 type=5/99/102/411 等保护类。
- 开关：`intel_preempt_gather` 默认 **true**（用户规则要求生效）；`VAULT_INTEL_PREEMPT=off` 可整体回滚。

## 4. 情报出征编队（修复 R2，实现规则 4）

### 4.1 解析优先级（服务端）

1. **指定编队**：`intel` params 存在 `formation_mode=ROLE` + `formation_id(s)` → 沿用现有 `FormationResolver`（玩家显式选择优先，不改）。
2. **情报自定义**：params 含 `intel_hero_shield/lancer/marksman`（英雄 id，0=自动）或 `intel_ratio`：
   - 英雄：按职业校验；指定的英雄不可用（不在城/301 拉黑/在途占用）→ 同职业**最强可用**兜底；
   - 兵种比例：`intel_ratio{infantry,lancer,marksman}`，默认 **10:10:80**（与内置打野编队 WILD 一致）；
   - 总兵力：`intel_total`（0=按出征容量与库存自动，单队上限 50000）。
3. **默认自动**（未配置任何情报编队参数，也是本次修复的默认行为）：
   - 盾：**最强可用盾兵**（profession=1）；
   - 矛：**波根 50029**（profession=2）可用则用，否则**最强可用矛兵**；
   - 弓：**吉娜 50008**（profession=3）可用则用，否则**最强可用弓兵**；
   - 比例 10:10:80，总兵力按容量/库存自动。
- 英雄最多 3 名、职业唯一；任何职业无可用英雄则跳过该位（不硬凑）。
- 兵量：与 AUTO 自动编队同口径——按 `MarchCapacity` 夹取、库存夹取、406 缩放、最高兵种 id；无可用兵/英雄 → 返回 null + 可读 SKIP 原因（不静默回退游戏第 1 队）。

### 4.2 App 设置（情报功能页）

- 新增卡片「情报出征设置」（仅 `fn.id=intel`，位于通用「编队」卡下方）：
  - 三行英雄下拉：**盾 / 矛 / 弓**，选项=目录中对应职业英雄（名字+等级+战力），另有「自动（最强）」；
    - 未同步目录时整卡显示「英雄目录未同步，先登录/等待同步」，比例仍可编辑；
    - 默认全部「自动」，卡片说明默认规则（最强盾 / 波根 / 吉娜 + 缺失回退）。
  - 三行比例输入：盾 / 矛 / 弓（0-100 整数，默认 10/10/80），校验合计 >0；
  - 保存 / 恢复默认；保存写 `intel_hero_*`、`intel_ratio`，立即 `VaultSync.onAccountsChanged` 下发；
  - 若当前是「指定编队（ROLE）」，卡片顶部提示“当前使用指定编队，本页出征设置仅在自动编队时生效”，并提供「切回自动」。
- 通用「编队」卡保持不动（指定编队/内置编队入口仍可用）。

### 4.3 参数键（App ↔ 服务端契约）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `intel_hero_shield` | long | 0 | 盾兵英雄 id；0=最强可用 |
| `intel_hero_lancer` | long | 0 | 矛兵英雄 id；0=波根→最强矛 |
| `intel_hero_marksman` | long | 0 | 弓兵英雄 id；0=吉娜→最强弓 |
| `intel_ratio` | `{infantry,lancer,marksman}` | 10/10/80 | 兵种比例（相对权重） |
| `intel_total` | long | 0 | 总兵力；0=按容量/库存自动 |
| `intel_preempt_gather` | bool | true | 30min 紧急时召回 1 个采集队列 |
| `VAULT_INTEL_PREEMPT` | env | 未设 | `off/0/false` 关闭采集让位 |

- `IntelPreemptTest`（新）：仅 type=4、仅 state=2/3、至少 2 队才召回、选最早结束、冷却与每分钟上限、保护类不动。
- `IntelFormationPlanTest`（新）：默认最强盾+波根+吉娜；无波根/吉娜回退最强矛/弓；指定英雄不可用回退；比例默认 10/10/80；ROLE 优先。

## 6. 回滚

- 代码回滚：分支回退；无数据迁移。
- 行为开关：`VAULT_INTEL_PREEMPT=off`（只关采集让位）；`intel_preempt_gather=false`（按角色）；
- 编队：App「恢复默认」清空 `intel_hero_*`/`intel_ratio` 即回到默认自动；指定编队仍可覆盖。
