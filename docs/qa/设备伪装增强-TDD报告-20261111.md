## 9. 二次审查修复记录（2026-11-11 三次迭代）

> 二次审查结论：P0 已清除；P1-1（legacy/发现式登录设备固定化回归）需处置；P2-1′ 建议一并处理。

### 9.1 P1-1：发现式登录改用每 Session 临时设备

**问题**：`SessionKeeper.loginBoundRoleLegacy` 的 `engine.login(fpid, token, null)`、
`RoleLogin` 的 `sid<=0` 路径以及无 uid 的 `engine.login(fpid, sid)`，在未固化时走
`generate(fpid, 0, 0)` 账号级确定性设备；同账号多 Session 发现登录会撞设备互踢。
旧逻辑是随机，属本次改造引入的回归。

**修复**：

1. `WjdrEngine.buildLoginPayload` 分支：`roleUid>0` 走 `generate(fpid, sid, roleUid)` 确定性；
   `roleUid<=0` 走 `DeviceProfile.ephemeral()`——每引擎一台随机临时设备，同一引擎内重试稳定。
   **口径（E2）**：发现式登录不"主动"持久化；`identityJson()` 仍会返回本次会话使用的设备，
   由调用方决定是否固化。现有调用方均不会在发现阶段固化（vault-server legacy 首次默认登录后
   会再走 `loginByRole` 带 uid 重新认证并覆盖；App 发现路径用后即 close）。
2. `DeviceProfile.ephemeral()` 新增（复用 `randomDevice`）。
3. `login()` 的 uid 提取抽为包内纯函数 `roleUidFrom(extraParams)`，补接线层单测。

**回归用例**：

- `buildLoginPayload_discoveryLoginIsPerSession`：不同引擎发现登录设备不同、同引擎重试稳定
- `roleUidFrom_extractsRoleUid`：数字/字符串/缺失/非法 uid

### 9.2 P2-1′：类型错误/越界的系统版本回退机型池版本

`androidVersionOfJson` 在缺失、类型错误、数值越界时统一回退 `poolAndroidVersion(model)`
（如 `vivo X200 Pro` → 14），保持机型与系统版本自洽；池外机型才回退 13。

### 9.3 P2-4′：Server 空 seed 也注入（清 pinned）

`SessionKeeper.startLogin` 改为 `engine.applyIdentity(seed == null ? "" : seed)`，
空 seed 时清空引擎复用可能残留的固定指纹，避免串号。
