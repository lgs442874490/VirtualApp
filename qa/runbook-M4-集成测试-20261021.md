## 4. 用例执行顺序（详见测试计划）
1. 先跑 TC-A/A-1~A-4（账号池视图/计数/搜索）——确认 server `/v1/vault/accounts` 返回与 UI 一致；
2. TC-C 单角色（C-1 上线/ C-2 暂停/ C-3 恢复/ C-4 停止/ C-5 幂等）；每步对照 server 日志与接口；
3. TC-D 同账号互斥；TC-E/F 账号级/全局批量（进度）；
4. TC-B 状态机（能真实构造的：在线/登录中/已暂停/已停止/离线；注入态按测试计划 §2 手段，若注入成本高则标记阻塞）；
5. TC-G 轮询（改 server 状态后 5s 内 UI 更新）；
6. TC-I/J/K 启动分身：版本过旧弹窗 →「从本地 APK 更新」入口（**不要真下载 888MB**；如本地已有 APK 可走导入/校验，否则只验证弹窗+预检+取消）；失败诊断分类文案；
7. TC-L 回归（角色切换/自动化触发/今日页/角色管理弹窗）；
8. 每步证据：截图、`adb logcat -d` 关键行、`curl`（带签名工具脚本）或 server 日志、接口响应（Lead 提供签名辅助脚本时优先用）。
9. 测完恢复：删除 `files/vault_endpoint.txt`（回生产端点）、force-stop 重启 App、确认隆科多在线状态；关闭本地 server（`pkill -f vault-server-all.jar`），数据留 `/tmp/vault-qa-m4` 供取证。
