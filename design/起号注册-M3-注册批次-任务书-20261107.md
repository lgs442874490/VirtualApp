## 2. 交付物

### 2.1 新建包 `vault-server/src/main/java/com/carlos/vaultserver/registration/`

**RegistrationService.java**（编排，全部依赖注入可测）：
- `RegistrationOutcome guestRegister()`：`DeviceProfile.random()` → `passport.guestRegister(profile)` → fpid/sk 非空则成功；产出 `RegistrationOutcome{fpid, sdkToken, encrypted, deviceJson, createdAt}`。失败抛 IllegalStateException（含 `errorText()`，无敏感值）。
- `RegistrationOutcome realName(String fpid, String sdkToken, String name, String idCard)`：passport.realName → `realNameVerified/realNameMessage` 布尔结论返回（Outcome 里加 `realNameVerified/realNameMessage` 字段，或独立结果类 RealNameOutcome）。
- `String buildEncrypted(RegistrationOutcome)` / `RegistrationOutcome parseEncrypted(String)`：加密串=自包含凭据包 `base64url( fpid + "\n" + sdkToken + "\n" + base64(deviceJson) )`，parse 与 build 互逆；非法输入抛 IllegalArgumentException("加密串格式不正确")。
- 手机号单号流程 `PhoneResult registerOnePhone(PhoneBatchConfig cfg, CredentialBox creds)`：acquireNumber(keyword) → passport.sendSms → 轮询 fetchSms（间隔 5s、超时 cfg.smsWaitSeconds 默认 120，可注入 Sleeper 供单测跳时）→ 得 code → passport.smsLogin → （cfg.realName 非空时）realName → release(order) → 产出 PhoneResult（成功：fpid/sdkToken/encrypted/phone；各失败分支：取号失败/超时未到码/登录失败/实名校验本地拒绝，分别带 step+error，且尽力 release 或 block——超时未到码 block、流程成功后 release）。
- 每个 PhoneResult 记录步骤轨迹 `List<StepLog{step, ok, message, at}>`（步骤名：ACQUIRE/SEND_SMS/WAIT_SMS/SMS_LOGIN/REAL_NAME/RELEASE/BLOCK）。

**RegistrationBatchRunner.java**（批次状态机）：
- 字段：批次 id（`b+yyyyMMddHHmmss+序号`）、config（providerType/providerConfigMap/keyword/maxNumbers/goalCount/smsWaitSeconds/realName{,} 可空/gamePassword 不落盘/intervalMillis）、每号 `PhoneEntry{phone, state: PENDING|RUNNING|SUCCESS|FAILED, result?，steps, error?}`、批次状态 `WAITING|RUNNING|COMPLETED|FAILED|CANCELLED`、startedAt/finishedAt、统计（成功/失败/尝试数）。
- `run()`：单线程串行逐号（取号上限 maxNumbers）；goalCount 个成功即提前完成；每号失败继续下一号；号码用尽且成功数 < goalCount → COMPLETED（部分成功）或 FAILED（0 成功）；`cancel()`：当前号自然结束后停（置 CANCELLED）。
- 批次全程凭据/实名信息只存在 `CredentialBox`（见 2.2）；批次结束（终态）时 `box.clear()`。

**CredentialBox.java**（凭据批次期加密）：
- 进程级随机 AES-256-GCM 密钥（SecureRandom，静态一份）；`seal(Map<String,String>)→String(base64(iv+ct))`、`open(String)→Map`、`clear()` 置空内部表；`masked()` 输出各值掩码摘要。
- 约束：**任何持久化/日志只允许出现 masked 形式**。

**RegistrationStore.java**（持久化，模式对齐 StateStore：原子写 + .bak）：
- 文件 `data/registration_batches.json`；保存最近 30 个批次的**可持久化视图**（批次元数据+每号 phone/state/steps/error/masked 凭据；**不含**明文凭据/身份证/密码/验证码）；`load()/append/update/ list(limit)/active()`；重启后 RUNNING 批次标记为 FAILED("服务重启中断")，可查历史。

**RegistrationApi.java**（静态 handler，风格对齐 MonitorApi）：
- `handle(Map<String,Object> fields)` 按 `action` 分发：
  | action | 入参 | 出参 |
  |---|---|---|
  | `express` | {} | guestRegister 结果（fpid/sdkToken/encrypted；**sdkToken 仅此响应返回一次**，同时 seal 存内存供后续 real-name/建号）|
  | `real-name` | fpid, name, id_card（sdkToken 从内存 seal 表取；取不到→提示先用 express/批次注册） | realNameVerified/realNameMessage |
  | `provider-test` | providerType, providerConfig{...} | testConnection 结果（ok/balanceText/maxNumbers/credentialMask/error） |
  | `batch-start` | providerType, providerConfig{...}, keyword, goalCount, maxNumbers, smsWaitSeconds?, realName{,}? , gamePassword? | 批次概要（id/状态/配置摘要，凭据 masked） |
  | `batch-status` | batchId | 批次全量视图（每号状态/步骤/统计） |
  | `batch-cancel` | batchId | 取消结果 |
  | `batch-list` | limit?（默认 30） | 批次列表摘要 |
- 校验：providerType ∈ {d1, haozhuma}；goalCount 1–50；maxNumbers ≥ goalCount 且 ≤100；realName.idCard 18 位；gamePassword ≥6 位或空。错误统一 `{error:"中文说明"}`。
- 批次执行在独立单线程 executor（daemon），HTTP 立即返回批次概要。

## 4. 设计说明（实现须遵守）

- PassportFacade 接口（`guestRegister/realName/sendSms/smsLogin` 四方法签名同 PassportClient）由 RegistrationService 依赖，生产实现直接包 PassportClient，测试用 fake——避免单测碰网络 Transport。
- 批次 runner 不持有 HTTP 请求线程；cancel 只是标志位。
- 「注册成功提示转入起号」由 App 侧负责（M5），服务端 batch-status 提供 `encrypted` 仅在 SUCCESS 条目里返回一次（凭据在批次内 seal 保存，批次终态后 encrypted 仍可从持久化视图返回——加密串本身是凭据包，属于用户自己的数据，持久化时**允许**存 encrypted 字段（它就是产物），但不存明文 sdkToken；sdkToken 只能通过 encrypted 解出）。
