## 1. 上线前的关键发现（先修后上）

合并 master v4.2.61 后独立审查（P0×2 / P1×4 / P2×5）发现**阻断项**：

| 项 | 问题 | 后果 |
|---|---|---|
| P0-1 | `license-server/features.go` 里 `immigration` 仍是 `implemented=false` | `featuresForRole` 的 `fc.implemented=1` 过滤 → 永不下发；`saveMatrix` 还拒绝运营勾选；**GM 也看不到** |
| P0-2 | 生产库矩阵行是「未实现恒 0」占位，只改目录不生效 | 仍不下发 |
| P1-1 | `visibleToolCount(Context)` 漏计移民（只改了 deprecated 纯函数版） | 工具箱计数与实际渲染不一致 |
| P1-2 | ToolBox 防旁路只查 3 个 key | 可能放行空壳页/挡下有效页面 |
| P1-3 | `formation_manage` 目录 `3/false` 与 App `T2/true` 相反 | 矩阵模式下 T2/T3 编队管理入口**会消失**（master 既存缺陷） |
| P2-3 | 移民页无自身门控 | 深链绕过风险 |

**全部已修**（commit `4224fca`），含：
- 目录：`immigration → 移民/T3/implemented=true`；`formation_manage → T2/true`
- 矩阵种子改 `INSERT OR IGNORE`（补缺失行，不覆盖运营配置）
- **一次性矩阵迁移**（`PRAGMA user_version`）把「未实现恒 0」的旧行按默认重置，只跑一次，之后运营可自由开关
- App 侧计数/防旁路同源（新增 `anyToolVisible`）+ 移民页自身门控

验证：App 988 用例、license-server `go test` 全绿；本地用「生产形态旧库」验证迁移生效且幂等。

## 4. App 侧生效条件（重要）

服务端矩阵已放行，但**已安装旧 APK 的用户需要两个条件**才能看到入口：

1. **装新 APK**：`无尽号库-v4.2.61-移民测试版.apk`
   - 13,065,138 B · sha256 `ebeb1357d91f04c45672fe9aabc278a59265d2bc098cac37399d953f84046e3d`
   - v4.2.61 / versionCode 23572
2. **触发一次许可证 verify**（票据里缓存着旧 features，10 分钟节流）：
   - 进入「账号池」页面会自动 `verifyAsync`
   - 或等下次启动/校验周期（≤10 分钟）

> 现象解释：旧票据若 `featuresPresent=false`（从未 verify），回退按等级判定 → T3 反而看得到入口；
> 进过一次账号池触发 verify 后，拿到的是**旧矩阵**（不含 immigration）→ 入口消失。
> 部署后重新 verify 即可恢复为「T3 可见」。
