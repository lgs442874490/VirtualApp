# 需求澄清变更单（2026-10-21 用户确认）：多角色并行在线 + 分身版本更新方式

> 用户原话要点：
> 1. 京东云代码仓库：本地存有云仓库地址，`wjdr-review` 是旧代码，需按最新源码对照（地址待定位）。
> 2. 「多角色并行在线不是账号」：要求**同一账号（fpid）下的多个 888 服角色可同时在线**（例：隆科多 + 小鹿矿工5号 并行），不是多个账号并行。
> 3. 「克隆游戏分身，如果重大版本更新应该是更新原生游戏就可以了，不需要号库处理」：分身游戏过旧时，App 引导用户更新**手机原生游戏**（应用商店/官方渠道），然后**重新克隆**进容器；不再由号库内下载 888MB APK。
> 4-6. 范围/提交（同意 3 个 commit）/发布部署（确认 v4.1.5 + 生产 server 部署 + M5 灰度）均获用户确认。

## 一、M1 语义变更（服务端）
- **取消「同 fpid 单角色在线」互斥**：会话键从 `fpid` 改为 `(fpid,sid,uid)`；同一账号多角色可并行会话。
- `role-action login`：只启动目标角色，**不停止**同账号其它角色；失败只影响本角色（不连带他人）。
- `account-action login-all`：对该账号所有 enabled 工作区角色逐个 login（并行/顺序均可，但都尝试），返回每角色结果；`onlineCount` = 在线角色数（可 >1）。
- `global-action login-all`：所有账号的所有 enabled 角色尝试上线；结果按账号汇总。
- `maxConcurrentSessions` 改为按**角色会话**计数（硬顶默认 8，同账号多角色也计入）。
- `desiredOnline` 持久化/重启恢复：同一 fpid 可有多个 desiredOnline 角色，全部恢复。
- `/accounts`：每角色独立 state；account.onlineCount=该账号在线角色数；全局 onlineCount=所有角色在线数。
- 兼容：旧 App（v4.1.4）sync 只有 active 角色时行为不变；`/status` 旧字段保留。
- 风险：游戏服可能对同账号多角色并发登录互踢（旧结论 code=46）；服务端不阻止，按角色失败/恢复状态上报，由真机灰度确认。

## 二、M2 语义变更（App）
- 移除「同账号互斥上线前确认弹窗」；点「上线」直接 role-action login（服务端不再互斥）。
- 账号级「全部上线」调用 `account-action login-all`（全部工作区角色上线），不再只上 1 个。
- 组头「在线 N」可 >1；行状态独立；保留「已收纳/暂停/停止」矩阵。
- 顶栏计数口径保持（工作区=启用角色数、在线=server 聚合）。

## 三、M3 语义变更（分身版本更新）
- 容器游戏版本过旧弹窗改为：
  - 主按钮「更新原生游戏」→ 打开应用商店/官方更新引导（`market://details?id=com.gof.china`，无商店时给官网/指引）；
  - 「重新克隆分身」→ 从**手机已更新的原生游戏**重新安装/覆盖进容器（`VirtualCore.installPackage(Uri.parse("package:"+GAME_PKG))`），保留容器数据；版本校验后重新拉起；
  - 高级兜底「从本地 APK 更新」保留；
  - **移除 App 内 888MB 自动下载入口/流程**（原下载器代码可保留但不再作为主路径，UI 不出现「立即更新(888MB)」）。
- 原生游戏更新后回到 App：onResume 检测原生 versionCode > 容器 versionCode → 提示「检测到原生游戏已更新，是否重新克隆分身？」。
- 重新克隆后必须验证：容器游戏 versionCode == 原生 versionCode、容器账号数据未丢（/virtual/data 保留）、可拉起游戏。
- 失败诊断保留（授权/引擎/克隆/版本/安装/系统分类）。

## 四、验收补充（M4c/M5）
1. 同账号两角色（隆科多 35371154 + 小鹿 88280792，均 888 服）可同时处于 online=true；服务端存在 2 条会话；App 组头「在线 2」；账号级全部上线两角色都上；无互斥弹窗。
2. 真机灰度（M5）：生产 server 部署 M1 后，真实登录两角色观察是否互踢；若互踢则回归为「同账号仅 1 在线 + 明确提示」，并记录游戏服约束实证。
3. M3：版本过旧弹窗不出现 888MB 下载；点「更新原生游戏」打开商店；「重新克隆分身」在原生未更新时提示先更新；原生更新后（M5 用户操作）重新克隆成功且数据保留。
