## 2. 交付物：新建包 `vault-server/src/main/java/com/carlos/vaultserver/bootstrap/`

### 2.1 BuildingGateCatalog.java
- 静态懒加载 `get()`：从 classpath `bootstrap/building-gate-catalog.json` 解析（org.json；参照 TownDevCatalog.get() 的加载风格与容错）。
- API（语义对齐原版 DailyTownDevelopmentCatalog 对应方法）：
  `long needExp(long buildingId, long level)`、`List<Cost> furnitureRequirement(long buildingId, long level)`（该级 furniture 门槛）、`List<Cost> furnitureCosts(long furnitureId, long level)`、`long furnitureExp(long furnitureId, long level)`、`long furnitureMaxLevel(long furnitureId)`、`boolean supports(long buildingId)`。
- Cost 复用 `TownDevCatalog.Cost`（构造可写 `new Cost(id, amount)`——若其构造包私有，本包内自建同名 record Cost{id,amount}，二选一以编译通过为准，注释说明）。
- 家具经验贡献判断（原版 furnitureContributesExp）：`furnitureExp(fid,1)>0`。

### 2.2 BootstrapPlanner.java
移植原版 BuildingUpgradePlanner（保持算法与 blockedReason 中文文案逐字一致）：
- `Plan plan(Request)`；`Request{buildingLevels, furnitureLevels(Map<bid,Map<fid,lv>>), targets, busyBuildings, resources:ResourceAvailability, maxActions(默认8,≤300)}`；`Plan{actions, blockedReason, complete}`；`Action{kind:CREATE_FURNITURE|UPGRADE_FURNITURE|UPGRADE_BUILDING, buildingId, buildingName, furnitureId, fromLevel, toLevel, costs}` + `usesQueue()/label()`（label 文案对齐原版）。
- 数据源：建筑名称/成本/前置= TownDevCatalog；needExp/家具= BuildingGateCatalog。
- **不依赖 Spring**（原版 @Component 去除）；纯函数可测。

### 2.3 BootstrapState.java
- `static BootstrapState fromLoadData(Map<String,Object> loadContent)`：解析建筑等级表 `Map<Long,Long>`（loaddata 的 building/建筑列表字段——**防御式深找**：键候选 `buildings/building_info`，条目内 `bid/id` + `lv/level`，参照 `ServerTownTasks.parseBarrackBuildingLevels` 风格但输出全建筑 Map）、家具等级 `Map<Long,Map<Long,Long>>`（条目家具列表键候选 `furnitures/furniture`，`conf_fid/fid` + `lv`）、升级队列 busy 建筑 Set（队列键候选 `queues/build_queue`，条目 `bid` + 未完成判定）。
- `level(bid)`/`furnitureLevels()`/`busyBuildings()`/`furnaceLevel()`（=level(301)）。
- 提供 `markedUpgraded(bid,toLevel)`/`markedBusy(bid)` 乐观更新方法（执行动作后本地推进，等待下轮 loaddata 校准——对齐原版 markBuildingStarted/markBuildingInstantUpgrade）。

### 2.4 BootstrapService.java（单号执行核心）
依赖注入 `ProtocolPort`（函数接口 `GameMessage request(String proto, Map<String,Object> args) throws Exception`，生产包 WjdrEngine，测试脚本回放）：
- `BootstrapConfig`（移植原版字段/默认值/fromMap/toMap：enabled,targetServerId,targetFurnaceLevel(1-9默认9),instantDiamond(默认true),claimRewards(false),buyShopResources(false),allianceName,autoApplyWhenPrivate,roleName≤16）。
- `Map<String,Object> status()`：对齐原版 status 结构（config/roleUid/roleName/targetRoleName/stateReady/furnaceLevel/targetFurnaceLevel/buildings[id,name,level,busy]/resources(wood103/coal104/iron105/diamond101——从 loaddata 背包资源字段深找，参照 `DailyBackpackResourceSupport.resourceCount` 若同源存在，否则本类内实现同语义)/remainingSteps(planner 规划)/blockedReason/completed/runState(DISABLED|WAITING_SYNC|READY|LEVEL_COMPLETED)/message 文案逐字对齐原版 runMessage）。
- `runNext()`：对齐原版 runNextStep（renameIfNeeded → 情报**略过**（M4b）→ 状态未同步 WAITING → planner → executeFirstAction）；`runUntil(maxSteps 1-300)`：对齐原版（步间 idleReached 等待≤10s，Sleeper 可注入；MANUAL/WAITING/RESYNC_REQUIRED/EXP_BLOCKED(119)/ITEM(51 重试一次后失败)/BUILDING_HAS_NOT_FURNITURE(120) 分支与文案对齐 upgradeRejected；806 → RESYNC_REQUIRED 文案）。
- `executeFirstAction`：协议 `req_upgrade_building(bid,use_diamond,qid)` / `req_create_furniture(bid,conf_fid)` / `req_upgrade_furniture(bid,conf_fid,add_lv)`（payload 对齐原版 protocol()/payload()）；队列 id 从 BootstrapState idleQueueId（无队列→WAITING「当前没有空闲建筑队列」；instantDiamond=true 时不需要队列）。
- `renameIfNeeded`：`req_player_modify_name(name,use_diamond)`；code 51→重试用钻石；205→视为成功（内存 renamedRoles 缓存）；文案对齐原版。
- `resolveAlliance(keyword)`/`joinAlliance()`：`req_alliance_search_by_key(key)` → 精确匹配 name/abbr 唯一 → `req_alliance_join(aid)`/`req_alliance_apply_join(aid)`；校验与文案对齐原版（≤16 字/未匹配唯一/非公开需 autoApply）。
- `levelBuilding(buildingId)`：对齐原版（单建筑 current+1 目标规划执行）。
- `createRole(fpid, sdkToken, serverId, displayName?)`：`engine.login(fpid, sdkToken, serverId, Map.of("is_create",true[, "name",displayName]))` —— 由调用方传 engine（本方法在 BootstrapService 上接受 `WjdrEngine` 参数或由外层 SessionKeeper 层完成，M4a 先提供 `LoginOutcome createRole(WjdrEngine engine, ...)` 直通实现：返回 uid/serverId/authContent，serverMismatch 判定对齐原版）。
- 所有 actionResult 文案（STARTED/WAITING/MANUAL/COMPLETED/RESYNC_REQUIRED/EXP_BLOCKED/FAILED/JOINED + message）逐字对齐原版（Unicode 转义已在上列源码中，展开为中文）。
