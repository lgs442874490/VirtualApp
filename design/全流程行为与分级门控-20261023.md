## 0. 结论速览

1. **当前 App 没有任何“按授权等级显示/隐藏功能”的门控**：只有“已激活/未激活”总闸（`AccountVaultActivity.java:119-136`）。`LicenseState.usable()` 决定能否进主界面（`license/LicenseState.java:37-40`），进入后 4 Tab 全量可见；`FnRegistry` 57 项全部 `implemented=true`（`daily/FnRegistry.java:38-110`），任务页按分类全量渲染（`HomeActivity.java:4116-4119,4429`）。
2. **兑换码只有“时长类型”，没有等级**：仅 `month`/`permanent`（`license/LicenseConfig.java:145-146`；服务端 `license-server/schema.sql:12-13`、`license-server/model.go:77-78,145-151`）。三级 tier（T1/T2/T3）尚未落库；**工作区已有未提交的客户端 tier 骨架**（`LicenseConfig.java` 新增 `TIER_BASIC/MEMBER/PREMIUM` 与 `normalizeTier`、`LicenseManager.tier()/tierAtLeast()`，见 `git diff app/src/main/java/com/carlos/vault/license/`），但**服务端 schema/接口/旧码默认 T3 迁移、UI 门控均未做**。
3. **初始化流程已有骨架但顺序与引导不闭环**：授权激活 → 主界面自动弹“初始化向导”（仅当已激活且未克隆/无基线，`AccountVaultActivity.java:216-226,119-136`）→ 向导四步（克隆/首启/重置/存基线，`AccountVaultActivity.java:1286-1500`）→ 添加账号（`846` 手动、`869` 批量）→ 启动分身（`EntryDetailActivity.java:237,923`）→ 设自动化（任务页 → `FunctionActivity`）→ 服务器执行与观测（`HomeActivity.java:4254` 服务器模式、账号池轮询 `408-441`、执行面板 `5710`）。缺口：**没有“首次使用一键引导”把①兑换码②加号③克隆④初始化⑤开自动化串起来**；向导只在“已激活”后才出现，激活页与初始化引导之间仍是空白。
4. **工具箱当前把 14 项未开发功能作为“规划中”网格直接展示**（`ToolBoxActivity.java:147-185`），且长按“开放策略”可进入 7 个真实消耗的 P1 协议探针（`ToolBoxActivity.java:217-220,447-526`），**没有 BuildConfig.DEBUG 门槛** → 普通用户可误触（迁城/驻防/加速链会消耗道具）。
5. **T3 六项现状**：敌情监控=已实现（App `daily/EnemyWatch*` + `NotifySettingsActivity` + 服务端 `WarNotify/WeComNotifier`）；守护盟友=部分（威胁判定/闸门/设计完成，自动驻防发射未接产品流程，`FnRegistry.java:96` 自述“建设中”）；迁城=仅调试探针（`ToolBoxActivity.java:500`）；坐标查询/充值记录=仅文案占位（`ToolBoxActivity.java:151-152`，无任何实现）；巨兽批量=未开发（单账号每日巨兽发起也未做，`ServerTasks.java:3670-3693` 仅原生自动上车）。
6. **T2 日常脚本（7 类 57 项）主体已在服务器端实现**（批次 1-6：`vault-server/.../task/` 55 个 TaskDef + `Modules.java:30-133`；7 类计数：奖励 10 / 城镇 11 / 活动 15 / 野外 7 / 联盟 8 / 商店 2 / 其他 4），**但仍有 4 项 UI 可见、服务端无对应实现或其状态为“建设中/仅部分”**：`guardian`、`war`（仅 UI 注册，`ServerTasks.all()` 无这两个 id）、`behemoth`（仅 auto_join）、`backpack`（自动使用范围产品未确认）。
7. **结论性建议**：本轮 UI 门控优先级 = ①先做 tier 字段与“T1 只显示分身相关”②下架工具箱 14 项规划格 + 隐藏调试探针（release 包）③T3 六项仅保留“敌情监控（已实现）”展示，其余标“规划中/灰度”或隐藏 ④初始化引导闭环 + 账户页“在线/启动”联动。

### 5.1 授权等级 tier（P0，需 App+服务端协同）

现状：`LicenseConfig.java:145-146` 仅 month/permanent；服务端 `license-server/schema.sql:12-13` CHECK 仅两种；`license-server/model.go:77-78,145-151` 无 tier。工作区客户端 tier 骨架（未提交）：`LicenseConfig.java` 新增 `TIER_BASIC/MEMBER/PREMIUM` + `normalizeTier/tierName`；`LicenseManager.tier()/tierAtLeast()`；`LicenseTicket.tier`（`git diff app/src/main/java/com/carlos/vault/license/`）。

建议：
1. 服务端 `license_code` 增列 `tier INTEGER NOT NULL DEFAULT 3`（存量码默认 T3，符合“旧码兼容不伤存量”）；`/v1/activate|verify` 响应增加 `tier`；admin 生成码 CLI 支持 `--tier 1/2/3`（`license-server/cli.go`）。
2. App 端 `LicenseTicket.tier` 默认 `TIER_DEFAULT=3`，**不改变 `signableFields` HMAC 规范化串**（旧票据继续有效，见 `LicenseTicket.java` 注释与 diff）。
3. App 侧提供统一门控 API（已有 `LicenseManager.tierAtLeast`）：
   - `FnRegistry.Fn` 增 `minTier` 字段（T1=1/T2=2/T3=3），任务页/常用区/搜索统一过滤（`HomeActivity.java:4116-4119,4429,4569`）；
   - `FunctionActivity.onCreate` 入口二次校验（直接 startActivity 的旁路也要拦）；
   - ToolBox/NotifySettings/我的页各行按 tier 显隐；
   - 授权卡“专业版授权”改 tier 名称（`HomeActivity.java:4833`）。
4. 服务端（可选 P1）：vault-server 目前不校验 license，只按 roleConfig 执行；若要防 App 绕过，可在 `/v1/vault/policy|sync` 附带 tier 并由服务端对 T2 任务做白名单（需与 license-server 打通，工程量大于 App 门控，建议后置）。

### 5.2 初始化引导闭环（P0，impl-bear）

- 在授权激活成功后（`LicenseUi` 激活回调 → `recreate()`）插入“首次使用引导”状态机：①兑换码（已完成）②克隆/初始化 ③添加账号（可跳过）④启动分身 ⑤打开自动化（T2+）。

- T1 用户引导止于④；T2+ 追加⑤并直达任务页（`HomeActivity.switchTab(2)`）。

### 5.3 账户页“在线/启动”联动（P0，impl-field）

- 现状：账号卡单击=启动本地分身（`HomeActivity.java:2283`）；在线状态来自服务端账号池（`HomeActivity.java:408-441,3260`）；两者无统一主按钮。

### 5.6 验收口径（建议写入测试/QA 清单）

1. T1 激活码登录后：日常 Tab/工具页 T3 卡/我的页运行组不可见；账号页仅“启动分身/快照/导入导出/角色管理”可用；无任何自动化开关可点。
