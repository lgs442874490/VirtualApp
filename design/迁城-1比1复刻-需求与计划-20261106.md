## 1. 背景与目标

网页版（`http://111.228.32.189:8888/`，紫色风铃 V419）有完整的「迁城」独立模块：
12 种迁城协议 + 立即批量迁城 + 定时抢位迁城 + 任务管理。

本项目此前迁城仅为 T3 规划项（`FeatureGate.MOVE_CITY` implemented=false）加一个烧道具的调试探针
（`GuardProbe.moveCity`，只支持 `req_world_move_city` 的 (+1,0) 四方位轮试）。

**目标**：以反编译源码为唯一行为基准，把迁城复刻为可产品化使用的功能：服务端执行引擎 + App 配置与任务页。

## 2. 范围与非目标

**范围内**
- 服务端：12 协议注册表、立即迁城、定时迁城、任务生命周期、持久化与重启恢复、
  自动上线保护、会话优先窗、重试与道具短缺短路、REST 端点。
- App：`MoveCityActivity`（协议/账号/坐标/王国/定时/任务列表详情取消）、工具箱入口、FeatureGate 放开。

**非目标**
- 不复制原版的「独立迁城账号池」（本项目直接用号库账号，H3）。
- 不做 App 本地模式执行引擎（迁城需服务器执行；未开服务器模式时页内提示）。
- 不做像素级 UI 复刻（用户裁决走 App UiStyle 规范）。
- 不做「移民」（原版独立模块，本项目 `IMMIGRATION` 另行立项）。
- 不改动守护盟友内部的 L2 迁城释队逻辑（`GuardianLaunch` 复用 `req_world_move_city` 不变）。

## 3. 用户与场景

- **用户**：T3 高级会员；T1/T2 不渲染入口。
- **场景**
  - S1 批量立即迁城：多账号各填目标坐标，一次性执行（盟战集合）。
  - S2 定时抢位：单账号设定未来时刻（精确到秒）+ 提前量，到点自动迁城。
  - S3 任务管理：查看状态、取消未开始任务、查看逐次尝试详情。
  - S4 离线账号定时迁城：开启「执行前自动上线」，服务端 T-60s 起抢登。

### FR2 立即迁城（多账号批量）

- 输入：协议 + 账号数组（`fpid/name/x/y/kid/selected`）。
- 校验：needsPoint 协议要求每账号 `x>0 && y>0`（缺失报「角色 X 缺少迁城坐标」）；
  needsKid 要求 `kid>0`（「角色 X 缺少王国 ID」）；多账号同坐标拒绝（「多个账号不能迁移到同一坐标: x,y」，
  原版该检查发生在异步执行期 → 任务失败）。
- 执行：每账号独立线程并发；离线且未开自动上线 → 「账号未在线，已跳过该账号」；
  失败**不重试**（maxAttempts=1）；请求超时 6s。
- 结果：逐账号 `success/attempts/message/attempt_details/response`，异步聚合，客户端查 jobs/job。

### FR3 定时迁城（每任务单账号）

- 输入：协议 + 单账号 + `executeAt`（`yyyy-MM-dd HH:mm:ss`，**北京时间**）+ `advanceMillis`（0–100，超界 clamp）+ `autoLogin`。
- 时间校验：必须晚于服务器时间（`GameServerClock` 已校准优先）；同账号同毫秒/±5000ms 冲突拒绝（文案逐字对齐）。
- 时间线（服务器钟）：T-60s 启动保护窗巡检（每 1s，离线即抢登）→ T-5s 准备（armed）→ T-1s 预热 →
  T-advance 释放发请求；失败重试 50ms × 200 次；保护窗截止 T+60s。
- 道具短缺：捕获专属短缺码 → 立即停止，文案「迁城道具不足，未使用钻石补购，本次迁城已跳过」（**零钻石路径**）。
- 准备失败 + autoLogin：进入「等待恢复」→ 释放时刻走仅恢复执行路径；未开 autoLogin 直接失败。
- 持久化：全量落盘 `data/movecity_jobs.json`；重启恢复 T+60s 内未完成任务。
- 状态机：已创建 → 准备中 → 等待执行 → 执行中 → 已完成/失败；分支：等待恢复、已取消。
  仅「已创建」可取消；取消记 `error=用户取消`；账号删除联动取消。
- **角色锁定（本项目新增）**：任务记录创建时会话的 `sid:uid`，执行前比对，不一致即失败
  （防同服多角色切号后迁错角色）。

### FR4 REST 端点（单端点 + action 分发，沿用项目惯例）

`POST /v1/vault/movecity`，`action ∈ {protocols, execute, schedule, jobs, job, cancel, remove-account}`；
账号列表通过 `accountsJson`（JSON 字符串）上传以保持签名层扁平（与 sync/watchpoint 一致），
服务端归一化回 `accounts` 列表。

### FR5 App 迁城页

- 入口：工具箱「迁城」卡片（`FeatureGate.visible(MOVE_CITY)`，T3）。
- 结构：模式分段（立即/定时）→ 迁城类型（12 项）→ 迁城坐标（needsPoint，逐账号 x/y）→
  目标王国（needsKid）→ 迁城账号（多选；定时限单选）→ 定时设置（时间选择器/手输、提前量、执行前自动上线）→
  提交 → 任务列表（定时中/已完成）。
- 校验文案逐字对齐原版：请选择迁城账号 / 请选择迁城类型 / 请填写迁城坐标 / 请填写目标王国 /
  请选择定时时间 / 定时时间必须晚于当前时间。
- 提交前二次确认：列出账号、协议、坐标/王国、（定时）执行时刻+提前量+自动上线。
- 结果 toast：迁城任务已执行 / 定时迁城已创建 / 定时任务已取消。
- 服务端未升级或未开服务器模式：顶部提示条 + 禁止提交。
- 文案口径：UID 一律显示 `fid`；不显示登录方式。

### FR6 门控

`MOVE_CITY("move_city", TIER_PREMIUM, true, false, "迁城")`；`visibleToolCount` 计入。

## 5. 非功能需求

- 定时释放到请求发出 ≤50ms（记录 `release_to_send_micros` 供验收）。
- 时钟：`GameServerClock` 优先，未校准回退本机钟。
- 零钻石路径；消耗性操作需二次确认。
- 可观测：逐次尝试详情 + 关键时间点日志 + 任务状态全量落盘。
- 回滚：`VAULT_MOVECITY=off`（服务端整体禁用）；App 侧把 `implemented` 翻回 false 即入口消失。
- 已完成任务保留上限 200 条（防落盘文件无限增长）。

## 6. 异常与边界

| # | 场景 | 行为 |
|---|---|---|
| E1 | 立即迁城账号离线 | 记「账号未在线，已跳过该账号」，其余账号不受影响 |
| E2 | 道具不足 | 短路不重试、不补钻石 |
| E3 | 同账号 ±5s 重复定时 | 创建被拒 |
| E4 | 多账号同坐标 | 任务失败（原版在异步执行期校验） |
| E5 | executeAt 已过期 | 创建被拒 |
| E6 | 执行中服务重启 | T+60s 内恢复；已过保护窗不重放 |
| E7 | 请求超时/错误码 | 立即不重试；定时 50ms×200 重试；error_detail 带码 |
| E8 | 账号从号库删除 | 联动取消其未开始任务 |
| E9 | advanceMillis 越界 | clamp [0,100] |
| E10 | 账号中途切角色 | 角色锁定校验失败，提示重建任务 |
| E11 | App 传非法 accountsJson | 业务错误「账号参数格式错误」 |

## 10. 代码审查结论（2026-11-06）

发现并修复 7 项：

| 级别 | 问题 | 修复 |
|---|---|---|
| P0 | `awaitReady` 超时导致线程/future 泄漏（原版同缺陷） | 异常时先释放 `startLatch` |
| P0 | 任务未锁角色 → 切角色后迁错号 | Action 记 `sid:uid`，执行前校验 |
| P0 | 优先窗 1215s 令日常任务停摆（原版账号池隔离才敢这么长） | 执行结束立即 `clearMoveCityHold` |
| P1 | 任务历史无限增长（全量重写 JSON） | 已完成保留 200 条 |
| P1 | 非法 accountsJson 冒泡 500 | 转业务错误 |
| P1 | App 把所有 3002 误报「服务端未启用」 | 优先用服务端中文文案 |
| P1 | 立即迁城的自动上线开关是假的 | 离线账号明确拦下并说明出路 |

记录不修：迁城失败可能触发会话 `beginRecovery`（会话层统一策略）/ App 缺「移除任务账号」UI /
`jobs` 返回完整 results（与原版形状一致）/ cancel 与 prepare 窄竞态（原版同样）/
错误码中文只覆盖已实证的 2836、2878。
