# 立项：守护盟友——盟友被攻击时自动卡秒驻防（协议层）

> 立项：2026-10-13。承接：号库壳协议级自动化（242 协议盘点、proto_log、
> GameNotifyListenerService 均为现有设施）。本功能与 luapatch 解密线**无关**，
> 不依赖 bundle 逆向进度。

## 1. 功能定义

监听联盟事件：当有盟友主城被敌方行军攻击时，自动向该盟友城堡发起驻防（增援），
使我方驻防部队的到达时刻**刚好早于**攻击方到达时刻（卡秒落地，让敌方一击撞上
我方驻防）。

## 2. 已有事实（本轮 spb 侦察实证）

- 协议定义文件：`app/src/main/assets/wjdr/game_proto_{c2s,s2c}.spb`，可按
  字符串 token 侦察（`strings` + grep）；
- 行军家族协议已枚举（c2s）：`req_alliance_help_all`、
  `req_arsenal_league_march` / `_march_detail` / `_march_recall` / `_march_off_work`、
  `req_arsenal_league_embassy_help_march_detail_list` /
  `_embassy_help_simple_info`（embassy = 使馆即驻防建筑，高度相关）；
- s2c 推送已枚举：`notify_arsenal_league_march_add` / `_del` / `_update`、
  `notify_arsenal_league_battlefield_*` 等。

## 3. 待研清单（按序）

1. **攻击检测推送**：在 game_proto_s2c.spb 与设备 proto_log.txt 中定位
   "盟友被攻击"告警协议（候选关键词：`be_attack` / `under_attack` /
   `union_warning` / `notify_union_*` / `battle_start`），确认字段含
   **攻击方到达时间戳**、防守方坐标/对象 id；
2. **驻防请求**：确认 c2s 驻防 req（候选 `req_arsenal_league_embassy_*` 或
   世界地图行军 req_world_march 的驻防变体），挖参数格式：目标坐标、
   将领、兵量结构（参照 VaultEngine 已有请求签名方式）；
3. **成员坐标**：盟友城堡坐标的来源协议（联盟成员列表）；
4. **行军时长公式**：距离 × 速度反算，或首跑实测标定（发出→记录
   march_add 的到达时间，回归出系数）；
5. **调度器**：号库内新增定时器——收到攻击推送 → 算出发时刻 →
   睡眠至 (到达_敌方 − 我方行军 − margin) → 发驻防 req；
6. **边界**：多路同时攻击的优先级、体力/驻防上限、取消行军
   （march_recall）兜底。

## 4. 验收

模拟（或真实）盟友被攻击 → 自动发起驻防 → 行军到达时间早于敌方到达
≤5s → 游戏内战斗为"驻防成功"。全程号库日志可见。
