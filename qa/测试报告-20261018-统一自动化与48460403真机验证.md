## 6. 重点问题：日常任务“显示已完成但游戏内奖励未触发领取”

### 6.1 现象（修复前）

1. 服务器对 `每日任务奖励` 的返回是：
   `⚠️ 响应无奖励字段，未确认到账（不视为成功）`。
2. 服务端 `st:2026-10-18:48460403:888:daily_mission = 3`（失败），App 功能详情显示
   `● 上次失败`，账号页显示 `异常 1`。
3. 游戏主城左侧任务入口仍有红色角标 `2`（见证据 `07-game-task-red-dot.png`）。
4. 旧客户端把 `SKIPPED` 与 `CLAIMED` 都写 `ST_DONE=2`，UI 显示“已完成”，
   造成“显示已完成但游戏内没有领取到奖励”的观感。

### 6.2 根因（已定位）

抓取 `notify_dailyquests` 与批量领取响应后确认两个确定缺陷：

1. **任务 id 解析失败**：`notify_dailyquests.quests` 的 key 形如 `"1320040.0"`，
   服务端旧代码用 `Long.parseLong` 解析，全部抛异常；结果只发送了静态 `DAILY_QUEST_IDS`
   的 21 个旧 id，漏掉 `1320090/1320100/1320200/1320210` 等新任务段。
   - 修复后请求 id 从 21 个增加到 **44 个**（见服务端日志）。
2. **4302 误判**：`req_get_all_dailyquest_award` 的响应 schema 只有
   `code/integral/geted_boxid/expert_effect_map`，**没有 awards/rewards 字段**。
   当所有任务都已领取时服务端返回 `code=4302`，旧逻辑把它归为 DEGRADED/异常。
   - 正确证据在 `notify_dailyquests.finishs[].isgetaward`：
     本次 7 个已完成任务全部 `isgetaward=true`，`unclaimed=0`。
3. **积分变化不能单独作为到账证据**：诊断轮中 integral 从 60 变为 75，
   但没有 `geted_boxid`；这只反映任务结算/服务端刷新，不能据此判成功。

### 6.3 已完成的修复

- 服务端 `dailyMission` 改为 `(long) Double.parseDouble(key)` 解析任务 id；
- 请求前统计 `finishs` 中 `isgetaward=false/缺失` 的 id 列表；
- 批量响应 `4302/4303`：
  - 未领数 = 0 → `SKIPPED "今日任务奖励已全部领取（码4302）"`；
  - 未领数 > 0 → 逐个调用 `req_get_dailyquest_award(questid)` 兜底，
    以 `finishs` 未领数下降作为到账证据；仍无变化才 DEGRADED；
- code=0 时只用两类证据判 `CLAIMED`：未领任务数下降、或 `geted_boxid` 非空；
  积分单独变化不再判成功；
- 客户端同逻辑同步（本地已停用，仅保持代码一致）；
- `ST_SKIPPED=4` 保留，UI 显示“已检查·无可领”，不再冒充“已完成”。


### 6.5 残余观察（红点 2）

游戏内左侧任务入口仍有红点 `2`，但协议数据表明 7 个已完成任务全部已领，
`unclaimed=0`。因此该红点**不是“已完成未领取的每日任务奖励”**，可能是：
- 活跃度宝箱/积分档位；或
- 章节任务/成长任务/其他活动入口的合并红点。

建议人工点开该入口确认红点归属；若确认仍有每日任务未领，则说明 `finishs`
没有覆盖该任务类型，需要再抓该任务对应的 notify/协议。
