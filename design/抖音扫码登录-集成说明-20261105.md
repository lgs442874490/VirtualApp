# 抖音扫码登录集成说明（2026-11-05）

> 来源：自营网页工具箱 `wjdr-tool`（2026-11-04 构建，commit `22d1173`）的抖音登录实现
> （`DouyinLoginService` + `DouyinQrLoginClient` + `DouyinHelperRuntime` + 打包内 `config/douyin-login.json`）。
> 号库按同一链路改写成端上纯 Java 实现，入口与「微信扫码登录」并排。

## 一、用户视角

账号详情 → **登录数据 → 抖音扫码登录** → 手机抖音扫码并确认 → 自动回填 `号ID + token` 到当前入口
（从账号页独立进入则写入「未分组」）。不需要在容器里安装抖音，也不走原生登录。

## 二、链路（与网页版一致）

| # | 步骤 | 接口/要点 |
|---|---|---|
| 1 | 生成二维码 | `GET https://live.douyin.com/passport/web/get_qrcode/…`（内置已签名模板；运行时只刷新 `ts`/`p_ts`） |
| 2 | 轮询扫码状态 | `POST https://live.douyin.com/passport/web/check_qrconnect/…`；表单 `need_logo=false&is_frontier=…&token=…&is_new_login=1&next=https%3A%2F%2Flive.douyin.com&need_short_url=true`；头 `x-tt-passport-csrf-token`；`msToken` 用响应头 `X-Ms-Token` 滚动刷新 |
| 3 | 抖音网页会话 | 确认后从 cookie 取 `sessionid`（状态 3 无跳转时访问 `https://www.douyin.com/` 探测） |
| 4 | 小游戏授权码 | `GET https://minigame.zijieapi.com/mgplatform/api/apps/v3/login?appid=ttcb0dbdb0543b8b2007&aid=1128&device_platform=android&is_phone_auth=false`，头 `X-Tma-Host-Sessionid` / `X-Tma-Host-Deviceid: 0` |
| 5 | 游戏 passport | `POST /client_api.php?ver=6`，raw 表单仅 `method=login_with_sns&game_id=20173&platform_id=tt_mini:<code>&access_token=<code>&minigame_scene_id=&bi_data={"social_type":"tt_mini_game"}`；`Authorization: FP 20173:base64(hex(HMAC-SHA256(字典序 k=v, game_key)))`；**不带** `cg-seid` |

返回 `fpid + session_key` 后按微信扫码同款规则写入账号库（入口 id 优先，其次按 fpid 覆盖，否则新建未分组）。

## 四、维护点（重要）

抖音二维码接口带 `a_bogus/sign/p_no/qs` 等非公开签名，**端上无法重算**，所以与网页版一样内置一份
已签名模板，只刷新时间戳与 `msToken`。抖音改协议或模板签名失效时，二选一：

1. 发版更新 `DouyinLoginTemplate` 常量（从新版 `wjdr-tool` jar 的 `config/douyin-login.json` 重新生成）；
2. 不改包应急：向应用私有目录（`getFilesDir()`）放一份 `douyin-login.json`，结构同网页版：
   `{"getQrUrl":"…","checkQrUrl":"…","userAgent":"…"}`，页面会优先使用它。

其它已知限制：抖音要求手机安全验证（`error_code=2046`）时无法在端上完成，会提示去抖音 App 验证后重新扫码；
登录会占用该抖音号当前网页会话（可能顶掉它正在用的设备），与网页版行为一致。
