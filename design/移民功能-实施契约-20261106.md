## 1. 传输层与身份映射（App ↔ 服务端）

**不复刻网页版 `/api/migrant/*` REST 路径**；本项目统一走 vault-http 信封 + ApiSign：

```
POST /v1/vault/migrant        op = "vaultMigrant"
body: commonFields + { fpid, sid, uid, action, ...payload }
响应: {code, message, data, serverTime}（沿用 VaultHttpApi.guard 信封）
```

App 端客户端仿 `VaultSync.roleAction()`（`VaultSync.java:770`）实现。

**身份映射（关键，两端必须一致）**

| 网页版字段 | 本项目字段 | 说明 |
|---|---|---|
| `account_id` | `fpid` | 账号（token 维度）。App `commonFields` 已有 |
| `account_role_id` | `uid`（long） | 角色主键。与 `RoleKey(fpid, sid, uid)` 一致 |
| `server_id` / `kid`（当前服） | `sid` | 服务器 id |
| `target_kid` | 同名，int | 目标王国 id |

> 注意：目标王国是**跨服**的 kid，与 `sid`（当前所在服）不同；`target_kid` 可能是未在本账号库出现的服。

## 3. 14 个 action 契约（字段 = 网页版响应字段，1:1 照抄）

### 3.1 `accounts`
出参 `{accounts:[{accountRoleId, game_name, server_id, online}]}`
- 数据源：`VaultStore` 账号池 → 每账号 `RoleEntry`（sid/uid/名称）；`online` 取 `SessionKeeper.roleRuntime(...).online`。

### 3.2 `overview`（payload `{account_role_id}`）
出参：
```
{ activity:{serial_no, config_version}, activity_open, state_complete, message,
  state: "FREEDOM"|"PROSPECT"|"INVITATION"|"CLOSED", freedom_start_millis, end_millis,
  current_kid, server_now_millis,
  kingdoms:[{kid,label,state,power_limit,power_limit_value,migrant_num,normal_migrant_num,remaining_quota}] }
```
- 数据源：该角色在线引擎的 `notify_migrant_init` 内容（`engine` 通知缓存）+ `req_migrant_get_kingdom_list`。
- 离线 → **返回 `{online:false, message}`**（2026-11-06 裁决：信封会把 null 兜成 `{}`，App 无法区分离线/空数据）；在线且无 `online` 键时服务端补 `online:true`。

### 3.3 `precheck`
payload：`{account_role_id, target_kid, auto_exit_alliance, recall_before_open, recall_speedup, recall_diamond_speedup, advance_millis}`
出参：`{ready, permits_owned, permits_required, remaining_quota, checks:[{id,label,detail,passed}], warnings:[string]}`
- 规则移植 `MigrantRules.evaluate()`：联盟状态、冷却、战力上限（赛区档位）、许可书、名额、同账号占用等。
- `advance_millis` 服务端钳位 `[0,100]`。

### 3.4 `test-early`（payload `{account_role_id, target_kid}`）
出参 `{accepted:bool, message:string}`；**真实发送一次 `req_migrant_migrate`**（危险语义保留）。

### 3.5 `create`（单个）
payload 同 precheck（无数组）→ `{job_id, ...}`；同角色已有 active 任务时拒绝（BizError，中文原因）。

### 3.6 `bulk`（payload 加 `account_role_ids:[...]`）
出参 `{requested, created:[job_id...], failed:[{account_role_id, message}]}`；逐角色独立，失败隔离。

### 3.7 `jobs`
出参 `{active:[job...], finished:[job...]}`；active = 非终态；finished 按 updated_at 倒序，最多 50。

### 3.8 `cancel`（`{job_id}`）→ 仅 `cancelable=true` 可取消；否则 BizError。

### 3.9 `recheck`（`{job_id}`）→ 重登读当前王国对账，返回更新后的 job。

### 3.10 `marches`（`{job_id}`）
出参：`{online, manual_recall_allowed, manual_recall_block_reason, recall_before_open, non_queue_march_count, marches:[{march_id,type,x,y,end_millis,remaining_millis,recalled,rally,recallable,recall_disabled_reason,requires_recall_item,recall_item_name,recall_item_count,recall_item_synced,recall_action}]}`

### 3.11 `recall`（`{job_id, march_id(0=全部), mode:"item"|"diamond"}`）
出参 `{results:[{march_id,success,message,recall_item_name?}], recalled, requires_diamond, message}`

### 3.12 `attempts`（`{job_id}`）
出参：任务汇总（`first_attempt_at_millis`/`last_attempt_at_millis`/`first_response_at_millis`/`last_response_at_millis`/`attempt_count`/`status`/`status_label`/`response_code`/`clock_source`/`clock_epoch_millis`/`account_name`/`target_kid`/`target_name`/`freedom_start_millis`/`created_at_millis`/`armed_at_millis`/`sent_at_millis`/`finished_at_millis`/`server_now_millis`）+ `attempts:[{sent_at_millis, response_at_millis, server_now_millis, server_clock_ready, phase, outcome, response_code, request_text, response_text}]`

### 3.13 `login` / `logout`（`{account_role_id}`）
角色上线/下线：复用 `SessionKeeper.roleAction login|logout`（2026-11-06 裁决：网页版工作区头部有上下线开关，故补 `logout`；下线只切会话，不改任务定义）。

### 3.14 越权
非本账号角色 → `BizError(1004, "角色不存在")`；job 不属于该角色 → 同上。

## 4. 任务实体字段（与网页版 job 响应 1:1）

```
job_id(String)  account_role_id(long)  account_name(String)
target_kid(int) target_name(String)    original_kid(int)

attempt_count(int)    max_attempts(int=200)

preparation_start_millis  preparation_started_at_millis
auto_exit_alliance(bool)  exit_alliance_message(String)
```

**时序常量（移植，不得改值）**：准备窗口 `freedom_start - 15min`；就绪目标 `freedom_start - 2min`；抢位节拍 `50ms`；最大尝试 `200`；对账窗口 `90s`；钻石兜底上限 `10/任务`；召回道具 800 钻 / 加速器 400 钻。
